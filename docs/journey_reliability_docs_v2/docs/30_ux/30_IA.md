# IA

## 1. Product Surface

Minimum Release는 계정 시스템 없는 single-session Web App을 기준으로 한다.

```text
Landing / Journey Input
    ↓
Analyzing
    ↓
Pre-trip Result
    ↓
Live Journey
    ├─ User Event / Reforecast
    ├─ Evidence Detail
    └─ Share Snapshot
```

## 2. Canonical Screens

| Screen ID | Name | Proposed URL | Purpose |
|---|---|---|---|
| SCR-01 | Journey Input | `/` | origin/destination/target/reliability 입력 |
| SCR-02 | Pre-trip Result | `/journey/{id}/plan` | route/P50/P90/P(on-time)/recommended departure |
| SCR-03 | Live Journey | `/journey/{id}/live` | 현재 leg/state와 live probability |
| SCR-04 | Reforecast Result | SCR-03 내 state/panel | UserEvent 전후 확률 변화 |
| SCR-05 | Evidence Detail | `/journey/{id}/evidence` 또는 drawer | support/fallback/freshness/limitation |
| SCR-06 | Share Snapshot | `/share/{token}` | 축약 결과 공유 |

URL은 구현 시 framework와 충돌하면 ADR로 변경 가능하다.
Screen ID가 정본이다.

## 3. Navigation Rules

### SCR-01 → SCR-02
조건:
- input validation pass
- structural route 확보
- Journey Analysis 성공

실패:
- input error → SCR-01 inline
- unsupported → SCR-01 result panel
- provider error → retry state

### SCR-02 → SCR-03
CTA: `이 경로로 이동 시작`

시작 시 analysis snapshot version을 고정한다.

### SCR-03 → SCR-04
UserEvent:
- BUS_SKIPPED
- BOARD_CONFIRMED
- TRANSFER_MISSED(조건부)

SCR-04는 별도 페이지가 아니라 live state의 결과 변경 surface로 구현 가능하다.

### SCR-03/SCR-02 → SCR-05
CTA:
- `계산 근거 보기`
- `근거 수준` badge

### SCR-02/SCR-03 → SCR-06
Share 생성 후 token URL.

## 4. State-to-Screen Mapping

| Journey State | Primary Screen |
|---|---|
| PLAN_INPUT | SCR-01 |
| ANALYZING | SCR-01 loading |
| PRE_TRIP_READY | SCR-02 |
| JOURNEY_STARTED / ACTIVE | SCR-03 |
| REFORECASTING | SCR-03 loading/optimistic-disabled |
| ARRIVED | SCR-03 terminal |
| ANALYSIS_FAILED | SCR-01/SCR-02 error |
| JOURNEY_ABORTED | SCR-03 terminal |

## 5. Cross-mode Status Labels

UI는 단순 `도보 중`으로 환승을 뭉개지 않는다.

- `버스 → 지하철 환승 중`
- `지하철 → 버스 환승 중`
- `지하철 → 지하철 환승 중`
- `버스 대기 중`
- `지하철 대기 중`

내부 Transfer/Wait contract와 표시 state가 일치해야 한다.

## 6. Mobile Priority

첫 화면에서 가장 중요한 순서:

1. 목표 도착시각
2. 정시 도착확률
3. P50/P90
4. 권장 출발시각
5. 현재 route
6. 근거 수준

Engineering/debug 정보는 Evidence Detail로 분리한다.

## 7. Unsupported Flow

지원 범위 밖이면 route를 억지로 잘라서 확률을 제공하지 않는다.

표시:
- `현재 이 경로는 분석 근거가 부족합니다.`
- 가능한 경우 이유: `지원 구간 밖`, `ID 연결 실패`, `데이터 없음`

## 8. No Account Assumption

Minimum Release에서 로그인/계정 복구를 IA에 추가하지 않는다.
새 account feature는 Scope Decision 없이는 추가 불가.

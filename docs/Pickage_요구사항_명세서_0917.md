## 1. 서비스 범위와 원칙

### 1.1 서비스 한 문장

Pickage는 사용자가 검토 중인 npm 패키지를 입력하면 순수 의미 검색 뒤 보완재·노후·실체 미달 구조적 관문을 통과한 관련 후보를 보여주고, 사용자가 확정한 최대 3개 패키지의 직접 의존 선언 수 추이·Snapshot 간 증감·Downloads·최신 DB Snapshot 기반 Version Share를 비교하도록 돕는 서비스다. 현재 plugin/adapter·same-family 제거는 목표 관문의 부분 구현 상태다.

### 1.4 적용 원칙

0. 사용자 화면 제공 범위는 데스크톱 컴퓨터의 웹 브라우저만으로 한정한다.
1. 후보 제공은 비교 후보 발견 기능이며 기술 우열이나 최종 선택을 의미하지 않는다.
2. 후보 이름 생성·후보 순서 변경에 생성형 AI를 사용하지 않는다.
3. 의미 유사도(cos)는 관문 통과 후보의 순서를 정하는 유일한 연속 신호다. popularity·Downloads·채택도는 검색·학습·정렬 score에 넣지 않는다.
4. 후보 ranking은 순수 의미 검색 `search_k=N` → 보완재·노후·실체 미달 구조적 관문 → cos 단독 정렬의 v1 계약(`DEC-RANK-20260910-01`)을 따른다. deprecated 패키지는 기준과 후보에서 모두 제외하며, `move_lift`와 대체 이동 쌍 가산은 사용하지 않는다. deprecated→대체·migration pair는 모델 학습 positive pair로만 사용한다.
5. v1은 가·감점 계수 튜닝으로 품질을 맞추지 않는다. API의 수치 score와 관문 판정은 화면에 노출하지 않되 정렬 결과인 `유사도 순위`는 표시한다.
6. 기준 패키지는 비교의 출발점으로 고정하고, 상위 후보를 최대 3개 미선택 카드로 제공해 사용자가 직접 선택하게 한다.
7. 최종 비교 대상은 기준 패키지를 포함해 최대 3개다.
8. 후보 단계에서는 버전을 선택하거나 확정하지 않는다.
9. MVP Dependency는 직접 의존만 제공한다. 간접·전이 의존은 범위에서 제외한다.
10. MVP Version Share는 최신 DB Snapshot의 version별 dependents를 major로 합산해 제공하고 시간축을 사용하지 않는다. requirement 해석 기반 분포는 확장이다.
11. 게시 데이터 상태와 UI 요청 상태를 구분한다. 후보 API의 `COMPLETE|NO_DATA`, 화면 요청의 `loading|success|empty|error`, PDF lifecycle을 서로 혼용하지 않는다. 실제 숫자 0과 자료 없음도 구분한다.
12. 보고서에서는 추천, 순위, 승자, 최종 선택을 제시하지 않는다.
13. 화면과 PDF는 완료된 동일 생태계 ReportSnapshot과 현재 선택 버전에 일치하는 완료 기능 비교 결과를 사용한다.
14. 색상만으로 선택·자료 상태를 구분하지 않고 문구·아이콘을 함께 사용한다.
15. 기능 비교 확장이 제공될 경우 근거가 없거나 충돌하면 임의로 지원 또는 미지원으로 판정하지 않는다.
16. MVP의 Dependency Snapshot 증감은 같은 표시 필터와 조회 구간에서 `마지막 유효 관측 직접 의존 선언 수 - 첫 유효 관측 직접 의존 선언 수`의 총수 차이만 의미하며 개별 dependent의 유지·유입·이탈로 해석하지 않는다. 계산은 프론트 `adapter.ts`에서 수행한다.

## 3. 전체 사용자 흐름

1. 사용자는 서비스 소개에서 제공 범위와 판단 한계를 확인한다.
2. 화면-01에서 접두사 자동완성 결과를 선택하거나 npm 패키지명을 자유 입력하고, 서버 검증을 통과한 이름을 기준 패키지로 확정한다.
3. 화면-02에서 기준 패키지와 미선택 상태의 후보 ranking 상위 최대 3개를 확인한다.
4. 후보를 해제하거나 다른 npm 패키지를 추가해 총 3개 이내로 비교 대상을 확정한다.
5. 보고서 1페이지에서 직접 Dependency, 패키지별 Snapshot 간 직접 의존 선언 수 증감, Downloads, 최신 Version Share Snapshot을 확인한다.
6. Dependency는 패키지별 `Total`로 시작하며 필요하면 하나 이상의 major 계열만 선택해 합산 추이로 바꾼다.
7. Version Share는 최신 DB Snapshot 기준일과 major 계열별 비중을 확인한다.
8. 기능 비교와 PDF 확장이 제공되는 경우, PDF 내보내기 조건을 만족하면 완료된 생태계 결과와 현재 선택 버전의 기능 비교 결과를 포함한 PDF를 생성하고 다운로드한다.

기능 비교와 GitHub 커뮤니티는 보고서의 확장 탭으로 제공할 수 있다. 생태계 보고서는 기능 비교의 진행 여부와 무관하게 계속 확인할 수 있지만, 기능 비교의 분석·재분석 상태는 PDF 적격성에 반영한다.

> **현재 후보 API 계약**: `GET /packages/similar?name={name}&limit={limit}`는 기본 20·최대 50개를 rank 순으로 반환한다. 응답의 `model_ver`, `data_status`, 후보 `rank`, `score`, `name`, `latest_version`, `description`, `not_found` 중 화면은 score를 제외한 후보 표시 필드와 존재 검증 결과를 사용한다. Notion/Swagger 동기화와 배치 결과 DB 게시 자동화는 후속 검증 대상이다.

## 10. 확장: 보고서 2페이지 기능 비교

### 10.3 분석 진행 상태 [확장]

버전 선택 영역 바로 아래에 분석 상태를 표시한다. 최초 분석 중에는 결과 위치에 빈 완성 문장을 만들지 않고 다음과 같은 실제 완료 단계를 순차 표시한다.

- 정확한 버전과 배포 자료를 확인하고 있습니다.
- 실행 환경과 공개 진입 정보를 확인하고 있습니다.
- 기능 근거를 정리하고 있습니다.
- 근거를 기능 판정과 연결하고 있습니다.
- 비교 해설을 작성하고 있습니다.

완료되지 않은 단계는 완료된 것처럼 표시하지 않는다. 해설 생성만 실패하면 비교표와 근거는 계속 제공한다.

### 11.2 표시 정보

1. 상단 신뢰 요약
   - 패키지와 정확한 버전
   - 기능과 판정
   - 한 문장 판정 이유
   - 공식 근거·정적 확인 수
   - 분석일
   - 자료 상태
2. 같은 기능의 패키지 탭
3. 역할별 근거 그룹
   - 지원 근거
   - 조건·제한 근거
   - 추가 확인
   - 충돌 근거
4. 기술 정보 접힘 영역
5. 허용 복사 동작
   - 근거 ID 복사 (`EVD-{reportSnapshotId}-{package}@{version}-{sequence}` 형식)
   - 분석 정보 복사

복사가 완료되면 같은 버튼 주변에 짧은 완료 문구를 표시하며, 복사 동작으로 Drawer가 닫히거나 외부 화면이 열리지 않는다.

같은 `reportSnapshotId` 안에서는 하나의 근거 ID가 하나의 패키지·버전·기능·판정·원문 위치만 가리킨다. 다른 보고서 예시나 재분석 결과는 reportSnapshotId가 달라 같은 sequence를 재사용할 수 있다.

### 13.2 적격성과 상태

| 상태       | 진입 조건                                                               | 표시와 행동                                                                           |
| ---------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| READY      | 비교 대상이 확정되고 생태계 핵심 결과 Snapshot 생성 가능, 기능 비교 결과가 각 현재 선택 버전과 일치                | 패키지·기간·직접 Dependency 필터·Version Share 기준일·기능 비교 버전·자료 상태 확인,`PDF 생성` |
| GENERATING | 생성 요청 완료                                                          | 생성 단계와 진행 안내, 창을 닫아도 계속됨                                             |
| COMPLETE   | 파일 생성 완료                                                          | 자동 다운로드, 파일명·생성 시각·크기 표시,`PDF 다시 받기`                         |
| FAILED     | PDF 생성 작업 시작 후 파일 생성 실패                                   | 생성 실패임을 표시하고 완료 파일/`PDF 다시 받기`를 노출하지 않음                    |
| BLOCKED    | 비교 대상 미확정, 최초 생태계 핵심 결과 미완료, Snapshot 생성 불가 오류, 기능 비교 미실행 또는 선택 버전과 결과 불일치 | 이유 표시, 생태계 보고서 또는 기능 비교로 이동                                                       |

기능 비교 버전 변경·재분석 상태는 PDF의 BLOCKED 조건이다. 사용자가 버전을 바꾸면 기존 기능 비교 결과는 읽기 전용으로 남기되, 새 선택 버전의 분석이 완료될 때까지 PDF 생성은 막는다.

다운로드만 실패한 경우 보고서를 다시 만들지 않고 준비된 동일 파일을 다시 받는다.

### 13.3 부분 결과 허용

- 일부 기간 자료 없음
- 일부 직접 Dependency 자료 부족

- 후보 API `NO_DATA`

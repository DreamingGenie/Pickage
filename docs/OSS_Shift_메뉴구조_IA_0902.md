# OSS Shift 메뉴와 화면 구조 0902

작성 기준일: 2026-09-02  
문서 상태: 최종본  
연결 문서: `OSS_Shift_요구사항_명세서_0902.md`, `OSS_Shift_서비스_기획서_0902.md`  
Figma 기준: OSS Shift Web Service Wireframe V1

이 문서는 메뉴, 화면 계층, 화면 안 정보 위치, 사용자의 조작과 화면·상태 이동을 정의한다. 데이터 수집·분석·저장 방법은 개발 구상안에서 다룬다.

## 1. IA 적용 원칙

1. 사용자는 입력 단계에서 패키지만 선택한다.
2. 버전은 후보 선택이 끝난 뒤 보고서 안에서 확인·선택한다.
3. 기준 패키지는 고정 선택하고 관련 후보 상위 2개는 기본 선택하되 사용자가 변경할 수 있다.
4. 비교 대상은 기준 패키지를 포함해 총 3개로 제한한다.
5. 보고서는 생태계 변화와 기능 비교를 같은 상단 구조 안에서 제공한다.
6. Dependency 표시 버전과 기능 비교 버전은 각 페이지 안에 배치한다.
7. 핵심 결과를 먼저 보여주고 상세 근거는 Drawer로 분리한다.
8. PDF는 보고서 상단의 공통 행동으로 제공한다.
9. 자료 부족·부분 완료·오류는 결과가 나타나는 바로 그 영역에서 표시한다.
10. 보고서 화면에서는 추천·순위·승자 표현을 사용하지 않는다.
11. 키보드 포커스와 상태 문구를 제공하고 색상만으로 의미를 전달하지 않는다.
12. 사용자 화면의 저장소·출처 식별 정보는 외부 링크로 동작하지 않는다.

## 2. 화면 용어

| 사용 용어 | 의미 | 사용 위치 |
|---|---|---|
| 관련 후보 | 입력 패키지와 의미가 가까운 실제 npm 패키지 | 화면-02 |
| 비교 대상 | 사용자가 확정한 최대 3개 패키지 | 화면-02, 보고서 상단 |
| 생태계 변화 | Dependency, Activity, Version Share | 보고서 1페이지 |
| 기능 비교 | 정확한 버전의 환경·기능·근거 비교 | 보고서 2페이지 |
| 미확인 | 기능을 확정할 근거가 없거나 충돌함 | 기능표, Drawer, PDF |
| Evidence Drawer | 선택한 기능 셀의 판정·근거 패널 | 보고서 2페이지 |
| PDF 내보내기 | 완료된 전체 보고서를 공유 문서로 생성 | 보고서 공통 상단 |

`확인 불가`, `대시보드`, `최고의 대안`, `추천 1위`, `승자`는 사용자 화면에 사용하지 않는다.

## 3. 메뉴와 화면 계층

### 3.1 상단 메뉴

- 서비스 소개
- 패키지 분석

보고서는 별도 최상위 메뉴가 아니라 패키지 분석 흐름의 결과다.

### 3.2 전체 계층

```text
서비스 소개
└─ 패키지 입력
   └─ 후보 선택
      └─ 보고서
         ├─ 1. 생태계 변화
         │  ├─ Dependency
         │  ├─ Activity
         │  └─ Version Share
         ├─ 2. 기능 비교
         │  ├─ 핵심 환경·설치 조건
         │  ├─ 핵심 기능 비교
         │  ├─ 기능 비교 버전 선택
         │  ├─ 분석 진행·완료 상태
         │  ├─ 기능 비교 해설
         │  └─ Evidence Drawer
         ├─ 3. GitHub 커뮤니티 현황 [확장]
         └─ PDF 내보내기
            ├─ 내보내기 확인
            ├─ 생성 중
            ├─ 다운로드 완료
            └─ 생성 불가
```

### 3.3 기본 이동

| 현재 화면 | 사용자 행동 | 이동·상태 | 유지되는 정보 |
|---|---|---|---|
| 서비스 소개 | 패키지 분석 시작 | 패키지 입력 | 없음 |
| 패키지 입력 | 확인 성공 후 다음 | 후보 선택 | 기준 패키지명 |
| 후보 선택 | 분석 시작 | 보고서 생태계 변화 | 최종 비교 대상 |
| 생태계 변화 | 기능 비교 탭 | 기능 비교 | 비교 대상, 페이지별 필터 |
| 기능 비교 | 생태계 변화 탭 | 생태계 변화 | 비교 대상, 기능 버전·결과 |
| 보고서 | GitHub 커뮤니티 탭 | GitHub 커뮤니티 [제공 가능할 때만] | 비교 대상, 패키지별 커뮤니티 상태 |
| 보고서 | PDF 내보내기 | 확인 또는 생성 불가 상태 | 완료 보고서 상태 |

## 6. 화면-02 후보 선택

Figma: `220:196`

### 6.1 화면 구성

1. 공통 헤더·단계 표시
2. 제목과 기본 선택 규칙
3. 기준 패키지 표시: 고정 선택, 해제 불가
4. 기준 패키지를 제외한 관련 후보 카드 최대 3개
5. 최대 선택 안내
6. 직접 추가 입력
7. 하단 고정 선택 바

### 6.2 후보 카드

| 정보 | 위치 | 표시 규칙 |
|---|---|---|
| 패키지명 | 카드 상단 | 가장 강조 |
| 선택 표시 | 카드 우측 상단 또는 테두리 | 선택 상태 즉시 확인 |
| 짧은 설명 | 패키지명 아래 | 최대 지정 줄 수로 축약 |
| 설명 유사도 | 카드 본문 | 관련성 근거로 표시 |
| 공통 키워드 | 카드 본문 | 태그 형태 |
| 최근 배포일 | 카드 하단 | 날짜만 표시 |
| 버전 | 표시하지 않음 | 보고서에서 선택 |

기준 패키지는 후보 카드에 다시 넣지 않는다. 기준 패키지 영역과 후보 카드 3개는 서로 다른 집합이며, 최종 선택 수는 두 영역을 합쳐 최대 3개다.

### 6.3 선택 동작

| 상태·행동 | 결과 | 안내 |
|---|---|---|
| 최초 진입 | 기준 패키지 + 상위 후보 2개 선택 | `3 / 3 선택됨` |
| 기준 패키지 선택 | 고정 상태 유지 | 비교의 출발점이므로 해제할 수 없음 |
| 선택 후보 클릭 | 해당 후보 해제 | 하단 목록·개수 갱신 |
| 미선택 후보 클릭, 현재 2개 이하 | 후보 선택 | 하단 목록·개수 갱신 |
| 미선택 후보 클릭, 현재 3개 | 선택 적용 안 함 | 기존 후보 1개 해제 안내 |
| 직접 추가 성공, 현재 2개 이하 | 사용자 추가 항목으로 목록에 추가·선택 | 후보 순위는 유지, 추가 패키지 강조 |
| 직접 추가, 현재 3개 | 추가 적용 안 함 | 기존 후보 해제 안내 |
| 직접 추가 패키지 미존재 | 입력값 유지 | 인라인 오류 |

서비스가 사용자의 기존 선택을 자동 해제해서는 안 된다.

### 6.4 하단 고정 선택 바

| 요소 | 위치 | 동작 |
|---|---|---|
| 선택 패키지 목록 | 좌측 | 현재 선택 실시간 반영 |
| 선택 개수 | 목록 인접 | `N / 3 선택됨` |
| 분석 시작 | 우측 | 선택 패키지를 확정하고 보고서 이동 |

## 7. 화면-03 보고서 공통

### 7.1 공통 상단

| 요소 | 위치 | 동작 |
|---|---|---|
| 분석 결과 제목 | 본문 상단 좌측 | 현재 보고서임을 표시 |
| 비교 패키지 | 제목 아래 | 패키지명만 표시 |
| PDF 내보내기 | 상단 우측 | 적격성 확인 후 상태 화면 |
| 보고서 탭 | 제목 영역 아래 | 생태계 변화 ↔ 기능 비교 |

확장 자료가 있는 경우 같은 위치에 `GitHub 커뮤니티` 탭을 추가한다. 비교 대상 전체에서 검증된 저장소가 하나도 없으면 탭을 표시하지 않는다.

공통 상단에 하나의 전역 분석 버전을 표시하지 않는다. 버전은 각 데이터가 사용되는 카드 안에서 표시한다.

## 8. 보고서 1페이지 생태계 변화

Figma: `220:197`, 상태 예시 `220:199`

### 8.1 페이지 순서

1. 공통 상단
2. Dependency 카드

### 8.2 Dependency 카드

| 요소 | 위치 | 기본 상태 | 행동 | 결과 |
|---|---|---|---|---|
| 카드 제목·설명 | 좌측 상단 | 표시 | 없음 | 데이터 의미 확인 |
| 직접/간접 의존 전환 | 우측 상단 | 직접 의존 | 클릭 | 같은 카드 그래프 변경 |
| 패키지 범례 | 그래프 상단 | 전체 패키지 | 없음 | 선 구분 |
| 시계열 그래프 | 중앙 | Total 추이 | Hover 등 | 시점별 값 확인 |
| 패키지별 드롭다운 | 그래프 아래 | 각각 Total | 특정 버전 선택 | 해당 패키지 선만 변경 |
| 유지·유입·이탈 | 카드 하단 | 요약 값 | 없음 | 변화 성격 확인 |
| 기간·출처 | 카드 하단 우측 | 표시 | 없음 | 관측 범위 확인 |

세 드롭다운은 서로 독립적이다. Dependency 드롭다운을 변경해도 기능 비교 버전이나 기능 결과는 바뀌지 않는다.

### 8.3 Dependency 상태

| 상태 | 화면 처리 |
|---|---|
| 드롭다운 열림 | Total과 사용 가능한 버전 목록 표시 |
| 특정 버전 선택 | 선택값을 드롭다운에 표시, 해당 선만 갱신 |
| 일부 기간 | 가능한 선 구간만 표시, 경고 문구 |
| 자료 없음 | 그래프 영역 안에 자료 없음과 범위 표시 |
| 오류 | 이전 정상 결과가 있으면 유지, 오류 표시 |

### 8.4 Activity 카드

| 요소 | 위치 | 기본 상태 | 동작 |
|---|---|---|---|
| Downloads/Issues | 우측 상단 | Downloads | 확장 시 Issues 전환 |
| 그래프 | 중앙 | Downloads 시계열 | 선택 탭에 따라 갱신 |
| 기간·출처 | 하단 | 항상 표시 | 자료 구간 확인 |

Issues 시계열은 GitHub 커뮤니티 3페이지가 아니라 이 카드에서 시각적으로 제공한다.

### 8.5 Version Share 카드

| 요소 | 위치 | 기본 상태 | 동작 |
|---|---|---|---|
| 패키지 탭 | 카드 상단 | 기준 패키지 | 다른 패키지 전환 |
| 도넛 | 좌측 | 전체 관측 비중 | 버전 조건 분포 확인 |
| 계열 막대 | 우측 | 버전 계열별 | 비중 확인 |
| 해석 불가 | 막대 하단 | 별도 표시 | 임의 버전 편입 없음 |
| 해석 안내 | 카드 하단 | 항상 표시 | 실제 설치 버전 오해 방지 |

## 9. 보고서 2페이지 기능 비교

Figma: `220:198`, 상태 예시 `220:199`

### 9.1 페이지 순서

1. 공통 상단
2. 기능 비교 버전 선택
3. 분석 진행·완료 상태
4. 핵심 환경·설치 조건 표
5. 핵심 기능 비교표: 근거가 충분하면 5~7개
6. 기능 비교 해설

Figma의 실제 배치처럼 버전 선택과 분석 상태를 먼저 두되, 최신 안정 버전을 자동 선택하고 완료 결과를 즉시 노출한다. 따라서 사용자는 별도 설정을 마쳐야만 표를 볼 수 있는 흐름을 거치지 않는다.

### 9.2 핵심 비교표

| 요소 | 위치 | 동작 |
|---|---|---|
| 기능명 | 첫 열 | 비교 기준 표시 |
| 패키지별 판정 | 각 패키지 열 | 지원·조건부·제한적·미확인 표시, 데이터 셀 전체가 Drawer 열기 대상 |
| evidence ID | 판정 아래 | 셀과 동일한 Drawer 열기 대상 |
| 표 하단 안내 | 카드 하단 | 검색 실패와 미지원 구분 |

긴 조건 설명과 발췌는 표 안에 넣지 않고 Drawer와 하단 해설로 분리한다.

근거가 충분한 기능이 5개보다 적으면 확인 가능한 항목만 표시하고 표 상단에 `직접 비교 가능한 기능이 제한적입니다`를 표시한다.

### 9.3 기능 비교 버전 선택

| 상태·행동 | 화면 표시 | 결과 |
|---|---|---|
| 최초 완료 | 패키지별 최신 안정 버전 | 현재 결과 즉시 표시 |
| 정식 버전 없음 | 자동 선택 없음 | 사전 배포 버전임을 표시하고 사용자 선택 대기 |
| 드롭다운 변경 | 선택 버전과 완료 결과 버전 구분 | `재분석 필요` |
| `선택한 버전으로 재분석` 선택 | 이전 정상 결과 유지, 진행 상태 표시 | 새 분석 시작 |
| 재분석 성공 | 변경점 요약 1회 | 새 결과로 교체 |
| 재분석 실패 | 실패 메시지 | 이전 결과 유지 |
| 일부 완료 | 영향받는 셀만 미확인 | 확인 가능한 결과 제공 |

### 9.4 분석 진행 상태

핵심 결과가 아직 없는 최초 분석에서는 결과 영역에 skeleton을 사용한다. 실제 완료 단계의 메시지만 차례로 표시한다. 버전 변경 재분석에서는 기존 결과를 그대로 두고 별도 상태 카드로 진행을 표시한다.

### 9.5 기능 비교 해설

| 구역 | 내용 |
|---|---|
| 공통 기반 | 여러 패키지에 공통으로 확인된 기능·조건 |
| 구성 방식 차이 | 같은 목적을 다른 API·구조로 제공하는 차이 |
| 상황별 확인 기준 | 환경·타입·브라우저 등 사용자가 추가 확인할 조건 |
| 하단 고지 | 추천·순위·승자 없음, 미확인은 미지원이 아님 |

## 10. Evidence Drawer

Figma: 축약 예시 `220:200`, 상세 상태 `315:236`

### 10.1 배치와 기본 동작

| 환경 | 위치·크기 | 배경 | 닫기 |
|---|---|---|---|
| 데스크톱 | 화면 우측 560px 오버레이 | 비교표 노출·선택 셀 강조·나머지 흐림 | X, 바깥, ESC |
| 모바일 | 전체 높이 하단 시트 | 뒤 화면 고정 | X, 아래로 닫기 |

Drawer 헤더와 패키지 탭은 고정하고 본문만 스크롤한다.

Drawer가 열리면 헤더 제목으로 포커스를 이동하고 내부에 포커스를 유지한다. 닫으면 Drawer를 열었던 비교표 셀로 포커스를 돌려보낸다.

### 10.2 내부 순서

1. 닫기와 제목
2. 패키지 탭
3. 판정 요약
   - 패키지·정확한 버전
   - 기능·판정
   - 한 문장 이유
   - 근거 수·분석일·자료 상태
4. 판정 설명
5. 역할별 근거
6. 기술 정보 접힘 영역
7. 근거 ID·분석 정보 복사

### 10.3 상태별 화면

| 상태 | 상단 판정 | 본문 |
|---|---|---|
| NORMAL | 지원·조건부·제한적 | 지원 근거와 조건·제한 근거 |
| UNKNOWN | 미확인 | 확인한 자료와 발견되지 않은 범위, 검색 실패≠미지원 |
| CONFLICT | 미확인·근거 충돌 | 지원 가능 근거와 제한 가능 근거를 모두 보존 |

### 10.4 근거 펼침

- 근거 그룹별 핵심 근거 1개 기본 펼침
- 나머지 근거 접힘
- 발췌 기본 3줄
- `근거 발췌 더보기` 선택 시 최대 10줄
- 전체 문서·전체 섹션·외부 원문 이동 없음
- source excerpt와 서비스 해석을 다른 구역으로 표시
- 근거 ID·분석 정보 복사 완료는 버튼 주변의 짧은 상태 문구로 표시

## 11. 확장 3페이지 GitHub 커뮤니티 현황

Figma: `239:227`

### 11.1 페이지 순서

1. 제목과 `Issue 추이는 1페이지 Activity에서 확인` 안내
2. 비교 패키지 탭
3. 저장소 연결·범위·조회 시점
4. 최근 릴리스·커밋·열린 Issue·PR 간략 요약
5. 현재 커뮤니티 논의
6. 표시 원칙
7. 자료 한계

패키지 탭에는 최종 비교 대상 순서를 사용한다. 저장소 연결이 검증된 첫 패키지를 기본 선택하고, 검증되지 않은 패키지는 비활성 탭과 이유를 표시한다. 저장소 주소는 읽기 전용이며 외부로 이동하지 않는다.

### 11.2 논의 항목 구성

| 정보 | 위치 |
|---|---|
| 논의 제목 | 항목 상단 좌측 |
| Issue/PR 번호·상태 | 상단 우측 |
| 주요 주장과 입장 차이 | 제목 아래 첫 문단 |
| 진행 중인 작업 | 두 번째 문단 |
| 합의 상태 | 항목 하단에 `합의됨`·`논의 중`·`입장 차이 유지 중`으로 구분 |

본문은 수치 카드보다 넓은 영역을 사용하며, 무엇을 논의·검토·구현 중인지 이해할 수 있는 글을 중심으로 한다.

## 12. PDF 내보내기

Figma 상태: `322:236`, 문서 레이아웃: `323:236`

PDF는 영역별 선택 없이 `전체 보고서 PDF 1종`으로 제공한다.

### 12.1 진입

보고서 공통 상단의 `PDF 내보내기`를 선택하면 서비스가 먼저 생성 가능 여부를 확인한다.

### 12.2 READY 확인 화면

| 구역 | 표시 정보 |
|---|---|
| 상단 | PDF 내보내기 제목과 닫기 |
| 비교 대상 | 최종 패키지명 |
| 기능 분석 버전 | 패키지별 정확한 버전 |
| 조회 기간 | 생태계 기간 |
| Dependency 표시 | 패키지별 Total 또는 선택 버전 |
| 포함 내용 | 생태계 변화·기능 비교·근거 요약·제공 가능한 모든 비교 패키지의 커뮤니티 |
| 자료 상태 | 전체·부분·미확인 수 |
| 하단 | 취소, PDF 생성 |

사용자는 이 화면에서 문서 구성을 편집하지 않는다.

### 12.3 생성 상태

| 상태 | 표시 | 행동 |
|---|---|---|
| GENERATING | `PDF를 만들고 있습니다`, 단계별 진행 | 창 닫기 가능 |
| COMPLETE | 파일명, 생성 시각, 페이지 수, 크기 | 자동 다운로드, PDF 다시 받기 |
| 다운로드 실패 | 동일 파일 준비 상태 유지 | PDF 다시 받기 |
| BLOCKED | 차단 이유, 선택 버전과 완료 버전 | 기능 비교로 이동 |

### 12.4 PDF 물리 구조

- 표지·요약
- 생태계 변화: Downloads, Dependency와 표시 필터, 유지·유입·이탈, Version Share, 제공 가능한 Issues
- 기능 비교: 분석 버전, 핵심 환경, 핵심 기능표, 중립 해설
- 판정·해설에 실제 연결된 근거 요약 부록
- 자료가 있으면 제공 가능한 비교 패키지의 GitHub 커뮤니티 자동 포함
- 실제 용지 수는 콘텐츠 길이에 따라 증가

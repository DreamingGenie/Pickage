- 서비스명을 `Pickage`로 변경한다.
- Version Share를 시계열이 아닌 **최신 집계 기준일 Snapshot**으로 확정한다.
- 기능-03 후보 제공은 description·keywords 의미 유사도만으로 최종 정렬하지 않고, cos 유사도 기반 score에 dependents 교집합 `>0.3` 보완재 감점·자격 미달 drop(deprecated 후보 완전 제외 포함)을 반영하는 후보 ranking으로 변경한다(`DEC-RANK-20260909-01`, 관측된 대체 이동 신호(`move_lift`)·대체 이동 쌍 가산은 v1 ranking에 사용하지 않음).
- 후보 ranking의 v1 내부 계산식·계수·필터는 개발 구상안의 시스템 아키텍처 확정안을 따르며 사용자 화면에는 품질 점수로 노출하지 않는다.

- 기능 비교 확장은 `구조화 데이터 + AI + RAG`를 우선 검토하고, 구조화 데이터 계층이 현실적으로 어렵다면 `AI + RAG`로 축소한다.
- MVP PDF는 생태계 보고서만으로 생성할 수 있으며 기능 비교 미제공·미완료를 차단 조건으로 사용하지 않는다.

## 1. 서비스 범위와 원칙

### 1.1 서비스 한 문장

Pickage는 사용자가 검토 중인 npm 패키지를 입력하면 의미적 관련성과 공개 생태계 신호를 함께 고려한 관련 후보를 보여주고, 사용자가 확정한 최대 3개 패키지의 직접 의존 관계·Downloads·최신 Version Share Snapshot을 비교하도록 돕는 서비스다.

### 1.2 사용자

| 사용자      | 사용 상황                                                | 필요한 결과                                                                                           |
| ----------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 주 사용자   | 새 프로젝트 도입 또는 기존 npm 패키지 교체 검토          | 현실적인 관련 후보, 직접 Dependency 변화, Downloads, 최신 버전 분포, 자료 범위                        |
| 확장 사용자 | 정확한 버전 기능·근거 또는 저장소의 현재 논의 추가 검토 | RAG 기반 기능 비교 근거와 상단 요약·수치, 핵심 이슈·쟁점, 실제 논의 흐름으로 구성된 커뮤니티 보고서 |

회원가입·로그인은 전제로 하지 않는다.

### 1.3 MVP와 확장

| 구분      | MVP                                                                          | 확장                                                            |
| --------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 입력      | npm 패키지명                                                                 | 동일                                                            |
| 후보      | 의미 관련성 + 공개 생태계 신호 기반 후보 최대 3개                            | ranking 고도화 가능                                             |
| 비교 대상 | 기준 패키지 포함 총 3개                                                      | 동일                                                            |
| 보고서 1  | 직접 Dependency, Downloads, 직접 의존 관계 변화, 최신 Version Share Snapshot | 간접·전이 Dependency, Issues, 버전 고착 심화, 관측된 교체 흐름 |
| 보고서 2  | 없음                                                                         | 정확한 버전 기능 비교, 재분석, 중립 해설, Evidence Drawer       |
| 보고서 3  | 없음                                                                         | GitHub 커뮤니티 현황                                            |
| PDF       | 완료된 생태계 보고서                                                         | 완료된 확장 결과가 있으면 해당 구역 자동 포함 가능              |

### 1.4 적용 원칙

0. 사용자 화면 제공 범위는 데스크톱 컴퓨터의 웹 브라우저만으로 한정한다.
1. 후보 제공은 비교 후보 발견 기능이며 기술 우열이나 최종 선택을 의미하지 않는다.
2. 후보 이름 생성·후보 순서 변경에 생성형 AI를 사용하지 않는다.
3. 의미 유사도 하나 또는 popularity 지표 하나만으로 최종 후보를 정하지 않는다.
4. 후보 ranking은 cos 유사도 기반 score에 dependents 교집합 `>0.3` 보완재 감점, 자격 미달 drop(deprecated 후보 완전 제외 포함)을 반영하는 v1 ranking 계약(`DEC-RANK-20260909-01`)을 따른다. 관측된 대체 이동 신호(`move_lift`)·대체 이동 쌍 관측 가산은 v1 ranking에 사용하지 않는다.
5. v1 내부 ranking 계산식과 계수는 개발 구상안에서 확정하며 요구사항 화면에는 점수나 계수로 노출하지 않는다.
6. 기준 패키지는 비교의 출발점으로 고정하고, 상위 후보 2개는 기본 선택 상태로 제공하되 사용자가 변경할 수 있다.
7. 최종 비교 대상은 기준 패키지를 포함해 최대 3개다.
8. 후보 단계에서는 버전을 선택하거나 확정하지 않는다.
9. MVP Dependency는 직접 의존만 제공한다. 간접·전이 의존은 확장이다.
10. Version Share는 최신 Snapshot으로 제공하고 시간축을 사용하지 않는다.
11. 화면에 표시하는 숫자 0, 자료 없음, 부분 자료, 처리 오류, 미검증 신호를 구분한다.
12. 보고서에서는 추천, 순위, 승자, 최종 선택을 제시하지 않는다.
13. 화면과 PDF는 완료된 동일 생태계 보고서 Snapshot을 사용한다.
14. 색상만으로 선택·자료 상태를 구분하지 않고 문구·아이콘을 함께 사용한다.
15. 기능 비교 확장이 제공될 경우 근거가 없거나 충돌하면 임의로 지원 또는 미지원으로 판정하지 않는다.

## 3. 전체 사용자 흐름

1. 사용자는 서비스 소개에서 제공 범위와 판단 한계를 확인한다.
2. 화면-01에서 npm 패키지명을 입력하고 존재 여부를 확인한다.
3. 화면-02에서 기준 패키지와 후보 ranking 상위 2개를 확인한다.
4. 후보를 해제하거나 다른 npm 패키지를 추가해 총 3개 이내로 비교 대상을 확정한다.
5. 보고서 1페이지에서 직접 Dependency, Downloads, 직접 의존 기준 유지·유입·이탈, 최신 Version Share Snapshot을 확인한다.
6. Dependency는 패키지별 `Total`로 시작하며 필요하면 특정 버전의 직접 의존 추이로 바꾼다.
7. Version Share는 최신 Snapshot 기준일과 버전 계열별 비중을 확인한다.
8. PDF 내보내기 조건을 만족하면 완료된 생태계 보고서 PDF를 생성하고 다운로드한다.

확장 기능이 제공되는 경우 사용자는 보고서 탭에서 기능 비교 또는 GitHub 커뮤니티 현황으로 이동할 수 있다. 기능 비교 확장의 분석·재분석 상태는 MVP 생태계 보고서 및 기본 PDF 적격성을 변경하지 않는다.

## 10. 확장: 보고서 2페이지 기능 비교

이 기능은 MVP 완료 조건이 아니다. 구현은 `구조화 데이터 + AI + RAG`를 우선 검토하며, 구조화 데이터 계층의 수집 가능성·정확도·비용이 충분하지 않으면 `AI + RAG`로 축소한다. 어느 방식이든 검색된 근거와 생성 결과의 연결을 검증한다.

### 10.1 확장 구현 조건과 최신 결과 우선 화면 구성

### 10.3 분석 진행 상태 [확장]

버전 선택 영역 바로 아래에 분석 상태를 표시한다. 최초 분석 중에는 결과 위치에 빈 완성 문장을 만들지 않고 다음과 같은 실제 완료 단계를 순차 표시한다.

- 정확한 버전과 배포 자료를 확인하고 있습니다.
- 실행 환경과 공개 진입 정보를 확인하고 있습니다.
- 기능 근거를 정리하고 있습니다.
- 근거를 기능 판정과 연결하고 있습니다.
- 비교 해설을 작성하고 있습니다.

완료되지 않은 단계는 완료된 것처럼 표시하지 않는다. 해설 생성만 실패하면 비교표와 근거는 계속 제공한다.

### 13.2 적격성과 상태

| 상태       | 진입 조건                                                               | 표시와 행동                                                                           |
| ---------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| READY      | 비교 대상이 확정되고 생태계 핵심 결과 Snapshot 생성 가능                | 패키지·기간·직접 Dependency 필터·Version Share 기준일·자료 상태 확인,`PDF 생성` |
| GENERATING | 생성 요청 완료                                                          | 생성 단계와 진행 안내, 창을 닫아도 계속됨                                             |

| BLOCKED    | 비교 대상 미확정, 최초 생태계 핵심 결과 미완료, Snapshot 생성 불가 오류 | 이유 표시, 생태계 보고서로 이동                                                       |

기능 비교 버전 변경·재분석 상태는 MVP PDF의 BLOCKED 조건이 아니다. 확장 결과를 PDF에 포함할 때는 해당 확장 결과의 완료 여부를 별도로 검사한다.

다운로드만 실패한 경우 보고서를 다시 만들지 않고 준비된 동일 파일을 다시 받는다.

### 13.3 부분 결과 허용

다음은 완료된 결과로 간주해 경고와 함께 PDF에 포함할 수 있다.

- 일부 기간 자료 없음
- 일부 직접 Dependency 자료 부족
- Version Share 해석 불가 조건
- 후보 ranking 신호 일부 미검증
- 확장 GitHub 보조 자료 일부 실패

### 13.4 PDF 구성

MVP:

1. 표지·요약
2. 후보·비교 대상과 분석 범위
3. Downloads
4. 직접 Dependency와 적용 필터, 유지·유입·이탈
5. 최신 Version Share Snapshot과 기준일
6. 자료 상태·해석 한계

확장 결과가 완료된 경우 추가 가능:

7. 기능 비교와 근거 요약
8. GitHub 커뮤니티 현황

## 15. 제공하지 않는 기능

### MVP에서 제공하지 않음

- 간접·전이 Dependency 분석
- 기능 비교·기능 버전 재분석·Evidence Drawer
- GitHub 커뮤니티·Issues 시계열
- 버전 고착 심화·관측된 교체 흐름
- 전체 분석 이력 탐색

### 서비스 전체에서 제공하지 않음

- 회원가입·로그인·조직 권한·결제
- `package.json` 업로드 분석
- 사람이 사전 등록한 비교 묶음
- 생성형 AI 기반 후보 이름 생성·후보 순서 임의 변경
- 기술 우열 점수·최종 자동 추천·승자 표시
- 실제 설치·실행·호출량 추정
- 코드 자동 수정·패키지 자동 교체
- 교체 원인·미래 생존 예측
- 확장 Drawer의 외부 원문·npm·GitHub·deps.dev 이동
- PDF의 섹션 선택·현재 화면만 내보내기
- npm 이외 생태계 지원

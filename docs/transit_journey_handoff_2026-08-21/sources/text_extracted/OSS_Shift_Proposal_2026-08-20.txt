Executive Summary
장기간운영할신규서비스나핵심기능에 OSS dependency 를도입할때 Tech Lead 는일반적으로 Stars,
downloads, release freshness, vulnerability, maintainer activity 와같은신호를본다. 이신호들은중요하
지만 공개 package ecosystem 에서실제 dependency 선택행동이어떻게변하고있는지를직접설명하지않는
다.


  OSS Shift 가답하려는핵심질문
  공개 npm package 들이 A 를계속새로선택하는가? 이미 A 를사용하던 package 는다음 release 에서도
  유지하는가? A 가제거될때특정대안이반복적으로함께추가되는가? 아니면여러 destination 으로분산되
  는가?

OSS Shift 는 공 개 npm package 의 version 별 regular dependency declaration history를 분 석 해
Adoption, Retention, Exit, Transition Candidate 를계산한다. 그뒤 Behavior 와 Movement 를 deter‑
ministic rule 로판정하고, 중요한 transition 에한해서실제 GitHub PR/commit evidence 를결합한다.
제품은특정 library 를자동추천하거나미래에죽을 package 를예측하지않는다. 최종적으로지원하는판단은세가
지뿐이다.


   Review Action          의미

   Proceed to Review      강한 ecosystem shift signal 이없어일반적인기술검토를계속
   Compare     Alterna‑   본격검토전에 functional alternatives 를함께비교할근거가있음

Analysis Unit and Mainline



원자단위
dependent package P 의 mainline releases 를 r1 , r2 , . . . , rn , release ri 의 regular dependency set 을
D(P, ri ) 라고한다. 기본 observation 은연속 release transition 이다.


                                           Ti = (ri−1 → ri )

예를들어 D(P, r1 ) = {A, C}, D(P, r2 ) = {B, C} 이면 A 는 REMOVED, B 는 ADDED, C 는 RETAINED 다. 이
단계에서는 A 에서 B 로 migration 했다고부르지않는다.

Transition Contract



Transition Candidate
같은 release transition 에서 A 가 REMOVED 되고 B 가 ADDED 되면:


                               T ransitionCandidate(P, A, B, t)

를만든다. 의미는 same‑release co‑change correlation까지이며 migration intent 가아니다.

Pair Complexity
한 transition 에서 removed dependency 가 m 개, added dependency 가 n 개라면 potential pair 는:


                                  P airComplexity = m × n

이다. Pair Complexity 가커질수록 unrelated co‑change false positive 와 candidate row expansion/shuf‑
fle 이함께증가한다. 따라서이후 quality gate 는제품정확성과 distributed cost 를동시에개선하는지점이된
다.

기록한다.

  fetch 를사용했는지여부는 npm dependency declaration 만으로확인할수없다. 강한해석은 reposi‑
  tory evidence 가필요하다.

State Rules



Stable

   BEHAVIOR_SUPPORT_OK
   AND NEUTRAL(CohortPresenceShare)
   AND NEUTRAL(CohortSwitchInShare)
   AND NEUTRAL(ExitRate)
   AND RetentionRate in calibrated stable range

Growing

   UP(CohortPresenceShare)
   AND (UP(CohortSwitchInShare) OR DOWN(ExitRate))

observable cohort 안에서 A 의선택/유지 behavior 가상대적으로강화되는경우다.

Mature Stable

release cadence 가 calibrated mature band 에있는경우다. GitHub commit frequency 는 Core State 에
넣지않는다. GitHub coverage 차이가 State 를왜곡하면안되기때문이다.

Weakening
한 signal 하나로판정하지않는다.


   DOWN(CohortPresenceShare) AND [DOWN(CohortSwitchInShare) OR UP(ExitRate)]
   OR
   DOWN(CohortSwitchInShare) AND UP(ExitRate)

즉적어도두개의 independent weakening signals 을요구한다.

Directional Shift
Weakening behavior 에더해 Exit 증가, sufficient Movement support, sufficient Replacement Cover‑
age, 높은 TopDestinationShare, 낮은 entropy, 높은 HHI, independent evidence gate 를모두통과해야한
다.
제품문장은 “A Exit 와같은 release 에서특정 B 가추가되는 repeated functional flow 가한 destination
으로집중되어관찰됨” 까지다. intentional migration 을자동주장하지않는다.

Fragmenting
Weakening 과 Exit 증가가존재하고, sufficient Movement support 와 Replacement Coverage 를확보했지
만 destination 이여러곳으로퍼져높은 entropy, 낮은 HHI, 낮은 TopDestinationShare 를보이면 Fragment‑
ing 으로본다. Directional 과 Fragmenting 사이 gray zone 이면억지로 label 을고르지않고 Weakening 으
로남긴다.

Cohort Contraction
CohortFootprint 가하락하고 cohort‑wide 신규선택 intensity 감소또는 cohort‑wide Exit 증가가함께나타
날때 context 후보가된다. focal A 의 relative CohortPresenceShare 가 cohort 전체보다유의하게더나쁘지
않을때 Display State 를 Cohort Contraction 으로올린다.

Insufficient Evidence
recent/baseline coverage, eligible Exit denominator, Switch‑in support, cohort denominator, core
DQ 중하나가 calibrated minimum 에미달하면 Behavior 를보류한다. Movement support 만부족하면
Behavior 까지제거하지않고 Weakening / Movement Insufficient처럼표현한다.

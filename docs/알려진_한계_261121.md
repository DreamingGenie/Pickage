# 알려진 한계 — 운영 종료 뒤 정리 (2026-11-21)

운영 서버(EC2 두 대)는 2026-10-02 에 내렸다. 이 문서는 **끝내지 못했거나, 알고도 남긴 것** 가운데
서버가 없어 이제 저장소만으로는 고칠 수 없는 것을 모은다. 저장소만으로 고칠 수 있는 것은
여기 적지 않고 고쳤다(문서 정정·수집 스크립트·시험).

적는 기준은 둘이다. 저장소 파일로 확인되는 것만 적고, 각 항목에 근거 파일을 단다.
제품 계약 차원의 제한(패키지 3개 비교 등)은 [`README`](../README.md)의
"프로젝트 현황과 알려진 제한"에 있다.

## 1. 데이터 범위

- **"대상 46.9만"은 다운로드·기본 정보를 채운 범위다.** 대상 목록은 468,519개지만
  regular 의존자가 있는 패키지는 185,319개이고, 272,890개는 세 종류 의존자가 모두 없어 이동
  분석이 빈다([`package_dependents_exp460k_260922`](../datasets/package_dependents_exp460k_260922/README.md)).
  의존 수 추이 표는 재정렬한 10만으로 좁혔다([`datasets/targets`](../datasets/targets/README.md)).
- **재정렬 10만 중 스코프 패키지 8,283개는 다운로드 수가 비어 있다**(S15P21A506-483).
  스코프 패키지는 벌크 조회가 안 돼 하나씩 불러야 하고, 발표 전에 돌리지 못했다
  ([`datasets/targets`](../datasets/targets/README.md) §7-3).
- **주간 수집 대상은 처음의 상위 10만에 묶여 있다.** `pipeline/weekly/steps.py` 의
  `TARGETS_SOURCE` 가 `rank_top100k_20260902.csv` 고정이라, 46.9만 확장분은 09-22 에 한 번
  채운 뒤 갱신되지 않았다.
- **운영 표의 `description`·`licenses`·`repo_url` 은 2026-08-31 기준이다.** 이 열을 담은
  `versions_full` 은 월간 묶음에서만 받는다(`pipeline/collectors/bigquery/collect.py`).
- **관측 이동 경로는 대체재 추천이 아니다.** 빌더에 "도착지가 출발지의 의존인가"를 보는 축이
  없어, 부품이 딸려 온 경우(`rxjs → tslib`)가 1위로 서기도 한다
  ([`검증_교체흐름_필터일관성_260922`](검증_교체흐름_필터일관성_260922.md) §4·§5).
- **관측 불가의 신선도 칸에 3,334개(0.082%)가 한 칸 오래된 쪽으로 들어간다**
  ([`dependent_transitions_260917`](../datasets/dependent_transitions_260917/README.md) §2).

## 2. 다시 만들 수 없는 것

- **운영 `package_snapshot` 은 저장소의 절차로 같은 값을 다시 만들 수 없다.** `pg_dump`
  이관(S15P21A506-341)으로 들어와 적재 이력이 0건이었고 재구성 입력이 남지 않았다. 다운로드 수
  보정은 재적재가 아니라 열 하나만 `UPDATE` 했다
  (`pipeline/postgresql/package_snapshot/downloads_reload.py`,
  [`worklogs/S15P21A506-453`](worklogs/S15P21A506-453/)). 기존 값이 있던 행은 재계산값과
  전부 일치했지만, 그것이 보증하는 것은 계산 규칙이 같다는 것까지다. 새로 채운 행의 값을
  독립된 원천과 맞대 보지는 못했다.
- **운영 DB 의 package-version 계보 3행은 손으로 등록했다.** 의존 수 추이 교체 때 적재기의
  계보 검사가 요구한 행이 운영에 없어서, 검사를 끄지 않고 로컬 계보를 가드(부재 확인 · 행 수
  정확 일치 · 등록 뒤 1행)와 함께 넣었다
  ([`02-partition-swap-runbook`](worklogs/S15P21A506-455/02-partition-swap-runbook.md) §1.3b).
  행 수 일치는 같은 실행이라는 필요조건이지 충분조건이 아니다. 사전에 팀 합의를 받지 않고
  Jira 코멘트와 명령서로 사후에 알렸다.
- **서버 밖 백업이 없었다.** `pg_dump` 는 DB 와 같은 디스크에 쌓였고 MinIO 는 단일 드라이브였다
  ([`deploy/prod/README`](../deploy/prod/README.md) "백업"). 서버를 내린 뒤 운영 DB 는
  남아 있지 않다([`README`](../README.md) 운영 종료 안내). 저장소의 `datasets/` 와 시드가 남은 전부다.

## 3. 하지 못한 검증

- **두 EC2 분산 처리의 처리시간·결과 검증(S15P21A506-208·-256)을 하지 못했다.** 선행 작업인
  Spark 범위 분할이 끝나지 않았고, 보고서 1페이지 집계는 단일 PC 의 DuckDB 로 돌았다. 두 EC2
  실험 기록은 팀원의 것이 하나 있다
  ([`20-experiment-summary-and-engine-decision`](worklogs/raw-to-curated-pipeline/20-experiment-summary-and-engine-decision.md)).
- **주간 수집을 중간에 끊고 이어 받는 동작은 운영에서 실측하지 않았다.** 시험으로만 확인했다
  (`pipeline/weekly/test_run.py`).
- **파티션 교체 SQL 의 `cmp=sample`·`cmp=none` 은 한 번도 돌려 보지 않았다.** 운영은 `full` 만 썼다
  ([`03-mr-description`](worklogs/S15P21A506-455/03-mr-description.md) "고치지 않고 한계로 남긴 것").

## 4. 설계에 남긴 빈틈

- **주간 수집은 덜 받고도 성공으로 끝날 수 있다.** npm downloads 수집기는 실패한 작업을 같은
  실행의 끝에서 한 번 더 돌고 다시 실행하면 또 고르지만(2026-11-21 수정, S15P21A506-367),
  그래도 남는 실패는 종료 코드 0 인 채 회차 상세에만 보인다. 수정 뒤의 동작은 시험으로만
  확인했고 운영 회차로는 돌려 보지 못했다. `BLOCKED` 가 되어도 알려 주는 장치가 없다
  ([`pipeline/weekly/README`](../pipeline/weekly/README.md)).
- **파이썬 러너와 자바 백엔드가 같은 규칙을 따로 구현한다.** 실행 주 계산 · 14일 창 · 수동
  요청 대기 판정이 두 언어에 각각 있다. 2026-11-21 부터 한 규칙표
  (`pipeline/weekly/contract/weekly_rules.json`)를 양쪽 시험이 읽어 맞대지만, 구현이 둘인 것은
  그대로다. `run.json` 의 공유 스키마는 여전히 없다
  (`pipeline/weekly/` · `backend/.../WeeklyIngestService.java`).
- **파티션 교체 SQL 에 알고 남긴 것이 넷이다.** 복구가 영수증 행을 지워 되돌린 사실이 남지
  않는다 · 값 대조와 `DETACH` 사이 틈 때문에 동시 실행 금지가 전제다 · `lock_timeout` 10초라
  긴 조회와 겹치면 마지막 단계가 실패한다 · 계획이 가리킨 DB 를 사람이 운영 값과 대조해야 한다
  ([`03-mr-description`](worklogs/S15P21A506-455/03-mr-description.md)).
- **파생 데이터셋 여섯 종에 최신 회차 포인터(`_current.json`)가 없다.** 문서를 쓸 때는 회차가
  하나씩이었지만 그 뒤 `dependent-transitions`·`migration-pairs` 에 새 회차가 생겼다
  ([`pipeline/minio/README`](../pipeline/minio/README.md) "포인터가 없는 파생 데이터셋").
  업로드 스크립트의 `PASSED` 는 올린 바이트의 해시가 같다는 뜻일 뿐이다.
- **추이 응답에 조회 구간 필드가 없다**(S15P21A506-418). 발표 직전에 응답 형식을 바꾸지 않기로
  하고 닫았다.
- **Jira 에 '완료'로 닫았지만 하지 않은 것이 있다.** 업로드 스크립트 세 벌 공통화(-344)는
  "하지 않는다"로 닫았다. 스크립트 세 벌은 지금도 중복이다
  (`pipeline/minio/ingest_*.py`).

# 검증 — 관측된 교체 흐름의 필터 일관성

작성 2026-09-22 (S15P21A506-424 4층). `S15P21A506-211` 결정 4의 **마지막 남은 체크박스**를 닫기 위한 실측이다.

> \[ ] 상위 5+그 밖, 최대 6개 방향, focus 결과에서 필터 일관성을 검증한다 → API 구현 후

## 0. 한 줄 요약

**필터는 한 곳에 있고 대표 사례 5개는 전부 맞다. 잡음 3종 중 하나(딸려 들어온 부품)는 기본 필터로 걸러지지 않고, "변종" 배지는 전제가 틀려 이름을 바꿨다.**

## 1. 방법

`datasets/migration_pairs_260908/migration_pairs_all.csv`(deps.dev 전수, 16,837쌍)에 **서빙이 쓰는 규칙을 그대로** 적용했다.

| 규칙 | 값 | 어디에 있나 |
|---|---|---|
| 기본 필터 | `votes>=5 AND publisher_months>=3` | `MigrationPairFilter.MIN_VOTES` · `MIN_PUBLISHER_MONTHS` |
| 상위 | 5개, `share_pm_pct` 내림차순 | `MigrationPairFilter.TOP_DESTINATIONS` |
| 등급 | strict · recommended · loose | `MigrationPairFilter.grade()` |

값을 손으로 옮겨 적지 않고 **같은 조건식**을 썼다. 옮겨 적으면 검증이 검증하려던 것(두 곳이 갈라지는 것)을 스스로 저지른다.

## 2. 필터가 한 곳에 있는가 — **그렇다**

`-211` 결정 4가 요구한 것은 "전체 흐름 · focus · 최대 6개 방향이 같은 값을 참조" 다.

- 하한이 나오는 곳은 `MigrationPairFilter` **한 파일뿐**이다. 조회 SQL에는 하한이 없다(`PackageQueryRepository.MIGRATION_PAIRS_SQL` 은 거르지 않고 읽는다).
- 세 경로가 **한 메서드**(`PackageService.fold`)를 지난다. 상위 5도, `etc` 도, "최대 6개 방향"(`crossDirections`)도 전부 그 결과를 다시 쓴다.
- 프런트는 **하한을 다시 적용하지 않는다.** `migration-*.ts` 어디에도 `votes`·`publisherMonths` 비교가 없다.

**다만 "전체 흐름" 경로는 아직 없다.** 지금은 패키지 focus 하나뿐이라, 세 경로가 갈라질 자리 자체가 생기지 않았다. 전체 흐름을 만들 때 이 문단을 다시 확인해야 한다.

## 3. 대표 사례 5개 — **1위가 전부 맞다**

| 출발 | 1위 | 점유율 | 등급 | 관측/통과 | 합 |
|---|---|---:|---|---:|---:|
| `moment` | **dayjs** | 5.7% | strict | 53 / 26 | 21.7% |
| `request` | **axios** | 12.4% | strict | 84 / 41 | 44.4% |
| `node-sass` | **sass** | 14.0% | strict | 37 / 19 | 30.9% |
| `chalk` | **picocolors** | 3.0% | strict | 114 / 60 | 28.9% |
| `lodash` | **lodash-es** | 5.4% | strict | 267 / 140 | 38.6% |

사람이 아는 답과 다섯 개 모두 일치한다. 2·3위도 납득 가능하다 — `moment` → date-fns · luxon, `request` → node-fetch · got.

### 3-1. 실제 화면은 **빗금이 대부분**이다

합이 21.7~44.4% 다. 즉 막대의 **56~78%가 "근거가 약해 집계에서 뺀" 빗금**이 된다. 계약대로의 동작이지만(분모가 적재되지 않은 쌍까지 포함), 처음 보면 "자료가 없는 것" 으로 읽힐 수 있다.

mock 픽스처를 이 모양으로 맞췄다(`winston` = 실제 `moment` 의 수). **mock 이 더 후하면 리뷰어가 화면의 진짜 모습을 못 본다.**

## 4. 잡음 3종 — 하나는 못 거른다

### ① 한 조직의 대청소 — **걸러진다**

`votes` 는 큰데 조직·달이 적은 쌍 **702개가 전부 기본 필터에서 탈락**한다.

```
@sap/cloud-sdk-core → @sap-cloud-sdk/core   votes=654.0  publisher_months=2   share_pm=100.0%
promise            → form-data              votes=355.1  publisher_months=2   share_pm=0.2%
```

첫 줄이 이 필터의 존재 이유다. 점유율 100%에 표가 654개인데 **한 조직이 두 달에 한 일**이다. `publisher_months` 를 `votes` 보다 위에 둔 결정 2가 실제로 작동한다.

### ② 딸려 들어온 부품 — **못 거른다**

```
rxjs → tslib   votes=273.0  publisher_months=269  share_pm=11.1%  → rxjs 의 1위
```

`-211` 이 잡음 ②의 예로 **직접 지목한 쌍**인데 기본 필터를 통과하고 1위로 선다. `tslib` 은 TypeScript 런타임 헬퍼라 "rxjs 대신 tslib 을 쓴다" 가 아니다.

**필터로는 못 막는다.** 조직·달이 269개로 진짜 넓게 퍼진 변화이고, 그 점에서 `moment → dayjs` 와 통계적으로 구별되지 않는다. 가르려면 "도착지가 출발지의 의존인가" 같은 **새로운 축**이 필요하고, 그건 빌더가 만들어야 하는 열이다.

- **이번 범위에서 하지 않는다.** 화면은 관측된 흐름으로만 말하고 "대체재" 로 단정하지 않으므로 거짓을 말하지는 않는다.
- 별도 이슈 후보 — 빌더에 `to_pkg ∈ deps(from_pkg)` 표시를 더하고 API가 배지로 가른다.

### ③ 같은 물건의 두 포장 — **표시되지만 배지 이름이 틀렸다**

```
lodash    → lodash-es   votes=1243.3  pm=916  share_pm= 5.4%  양방향=true
lodash-es → lodash      votes= 537.2  pm=385  share_pm=18.0%  양방향=true
lodash    → lodash.merge votes= 92.4  pm=161  share_pm= 0.9%  양방향=true   ← 분해, 대체 아님
```

양방향 관측 자체는 의도대로 잡히고, 지우지 않고 표시만 다르게 한다.

**문제는 이 플래그가 너무 자주 참이라는 것이다.**

| 범위 | 양방향 비율 |
|---|---:|
| `regular` 전체 16,837쌍 | 24.6% |
| 기본 필터 통과 5,979쌍 | 43.0% |
| **화면 상위 5에 서는 4,182자리** | **38.2%** |

`rxjs → tslib`, `moment → lodash` 도 참이다. 널리 쓰이는 패키지 둘은 어디에선가 서로 반대로도 바뀌기 때문이다.

`-211` 결정 4 ③ 은 이 플래그를 "같은 물건의 두 포장" 으로 보고 배지 이름을 **"변종"** 으로 정했는데, **그 전제가 실측으로 깨졌다.** 열 중 넷에 "변종" 이 붙으면 그 말은 거짓이 된다.

**조치 — 배지 이름을 "양방향" 으로 바꿨다.** 데이터가 실제로 말하는 것이 그것이고, "같은 것의 다른 포장" 은 그 사실의 한 가지 해석이다. 두 해석을 툴팁에 나란히 두고 판단은 사람에게 남긴다.

## 5. 남은 약점 — 잡음이 "근거 강함" 을 단다

```
node-sass → react-dom   share_pm=1.3%  strict
node-sass → react       share_pm=1.2%  strict
chalk     → react       share_pm=1.0%  strict
```

`node-sass` 를 빼면서 `react` 를 넣은 것은 대체가 아니라 같은 시기의 다른 변경이다. 그런데 빌더의 strict 조건(`votes>=12 · publisher_months>=10 · a_pct>=3`)을 통과해 **최고 등급 배지**를 단다.

- 등급은 빌더가 정한 고정 문턱이고 API는 옮겨 적기만 한다(결정 1). **이번 범위에서 문턱을 바꾸지 않는다** — 바꾸면 CSV 3종과 화면이 갈라진다.
- 완화 요인 — 점유율이 1% 대라 막대에서 눈에 띄지 않고, 배지 툴팁이 "무엇을 보고 붙었는지" 를 숫자로 밝힌다.
- 별도 이슈 후보 — ④와 같은 뿌리다. 도착지가 출발지의 의존이거나 같은 릴리스의 무관한 변경인지 가르는 축이 없다.

## 6. 완료 판단

`-211`·`-424` 의 완료 조건은 이것이다.

> 대표 사례와 잡음 사례에서 같은 규칙이 재현되고, 제외·표시 구분 이유를 API와 화면이 설명할 수 있다.

| | |
|---|---|
| 같은 규칙이 재현되는가 | **예** — 하한이 한 곳에 있고, 대표 5개가 전부 맞다 |
| 제외 이유를 설명하는가 | **예** — 접은 칸이 `below_filter` 로 몇 개가 근거 부족이었는지 세고, 빗금이 "집계에서 뺀 몫" 을 그린다 |
| 표시 구분 이유를 설명하는가 | **예** — 배지 툴팁과 모달 풀이표가 판정 숫자를 그대로 밝힌다 |
| 잡음 3종을 다 가르는가 | **아니오** — ②는 못 거른다(4-② 참고). 화면이 단정하지 않는 것으로 막고, 새 축은 별도 이슈로 남긴다 |

## 7. 재현

```bash
python - <<'PY'
import csv, collections
rows = list(csv.DictReader(open("datasets/migration_pairs_260908/migration_pairs_all.csv",
                                encoding="utf-8-sig")))
by = collections.defaultdict(list)
for r in rows:
    by[r["from_pkg"]].append(r)
ok = lambda r: float(r["votes"]) >= 5 and int(r["publisher_months"]) >= 3
for name in ["moment", "request", "node-sass", "chalk", "lodash"]:
    top = sorted(filter(ok, by[name]), key=lambda r: -float(r["share_pm_pct"]))[:5]
    print(name, [(r["to_pkg"], r["share_pm_pct"]) for r in top])
PY
```

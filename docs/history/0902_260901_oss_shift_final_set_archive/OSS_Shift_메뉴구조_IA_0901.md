작성 기준일: 2026-09-01

## 1. 문서 적용 원칙

### 사용자가 마지막 선택을 한다

- 사용자는 실제 npm 패키지명 또는 `패키지@버전`을 입력한다.
- 서비스가 보여 주는 후보는 관련 패키지를 발견하기 위한 제안이다.
- 추천 후보가 완전한 대체 관계라고 표현하지 않는다.
- 사용자는 추천 후보를 선택하거나 다른 패키지를 직접 추가한다.
- 서비스가 기술적으로 가장 좋은 패키지를 자동 결정하지 않는다.

### 후보 추천은 MVP에 포함한다

- 후보 추천은 별도 확장 화면이 아니다.
- 기본적으로 최대 3개 후보를 보여 준다.
- 추천 기준을 넘는 후보가 부족하면 3개보다 적게 표시한다.
- 후보 카드에는 설명 유사도, 공통 키워드, 버전, 배포일과 자료 상태를 보여 준다.
- 후보 이름을 생성하거나 순서를 생성형 AI 또는 LLM으로 다시 정하지 않는다.

### 결과와 근거를 함께 보여 준다

- 1페이지는 `생태계 변화 분석`이다.
- 2페이지는 `기능 비교 분석`이다.
- 확장 3페이지는 `GitHub 커뮤니티 현황`이다.
- 기준일, 분석 버전, 출처, 근거, 자료 부족과 확인 불가 상태를 숨기지 않는다.

### 화면에 넣지 않는 기능

- 가입·로그인
- 회원 프로필·조직 관리
- 결제·요금제
- `package.json` 업로드
- 사람이 미리 정한 비교 묶음
- 생성형 AI를 이용한 후보 생성·재정렬
- 공개 트렌드 기사·소식 메뉴
- 코드 자동 수정·자동 교체
- 기술 우열 점수·최종 추천

## 2. 화면에서 사용하는 표현

| 피할 표현 | 화면에서 사용할 표현 |
|---|---|
| 코호트 | 비교 대상 |
| AI 추천 | 후보 추천 |
| 대체재 보장 | 관련 후보 |
| 대시보드 | 보고서 |
| 리포트 | 보고서 |
| ecosystem | 생태계 |
| uncertainty | 확인 불가 |
| migration | 관측된 교체 흐름 |
| version lock-in | 버전 고착 |

`npm`, `package.json`, `GitHub`, 실제 패키지명과 버전 표기는 그대로 사용한다.

## 3. MVP 메뉴와 화면 구조

### 상단 메뉴

- 서비스 소개
- 패키지 분석

`보고서`는 별도 상단 메뉴로 만들지 않고 패키지 분석 흐름 안에서 제공한다.

### MVP 화면 목록

| 화면 번호 | 화면 이름 | 역할 |
|---|---|---|
| 화면-00 | 서비스 소개 | 서비스 목적, 관측 범위, 결과 예시, 분석 시작 |
| 화면-01 | 패키지 입력 | 패키지·버전 입력, 존재 여부, 분석 버전 확인 |
| 화면-02 | 후보 선택 | 추천 후보 최대 3개, 직접 추가, 최종 비교 대상 확정 |
| 화면-03 | 보고서 | 1페이지 생태계 변화 분석, 2페이지 기능 비교 분석, PDF |

### MVP 기본 이동

```mermaid
flowchart LR
    A["서비스 소개"] --> B["패키지 입력"]
    B --> C["후보 선택"]
    C --> D["보고서"]
    D --> E["PDF"]
```

### 화면-03 하위 페이지

```text
보고서
├─ 1. 생태계 변화 분석
└─ 2. 기능 비교 분석
```

두 페이지는 같은 비교 대상과 분석 버전을 사용한다.

## 4. 확장 메뉴와 화면 구조

상단 메뉴는 MVP와 동일하게 유지한다. 확장 기능은 보고서 안에 추가한다.

```text
보고서
├─ 1. 생태계 변화 분석
│  ├─ MVP: 다운로드·직접/간접 의존·유지·유입·이탈
│  └─ 확장: 버전 고착·관측된 교체 흐름
├─ 2. 기능 비교 분석
└─ 3. GitHub 커뮤니티 현황
```

확장 3페이지는 npm 패키지와 GitHub 저장소 연결을 검증한 경우에만 표시한다.

## 5. 화면별 역할과 이동

### 화면-00 서비스 소개

#### 반드시 들어갈 내용

- OSS Shift 한 문장 설명
- 관련 후보를 찾은 뒤 사용자가 비교 대상을 정한다는 설명
- 공개 npm 생태계의 관측 결과라는 설명
- MVP 보고서 2페이지 소개
- 확장 3페이지 소개
- `패키지 분석 시작` 버튼
- 예시 화면은 실제 분석 결과가 아니라는 표시

### 화면-01 패키지 입력

#### 반드시 들어갈 내용

- 패키지명 또는 `패키지@버전` 입력
- 예: `winston`, `axios`, `zod@4.0.0`
- `패키지 확인` 버튼
- 실제 npm 존재 여부
- 분석할 정확한 버전
- 1페이지 자료 상태
- 입력 오류·미존재·버전 없음 상태

#### 이동 규칙

- 패키지와 분석 버전이 확인되면 화면-02로 이동한다.
- 버전을 입력하지 않은 경우 서비스가 확정한 분석 버전을 먼저 보여 준다.
- 사용자가 확인한 버전은 보고서 끝까지 유지한다.

### 화면-02 후보 선택

#### 반드시 들어갈 내용

- 입력 패키지와 분석 버전
- 추천 후보 최대 3개
- 후보별:
  - 패키지명
  - 설명 유사도
  - 공통 키워드
  - 분석 기준 버전
  - 최근 배포일
  - 자료 상태
- 후보 선택
- 후보 제외
- 다른 실제 npm 패키지 직접 추가
- 최종 비교 대상 목록
- `보고서 만들기` 버튼

#### 후보가 부족한 경우

- 3개보다 적어도 정상 상태로 처리한다.
- 후보가 하나도 없으면 `추천 근거가 부족합니다`를 표시한다.
- 사용자는 직접 패키지를 추가해 계속 진행할 수 있다.

#### 표현 원칙

`대체 가능`, `최고의 대안`, `추천 1위`처럼 완전한 대체나 우열을 암시하지 않는다.

### 화면-03 보고서

#### 공통 상단

- 입력 패키지
- 최종 비교 대상
- 각 패키지의 정확한 분석 버전
- 자료 기준일
- `PDF 받기`
- 자료 상태 요약

### 1페이지 생태계 변화 분석

#### 필수 구성

1. 다운로드 변화
   - 출처
   - 조회 기간
   - 후보별 변화 그래프
2. 의존 관계
   - 직접 의존
   - 간접 의존
3. 변화 지표
   - 유지
   - 유입
   - 이탈
4. 근거와 한계
   - 자료 기준일
   - 관측 범위
   - 자료 없음·오류·부분 기간
   - 전체 npm 실제 사용량이 아니라는 안내

#### 확장에서 추가

- 버전 고착
- 관측된 교체 흐름

### 2페이지 기능 비교 분석

#### 필수 구성

1. **공통 환경·설치 조건**
   - 정확한 버전
   - 실행 환경 조건
   - ESM·CommonJS
   - 타입 제공 여부·위치
   - 의존 조건
   - 확인 가능한 배포 정보
   - 라이선스

2. **공식 자료에서 발견한 기능**
   - 기능 이름
   - 패키지별 판정
   - 조건
   - 근거 번호
   - 근거 보기

3. **판정 표시**
   - 지원
   - 제한적 지원
   - 확인 불가
   - 지원하지 않음은 공식 미지원 근거가 있을 때만

#### 목적이 다른 패키지를 고른 경우

- 공통 환경·설치 조건은 보여 줄 수 있다.
- 기능 비교 항목이 충분하지 않으면 `기능 목적이 달라 직접 비교 가능한 항목이 부족합니다`라고 안내한다.
- 빈 기능표를 억지로 채우지 않는다.

### 3페이지 GitHub 커뮤니티 현황

확장 범위다.

#### 표시 조건

- GitHub 저장소 연결이 검증됨
- 패키지 단위인지 저장소 전체인지 범위를 표시할 수 있음

#### 주요 구성

- 연결된 저장소
- 패키지 단위 / 저장소 전체 구분
- 최근 릴리스·커밋 등 확인 가능한 활동
- 열린 이슈·PR 등 확인 가능한 현황
- 조회 시점
- 자료 한계

기본 브랜치의 최신 문서를 과거 분석 버전의 기능 확정 근거로 사용하지 않는다.

## 6. 오류와 자료 부족 상태

### 화면-01

| 상황 | 화면 처리 | 사용자 안내 |
|---|---|---|
| 빈 입력 | 확인 중단 | 실제 npm 패키지 입력 필요 |
| 형식 오류 | 확인 중단 | 이름 또는 `패키지@버전` 형식 확인 |
| 존재하지 않음 | 분석 중단 | npm에서 확인되지 않음 |
| 버전 없음 | 분석 중단 | 분석 가능한 버전 선택 필요 |
| 자료 확인 실패 | 오류 표시 | 다시 시도 가능 |

### 화면-02

| 상황 | 화면 처리 | 사용자 안내 |
|---|---|---|
| 추천 후보 3개 미만 | 있는 후보만 표시 | 기준 미달 후보를 채우지 않음 |
| 추천 후보 없음 | 직접 추가 제공 | 추천 근거 부족 |
| 직접 추가 패키지 미존재 | 추가 거부 | npm 이름 확인 |
| 일부 후보 1페이지 자료 부족 | 경고 표시 | 페이지별 결과가 제한될 수 있음 |

### 화면-03 1페이지

| 상황 | 화면 처리 |
|---|---|
| 다운로드 일부 기간 없음 | 가능한 기간만 표시 |
| 직접 의존 자료 없음 | `자료 없음` |
| 간접 의존 자료 없음 | `자료 없음` |
| 값이 실제 0 | 숫자 0과 근거 표시 |
| 처리 오류 | 정상 값과 분리 |
| 일부 기간 | 가능한 구간과 제한 문구 표시 |

### 화면-03 2페이지

| 상황 | 화면 처리 |
|---|---|
| tarball 또는 공식 자료 확보 실패 | 해당 패키지 자료 상태 경고 |
| 기능 근거 부족 | `확인 불가` |
| 같은 기능 표현을 연결할 근거 부족 | 별도 기능으로 유지하거나 비교 제외 |
| 서로 목적이 다른 패키지 | 비교 가능한 항목 부족 안내 |
| 근거 기반 설명 생성 실패 | 원자료와 표를 그대로 제공 |

### 화면-03 3페이지

| 상황 | 화면 처리 |
|---|---|
| 저장소 연결 검증 실패 | 페이지 숨김 또는 연결 불가 안내 |
| 모노레포 범위 불명확 | 저장소 전체 정보로 단정하지 않음 |
| API 조회 실패 | 최신 상태처럼 표시하지 않음 |

## 1. 왜 이렇게 배분했는가

`OSS_Shift_기능별_개발_구상안_0901.md` 12장은 MVP 하나에만 4주(28일)를 배정한 예시 순서를 제시한다.
이번 목표는 그 4주 분량의 MVP를 **18일**로 압축하고, 원래 별도 배정이 없던 확장 기능(확장-01~03)에
**9일**을 새로 배정하는 것이다. 즉 기존 계획보다 실질적으로 더 빠듯하다.

이 압축을 감당하려면 원안의 "1주차→2주차→3주차→4주차" 순차 진행 대신, **역할별 트랙을 처음부터 병렬로
진행**해야 한다. 아래 일정은 원안의 주차별 목표(구상안 12장 표)를 그대로 유지하되, 각 목표를 여러 트랙이
동시에 나눠 맡는 방식으로 재배치했다.

## 4. Phase별 상세 일정

### Phase 0 — 기반 구축 (09-01 화 ~ 09-06 일, 6일)

**목표**: 구상안 원래 1주차 목표("Registry/BigQuery → 로컬 결과" 최소 흐름)를 6일 안에 달성.

| 트랙 | 작업 |
|---|---|
| 인프라 | EC2 2대 환경 세팅, Spark standalone 클러스터 구성, 두 서버 작업 분담 방식 확정(구상안 10.1) |
| 데이터/색인 | deps.dev BigQuery 접근 확인, npm Registry/Downloads API 연동 테스트, 후보 색인 스키마 설계(4.1~4.2) |
| 백엔드 | 기능-01·02 (패키지·버전 입력/확인) API 골격, `GET /packages/resolve` 구현 |
| AI | 임베딩 모델 후보 선정, 로컬 벡터 검색 방식 실험 착수 (구상안 13장 "먼저 증명해야 할 것") |
| 프론트 | 기능-15 서비스 소개 정적 페이지, 메뉴구조 IA 기준 라우팅 골격 |

**체크포인트 (09-06)**: Registry/BigQuery 연동 확인 + 최소 파이프라인 1회 성공.

### Phase 1 — 후보 추천 + 1페이지 (09-07 월 ~ 09-13 일, 7일)

**목표**: 구상안 원래 2주차 목표(후보 색인 10만, 최대 3개 추천, 사용자 선택)를 1페이지 집계와 병행 완료.

| 트랙 | 작업 |
|---|---|
| 데이터/색인 | BigQuery 사전처리 → 임베딩 계산 → 로컬 벡터 색인 적재(4.2), 10만 목표 1차 구축 |
| 데이터/1페이지 | Spark 사전집계 파이프라인(6.1~6.3), 직접·간접 의존 구분, 유지·유입·이탈 계산, 3만 집계 완료 |
| 백엔드 | 기능-03 후보 추천 API, 기능-04 비교 대상 확정 API |
| AI | 벡터 유사도 기준 실험, 플러그인/어댑터 오추천 제외 규칙(4.3) 확정 |

**체크포인트 (09-13)**: "입력 → 후보 선택" 흐름 완성 + 1페이지 데이터(3만) 확보.

## 6. 완료 판단 기준 (DoD)

### MVP DoD (`OSS_Shift_서비스_기획서_0901.md` 7장 기준)

- [ ] 기능-01: 유효·무효 패키지/버전 입력 구분
- [ ] 기능-02: 분석 버전이 보고서 끝까지 유지됨
- [ ] 기능-03: 기준 미달 후보를 억지로 3개 채우지 않음
- [ ] 기능-04: 사용자가 비교 대상을 최종 결정
- [ ] 기능-05: 출처별 조회 기간 차이가 화면에 표시됨
- [ ] 기능-06~08: 다운로드/직접·간접 의존/유지·유입·이탈이 출처·기간과 함께 표시
- [ ] 기능-09: 1페이지에서 기능-06~08 결과가 근거와 함께 한곳에 모임
- [ ] 기능-10~11: 근거 출처·버전이 연결되고 공통 환경 비교가 모든 패키지에 적용됨
- [ ] 기능-12: 분야 고정 기능표를 쓰지 않고 실제 발견된 기능만 비교
- [ ] 기능-13: 모든 확정 주장에 근거가 연결됨
- [ ] 기능-14: PDF가 화면과 같은 기준일·버전·근거를 유지
- [ ] 기능-15: 미검증 수치를 실제 결과처럼 쓰지 않음
- [ ] 기능-16: 자료 없음·확인 불가·오류 상태가 0과 구분됨

### 확장 DoD (`OSS_Shift_기능별_개발_구상안_0901.md` 9장 기준, 09-27까지 확정된 항목만)

- [ ] 확장-01: 해석 불가 버전 조건이 별도 상태로 분리되고, 실제 설치본으로 오인되지 않음
- [ ] 확장-02: 충분한 근거가 있는 관계만 결과로 제공, 교체 "원인"으로 표현하지 않음
- [ ] 확장-03: 저장소 연결이 검증된 경우만 제공, 기본 브랜치 최신 문서를 과거 버전 근거로 쓰지 않음

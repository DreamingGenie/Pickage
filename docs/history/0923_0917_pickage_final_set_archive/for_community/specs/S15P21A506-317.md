## 3. 아키텍처 / 데이터 흐름

### 3.1 admission 순서 (Jira "세부 항목" 그대로)

```text
POST /refresh (name, trigger)
  1. package 존재 확인 (없으면 404 C006)
  2. RefreshTaskRegistry에 이미 진행 중인 task 있으면 → 참여(같은 task, 200)
  3. 314에서 fresh(24h) 결과 있으면 → 새 task 시작 안 함(200, 결과 그대로)
     단, 이전 결과의 summary_status=FAILED면 5분 쿨다운 지난 뒤에는 재시도 허용
  4. 설정/호출량/용량 확인:
     - ANALYSIS_CONFIRMED: 시작 토큰(10/분·burst4) 없으면 즉시 거절(무대기, 200 CAPACITY_LIMITED)
     - TAB_OPENED: 토큰 예약 후 세마포어(2) 없으면 대기 큐(4)에 진입, 큐도 차면 거절
  5. 통과하면 registry에 등록하고 worker(고정 2개)에 작업 제출 → 202
```

### 3.2 GET은 절대 수집을 시작하지 않는다

`GET /api/packages/community?name=`은 registry의 진행 상태 또는 314의 저장 결과만 읽는다.
없으면(`NOT_STARTED`, `result=null`)로 응답 — 이 경우에도 POST를 유도할 뿐 직접 시작하지
않는다(Jira "GET은 수집 시작 금지").

### 3.3 작업 본체 — `CommunityRefreshOrchestrator`

```text
deadline = now + 20s (CommunityProperties.totalBudget)
1. REPOSITORY_VERIFY: 213.RepositoryVerificationService.verify(name, dbRepoUrl)
   -> Verified 아니면 그 결과를 그대로 DataStatus로 변환해 314에 게시하고 종료
2. ISSUE_SEARCH+COMMENTS: 212.IssueCollectionService.collect(owner, repo, timeLeft(deadline))
   -> NoDiscussionData/FetchLimited 처리
3. GMS: CommunitySummarizer.summarize(topics) — 지금은 FakeCommunitySummarizer
4. PUBLISHING: 213/212/GMS 결과를 Phase 1의 CommunityResultPayload로 조립해
   CommunitySnapshotRepository.upsert(...) 호출(2초 예약은 314가 이미 SET LOCAL로 구현)
```

### 3.4 config는 `@ConfigurationProperties`로 (자체 검증 필요 항목, §6)

구현계획의 숫자값이 "운영 p95를 보고 조정"하라고 명시하므로 하드코딩 상수가 아니라
Spring 설정으로 둔다. `application.yaml`에 `community:` 섹션을 추가해야 하는데, 이건
`application.yaml`이 공용 파일이라 범위 밖 승인이 필요할 수 있다 — §6에서 확인 요청.

- [ ] `RefreshAdmissionCoordinator` 동시성 시험 — 213/212에서 쓴 advisory-lock-timeout

## 7. 2026-09-11 사용자 결정 — 미결 사항 해소

- **설정값**: `CommunityProperties`는 상수 클래스로 시작한다. `application.yaml`은 건드리지
  않는다. 운영에서 조정이 실제로 필요해지면 그때 `@ConfigurationProperties`로 승격한다.
- **커밋 단위**: 3단계 — (1) DTO·`CommunityProperties`·enum 묶음, (2)
  `RefreshTaskRegistry`·`RefreshAdmissionCoordinator`, (3)
  `CommunityRefreshOrchestrator`·`CommunityController`·`CommunityService`. 각 단계마다
  컴파일·관련 테스트가 되는 상태로 커밋한다.
- **동시성 시험 한계**: 단위/통합 시험으로 잡을 수 있는 것까지만 하고, 운영 수준 부하는
  315(통합 인수)의 몫으로 남긴다.
- **`RefreshTaskRegistry` 저장소**: 인메모리, 단일 인스턴스 가정으로 진행한다.

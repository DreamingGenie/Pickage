       실제 도착지까지 특정시간에 도착하
       는 확률 계산 방법의 연구
       RailOdds 전체 경로 도착확률 계산 설계
       1. 목표
       사용자가 집에서 출발해 환승을 거쳐 목적역에 도착할 때까지 발생할 수 있는 모든 변수를
       반영하여 다음 정보를 제공한다.

             지금 출발하면 목적역에 언제 도착할 가능성이 높은가?

             특정 시각까지 도착할 확률은 얼마인가?

             계획한 환승열차를 탈 확률은 얼마인가?

             환승을 놓쳐도 다음 열차로 제시간에 도착할 수 있는가?

             목표 도착확률 90%를 만족하려면 언제 집에서 나가야 하는가?

       현재 기획서의 역별 도착예정시간 신뢰도만으로는 이러한 질문에 답할 수 없다. 전체 경로를
       계산하는 별도의 Journey Probability Engine 이 필요하다.


       2. 핵심 계산 방식
       각 구간의 지연 확률을 단순히 더하거나 곱하지 않는다.

       대신 가상의 열차 운행 상황을 수천 개 생성한 뒤, 각각의 상황에서 사용자가 집에서 출발해
       목적역에 도착할 때까지의 과정을 실제처럼 재생한다.


         집
         → 출발역 승강장
         → 첫 번째 열차
         → 환승역 도착
         → 환승 통로 이동
         → 환승열차 또는 다음 열차
         → 목적역 도착




       전체 시뮬레이션 중 목표 시각 전에 도착한 비율을 최종 확률로 사용한다.


         정시 도착확률
         = 목표 시각 전에 도착한 시뮬레이션 수




실제 도착지까지 특정시간에 도착하는 확률 계산 방법의 연구                            1
           ÷ 전체 시뮬레이션 수




       예를 들어 10,000번 시뮬레이션하여 8,600번이 오전 9시 전에 도착했다면 정시 도착확률
       은 86%다.


       3. 시뮬레이션 진행 과정
       3.1 집에서 출발역까지 이동
       먼저 사용자가 출발역 승강장에 도착하는 시각을 계산한다.


         승강장 도착시각
         = 집 출발시각 + 집에서 승강장까지 걸리는 시간




       집에서 승강장까지의 시간에는 다음이 포함된다.

           집에서 지하철 출입구까지 이동

           출입구에서 개찰구까지 이동

           개찰구에서 승강장까지 이동

       MVP에서는 사용자가 평소 걸리는 시간을 직접 입력하게 한다. 이후 지도 API와 사용자 이
       동 기록이 쌓이면 확률분포로 개선할 수 있다.

       3.2 탑승 가능한 첫 열차 선택
       사용자가 승강장에 도착한 뒤 출발하는 열차 중 가장 빠른 열차를 선택한다.


         열차 실제 출발시각
         ≥ 사용자 승강장 도착시각 + 안전여유시간




       안전여유시간은 계단 이동, 문 닫힘, 승차 준비 등에 필요한 시간이다.

       계획한 첫 열차를 놓친 경우 계산을 종료하지 않고, 실제로 탈 수 있는 다음 열차를 선택한다.

       3.3 환승역 도착
       첫 번째 열차가 환승역에 도착하는 시각을 계산한다.


         환승역 도착시각
         = 열차 도착예정시각 + 해당 열차의 지연




실제 도착지까지 특정시간에 도착하는 확률 계산 방법의 연구                              2
       TOPIS 실시간 도착정보를 사용할 때 절대 도착예정시각은 다음과 같이 계산한다.

         도착예정시각 = recptnDt + barvlDt




        recptnDt 는 데이터가 생성된 시각이고, barvlDt 는 해당 시점부터 남은 도착시간이다. API
       를 받은 시각에 barvlDt 를 더하면 데이터 지연만큼 계산이 틀어질 수 있다.

       3.4 환승 가능 여부 판단
       환승 성공 조건은 다음과 같다.


         도착열차 실제 도착시각
         + 환승 보행시간
         + 안전여유시간
         ≤ 환승열차 실제 출발시각




       조건을 만족하면 계획한 환승열차를 탄다.
       조건을 만족하지 못하면 환승 실패로 끝내지 않고, 실제 탑승 가능한 다음 열차를 선택한다.

       MVP에서는 동일 노선·방향의 다음 열차만 선택하고, 이후에는 현재 역과 시각을 기준으로
       전체 경로를 다시 탐색하도록 확장할 수 있다.


       4. 지연을 계산하는 방법
       4.1 역별 지연을 독립적으로 계산하면 안 되는 이유
       같은 열차가 첫 번째 역에서 2분 지연됐다면 이후 역에서도 비슷하게 지연될 가능성이 높다.

       그런데 각 역의 지연을 독립적으로 뽑으면 같은 지연을 여러 번 중복해서 더하거나, 앞 역에
       서는 3분 지연된 열차가 다음 역에서는 갑자기 정시 운행하는 비현실적인 결과가 발생할 수
       있다.

       따라서 열차 한 대의 전체 운행 흐름을 하나의 표본으로 사용해야 한다.

       4.2 열차 운행 궤적 저장
       열차는 다음 조합으로 식별한다.


         train_run_id
         = 운행일 + 호선 + 방향 + 열차번호 + 종착역




       각 열차에 대해 다음과 같은 역별 지연 궤적을 저장한다.


실제 도착지까지 특정시간에 도착하는 확률 계산 방법의 연구                                     3
         [역1 지연, 역2 지연, 역3 지연, ..., 종착역 지연]




       시뮬레이션에서는 현재와 조건이 비슷한 과거 열차의 지연 궤적을 통째로 가져온다.

       조건에는 다음 항목이 포함된다.

           호선과 방향

           평일·주말

           시간대

           일반·급행

           현재 지연 수준

           현재 배차간격

           지연·사고 알림 여부

       이 방식을 Block Bootstrap 이라고 한다.

       4.3 현재 지연상태 반영
       현재 열차가 이미 90초 지연된 상태라면 과거 궤적의 절대 지연을 그대로 사용하는 것이 아
       니라, 이후 지연이 증가하거나 회복되는 변화량만 적용한다.


         미래 지연
         = 현재 확인된 지연
         + 과거 유사 열차의 이후 지연 변화량




       이렇게 하면 현재 실시간 상황과 과거 운행 패턴을 함께 반영할 수 있다.


       5. 이동 중 새로 발생하는 지연
       지연은 두 종류로 나눠 처리한다.

       일상적인 지연
       다음과 같은 일반적인 운행 변동이다.

           승하차 시간 증가

           배차간격 변화

           열차 정차시간 증가




실제 도착지까지 특정시간에 도착하는 확률 계산 방법의 연구                            4
           혼잡으로 인한 소규모 지연

       이러한 지연은 과거 열차 운행 궤적 안에 포함되므로 별도 사건 모델이 없어도 반영할 수 있
       다.

       사고·시위 등 이례상황
       다음과 같은 사건은 별도로 처리한다.

           열차 고장

           안전사고

           시위 및 역사 혼잡

           무정차 통과

           임시 시간표 변경

       현재 발생한 사건은 서울교통공사 지하철 알림정보 API를 이용해 반영한다.

       앞으로 이동 중 새로운 사건이 발생할 확률까지 계산하려면 알림정보와 당시 열차 지연 궤적
       을 직접 장기간 저장해야 한다. 4주 데이터만으로는 희귀 사고의 발생 확률을 안정적으로 계
       산하기 어렵다.

       따라서 MVP에서는 현재 발생 중인 사건만 반영하고, 미래 사건 발생 예측은 데이터가 충분
       히 쌓인 이후 추가한다.

       직접 수집해야 한다.

       7. 사용자에게 보여줄 결과
       전체 경로 계산 결과에서는 다음 정보를 구분해서 제공해야 한다.

       최종 도착정보

         예상 도착시각: 08:52
         도착 범위: 08:48~09:03
         오전 9시 전 도착확률: 86%
         90% 기준 권장 출발시각: 08:07




       환승정보

         계획한 환승열차 탑승확률: 72%
         환승 실패 후 다음 열차로 복구될 확률: 61%
         평균 추가 대기시간: 4분




        계획한 환승을 지킬 확률 과 최종적으로 제시간에 도착할 확률 은 반드시 분리한다     . 환승을 놓쳐도 다
       음 열차를 이용해 제시간에 도착할 수 있기 때문이다.


       8. 가상 계산 예시
       10,000번의 시뮬레이션 결과가 다음과 같다고 가정한다.
        결과                                      횟수

        계획한 첫 열차와 환승열차로 09:00 전 도착              7,200회
        환승을 놓쳤지만 다음 열차로 09:00 전 도착              1,100회
        첫 열차를 놓쳤지만 대체 열차로 09:00 전 도착            300회
        09:00 이후 도착                             1,400회
       최종 정시 도착확률은 다음과 같다.


         (7,200 + 1,100 + 300) ÷ 10,000 = 86%




       계획한 열차를 모두 그대로 탄 확률은 72%지만, 대체 열차까지 고려한 최종 정시 도착확률
       은 86%다.
       이 차이가 전체 경로 시뮬레이션이 필요한 이유다.

       9. MVP 권장 범위
       현재 기획서에는 경로 탐색·환승 안내 가 MVP 제외 항목으로 명시돼 있다. 따라서 전체 경로
       계산을 추가하면 기존의 역별 ETA 신뢰도 서비스에서 확률적 여정 플래너로 범위가 확장된
       다.

       4주 내 구현하려면 다음과 같이 제한하는 것이 현실적이다.
           서울 1~9호선의 서울시 제공 구간만 지원

           환승 최대 1회

           경로 생성은 서울교통공사 API에 위임

           RailOdds는 경로별 도착확률 계산에 집중
           집→승강장 시간은 사용자가 직접 입력

           목적지 도착 기준은 우선 목적역 하차 승강장 으로 정의

           환승 실패 시 동일 노선의 다음 열차만 선택

           현재 발생 중인 사고·지연만 반영

           온라인 계산은 약 2,500회 시뮬레이션

           정밀 분석과 발표용 결과는 약 10,000회 시뮬레이션


       10. 최종 정리
       RailOdds의 기존 기능은 다음 열차의 ETA가 얼마나 믿을 만한지를 계산한다.
       전체 경로 기능은 이 결과를 입력으로 사용하여 다음 과정을 추가로 계산한다.


         집에서 승강장까지 걸리는 시간
         + 첫 열차 탑승 가능 여부
         + 열차의 구간별 지연
         + 환승 이동시간
         + 환승 성공 여부
         + 환승 실패 시 다음 열차
         = 최종 목적지 도착시간 분포




       핵심은 구간별 확률을 합산하는 것이 아니다.

       가상의 운행 상황마다 사용자의 여정을 목적지까지 끝까지 실행하고, 목표 시각 전에 도착한
       상황의 비율을 최종 도착확률로 계산하는 것이다.

## 1. 서비스 범위와 요구사항 원칙

### 서비스 한 문장

OSS Shift는 회원이 검토 중인 실제 npm 패키지를 같은 역할의 후보와 비교하도록 돕고, 공개 의존 관계 이력에서 현재 규모·신규 선택·유지·이탈을 계산해 근거와 함께 보고서로 제공하는 서비스다.

확장 단계에서는 `package.json` 입력, AI 비교 묶음, 이전 버전 유지 현황, 패키지 교체 흐름과 공개 패키지 변화를 추가한다.

### 서비스가 관찰하는 범위

- npm에 공개된 정식 배포 버전을 대상으로 한다.
- 공개 시각을 확인할 수 있는 배포만 기간 비교에 사용한다.
- 핵심 분석은 `package.json`의 일반 의존 패키지 항목에 적힌 관계를 대상으로 한다.
- 결과는 의존 관계가 문서에 선언된 상태와 그 변화를 뜻한다.
- 실제 설치 횟수, 실행 횟수, 호출량이나 내부 회사 프로젝트의 선택을 뜻하지 않는다.

### 요구사항 적용 원칙

1. MVP는 기능-01~16만으로 완결된 회원 분석 흐름을 제공한다.
2. 확장-01~09는 MVP가 완성되고 안정된 뒤 추가한다.
3. 확장 기능은 대응하는 MVP 기능을 없애지 않고 선택지나 결과를 추가한다.
4. 사용자는 기능명이 아니라 실제 npm 패키지명을 입력한다.
5. 서비스가 비교 후보를 제안해도 사용자가 후보와 기간을 최종 확정한다.
6. 결과와 근거, 자료 부족과 해석 한계를 함께 보여 준다.
7. 자료 없음, 관측 불가와 처리 오류를 숫자 0으로 바꾸지 않는다.
8. 서비스는 원인, 기술 우열, 미래 전망과 최종 추천을 단정하지 않는다.

|---|---|---|

## 3. 전체 사용자 흐름

### MVP 회원 분석

1. 비회원은 서비스 소개에서 관찰 범위와 제공 결과를 이해한다.
2. 분석 시작을 선택하면 가입·로그인으로 이동한다.
3. 로그인한 회원은 검토 중인 실제 npm 패키지명 1개를 입력한다.
4. 서비스는 패키지 존재 여부, 분석 가능 여부와 관측 가능한 기간을 보여 준다.
5. 운영자가 정한 비교 묶음이 있으면 후보와 선정 이유를 보여 준다.
6. 운영자 묶음이 없으면 사용자가 비교 후보를 직접 입력한다.
7. 사용자는 후보를 추가하거나 제외하고 최종 비교 대상을 확정한다.
8. 사용자는 모든 후보를 함께 볼 수 있는 범위에서 분석 기간을 선택한다.
9. 서비스는 현재 규모·신규 선택·유지·이탈과 시계열 그래프를 보여 준다.
10. 서비스는 근거 수, 자료 기준일, 계산 범위, 자료 부족과 쉬운 해설을 함께 보여 준다.
11. 사용자는 같은 내용을 한 화면에서 확인하고 인쇄한다.

### 확장 회원 분석

1. 회원은 패키지명을 직접 입력하거나 `package.json`을 읽는다.
2. `package.json`을 사용하면 일반 의존 패키지 목록에서 분석 대상 1개를 선택한다.
3. AI가 실제 후보를 직접 대안과 제외 대상으로 나누고 이유와 함께 제안한다.
4. AI 제안을 만들지 못하면 운영자 묶음이나 직접 입력으로 계속 진행한다.
5. 사용자는 비교 후보와 기간을 최종 확정한다.
6. MVP의 네 가지 지표와 보고서를 먼저 확인한다.
7. 같은 보고서에서 이전 버전 유지 현황과 패키지 교체 흐름을 추가로 확인한다.

### 확장 공개 패키지 변화

1. 회원 여부와 관계없이 패키지 변화 목록을 연다.
2. 처음 선택, 신규 선택 증가, 신규 선택 감소, 이탈 증가 또는 공식 저장소 논의를 고른다.
3. 역할별 목록에서 패키지명, 변화 종류, 기간, 근거 수와 한 문장 설명을 확인한다.
4. 상세 화면에서 최근 값·이전 값, 그래프, 계산 기간, 대상·제외 수, 탐지 기준과 원문을 확인한다.
5. 더 깊은 비교가 필요하면 `이 패키지 분석하기`를 선택한다.
6. 비회원은 가입·로그인 뒤 해당 패키지의 분석 흐름으로 이동하고, 회원은 바로 이동한다.

## 4. 공통 요구사항

| 번호 | 요구사항 | 정상 상태 | 예외·제한 | 완료 판단 |
|---|---|---|---|---|
| 공통-R01 | 모든 분석 결과에 공개 npm 의존 관계 선언을 관찰한다는 범위를 표시한다. | 사용자가 결과의 의미를 확인할 수 있다. | 실제 설치·실행량으로 표현하지 않는다. | 화면과 인쇄 결과 모두에서 관찰 범위를 확인할 수 있다. |
| 공통-R02 | 결과에는 값뿐 아니라 자료 기준일, 계산 기간과 근거 수를 함께 제공한다. | 사용자가 값의 범위와 시점을 확인한다. | 근거가 없으면 값이나 방향을 만들지 않는다. | 주요 결과에서 근거와 기준일로 이동할 수 있다. |
| 공통-R03 | 자료 없음, 관측 불가, 처리 오류와 실제 값 0을 서로 다른 상태로 표시한다. | 상태별 안내와 가능한 다음 행동을 제공한다. | 알 수 없는 상태를 0 또는 이탈로 바꾸지 않는다. | 네 상태가 서로 다른 문구로 구분된다. |
| 공통-R04 | 사용자가 비교 후보와 기간을 최종 확정한다. | 제안된 후보를 추가·제외하고 확정할 수 있다. | 운영자 또는 AI 제안을 자동 확정하지 않는다. | 수정된 후보와 기간이 분석 조건에 그대로 표시된다. |
| 공통-R05 | 같은 자료 기준일·후보·기간·규칙으로 다시 확인한 결과는 같아야 한다. | 화면과 인쇄 결과의 값이 일치한다. | 서로 다른 기준일의 값은 같은 결과처럼 섞지 않는다. | 동일 조건의 화면·보고서에서 값과 근거 수가 일치한다. |
| 공통-R06 | 개인 분석과 공개 패키지 변화를 구분한다. | 개인 입력·후보·기간·보고서는 본인만 본다. | 개인 분석을 공개 소식으로 바꾸지 않는다. | 다른 회원과 비회원이 개인 결과에 접근할 수 없다. |
| 공통-R07 | 화면 용어는 쉬운 한국어를 우선 사용한다. | 비교 묶음, 분석 결과, 이전 버전 유지 현황, 패키지 교체 흐름으로 표시한다. | 실제 이름인 npm·`package.json`·패키지명은 바꾸지 않는다. | 주요 메뉴·제목에 불필요한 전문 용어가 없다. |
| 공통-R08 | 확장 화면은 MVP의 입력·후보 수정·기간 선택·네 지표·근거·인쇄를 유지한다. | 기존 사용자는 같은 흐름으로 이용한다. | 공간 부족을 이유로 MVP 기능을 삭제하지 않는다. | MVP와 확장 화면 연결표의 유지 항목이 모두 존재한다. |
| 공통-R09 | 결과는 추천이나 기술 우열이 아니라 추가 검토를 위한 근거로 표현한다. | 사실과 주의사항을 함께 보여 준다. | 우승자·추천 점수·미래 생존·교체 원인을 만들지 않는다. | 화면과 보고서에 금지 표현이 없고 판단 경계가 표시된다. |
| 공통-R10 | 기간 안에 새 정식 배포가 없으면 이전에 확인된 상태를 이어서 보되, 첫 관측 전 기간은 값으로 채우지 않는다. | 배포가 없는 기간에도 확인된 관계 상태를 일관되게 비교한다. | 관측하기 전 기간을 `관계 없음`으로 만들지 않는다. | 빈 배포 기간과 관측 전 기간이 서로 다르게 처리된다. |

| 공개·보관 | 공개 내용만 제공하며 개인 분석 정보는 사용하지 않음 |

| 번호 | 요구사항 | 정상 상태 | 예외·제한 | 완료 판단 |
|---|---|---|---|---|
| 기능-15-R01 | 로그인하지 않아도 서비스 한 문장과 해결하려는 문제를 확인할 수 있어야 한다. | 첫 화면에서 패키지 비교 서비스임을 이해한다. | 분석 결과를 공개하지 않는다. | 비회원이 별도 설명 없이 서비스 목적을 확인한다. |

| 기능-15-R04 | 분석 시작, 회원가입과 로그인으로 이동할 수 있어야 한다. | 선택한 가입·로그인 경로로 이동한다. | 비회원이 바로 분석 입력 화면을 사용하지 못한다. | 세 진입 동작이 접근 규칙에 맞게 연결된다. |

### 기능-03 비교 묶음 제안

| 항목 | 내용 |

| 기능-13-R05 | 계산 방법 설명은 사용자에게 필요한 쉬운 정의로 제공해야 한다. | 현재 규모·신규 선택·유지·이탈의 차이를 이해한다. | 내부 작업 방식이나 저장 구조를 필수 설명으로 사용하지 않는다. | 주요 지표마다 쉬운 정의가 있다. |

## 6. 확장 기능 요구사항

확장 기능은 MVP의 회원 분석 흐름을 유지한 상태에서 추가한다. 확장 기능을 사용할 수 없는 경우에도 직접 패키지 입력, 운영자 정의 묶음, 후보 수정, 기간 선택과 MVP 보고서는 계속 이용할 수 있어야 한다.

### 확장-02 AI 비교 묶음 제안

| 항목 | 내용 |
|---|---|
| 적용 범위 | 확장 회원 분석 |

| 사용자 결과 | 같은 역할의 직접 대안 후보와 포함·제외 이유 확인 |
| 연결 화면 | 화면-02 비교 묶음과 기간 |
| 공개·보관 | 개인 분석 후보로 제공하며 사용자가 최종 확정 |

| 번호 | 요구사항 | 정상 상태 | 예외·제한 | 완료 판단 |
|---|---|---|---|---|
| 확장-02-R01 | AI가 만든 결과는 `AI 제안 묶음`으로 표시해야 한다. | 제안 출처를 확인한다. | 운영자 검토 묶음이나 확정된 정답처럼 표시하지 않는다. | 화면과 보고서에 제안 사용 여부가 남는다. |
| 확장-02-R02 | AI는 실제로 확인된 후보 안에서 직접 대안을 제안해야 한다. | 실제 패키지명과 분석 가능 상태를 본다. | 존재하지 않는 이름이나 기억으로 만든 이름을 노출하지 않는다. | 표시된 후보가 존재·자료 확인을 통과한다. |
| 확장-02-R03 | 포함 후보와 제외 후보를 나누고 각각 짧은 이유를 제공해야 한다. | 설명·분류·사용 목적과 관련된 근거를 확인한다. | 내부 판정값을 사실 확률이나 추천 점수로 표시하지 않는다. | 모든 제안 후보에서 포함·제외 이유를 확인한다. |
| 확장-02-R04 | 사용자는 AI 후보를 추가하거나 제외하고 최종 확정할 수 있어야 한다. | 수정된 묶음으로 기간을 선택한다. | AI 결과를 자동 확정하지 않는다. | 최종 후보와 보고서의 비교 묶음이 일치한다. |
| 확장-02-R05 | AI 제안이 보류되거나 실패하면 대체 경로를 제공해야 한다. | 운영자 정의 묶음 또는 직접 입력으로 진행한다. | AI 실패를 전체 분석 실패로 처리하지 않는다. | AI 없이도 MVP 분석 흐름을 완료할 수 있다. |
| 확장-02-R06 | 제안 근거가 부족하거나 후보가 직접 대안인지 불분명하면 자동 포함하지 않아야 한다. | 보류 또는 제외 상태로 보여 준다. | 억지로 최소 후보 수를 채우지 않는다. | 불확실 후보가 이유 없이 기본 선택되지 않는다. |

AI 비교 묶음을 기본 제안 방식으로 공개하기 전에는 다음 목표를 실제 평가에서 확인해야 한다. 이 값은 현재 성능이 아니라 공개 판단 기준이다.

| 확인 항목 | 공개 판단 목표 |
|---|---|
| 직접 대안 검색 범위 | 정답 대체 후보의 95% 이상이 검색 후보 20개 안에 포함 |
| 최종 후보 정확성 | 최종 후보 5개 안의 직접 대안 정확도 90% 이상 |
| 위험한 잘못 포함 | 부가 기능·연결 도구·관련 없음 포함 5% 이하 |
| 존재하지 않는 이름 | 0건 |
| 같은 조건의 반복 제안 | 최종 묶음 겹침 80% 이상 |
| 사용자 대규모 수정 | 전체 제안 중 20% 미만 |

하나라도 충족하지 못하면 AI 묶음을 기본 방식으로 전환하지 않고 운영자 정의 묶음과 직접 입력을 유지한다.

| 확장-09-R03 | 상세 글에는 계산 대상 수·제외 수·탐지 기준·해석 한계와 공식 원문을 제공해야 한다. | 사용자가 글의 근거를 직접 확인한다. | 전체 원천 자료나 개인 분석을 노출하지 않는다. | 근거 영역과 원문 이동이 정상 동작한다. |
| 확장-09-R04 | AI는 검증된 사실을 쉬운 제목과 설명으로 정리하는 데만 사용해야 한다. | 사실 범위 안의 문장을 본다. | 원인·전망·추천·감정·품질을 만들지 않는다. | 문장의 숫자와 원문이 입력 사실과 일치한다. |
| 확장-09-R05 | 운영자가 승인한 글만 공개해야 한다. | 승인된 사건이 목록과 상세에 표시된다. | 미승인·근거 부족·자료 갱신 실패 글은 공개하지 않는다. | 공개 상태와 승인 상태가 일치한다. |
| 확장-09-R06 | 상세 화면에서 해당 패키지의 회원 분석으로 이동할 수 있어야 한다. | 회원은 바로 분석 입력으로, 비회원은 가입·로그인 뒤 분석으로 이동한다. | 공개 글을 개인 보고서로 오해시키지 않는다. | 로그인 여부에 맞는 이동이 완료된다. |

## 7. 화면별 요구사항

### 화면 구성표

| 화면 | 접근 | MVP 필수 내용 | 확장 추가 내용 | 주요 동작 |
|---|---|---|---|---|
| 화면-00 서비스 소개 | 공개 | 서비스 한 문장·관찰 범위·네 지표 설명·결과와 근거·가입·로그인 | 패키지 변화 메뉴·최근 공개 글 진입 | 분석 시작·회원가입·로그인·패키지 변화 보기 |
| 공통-A 가입·로그인 | 공개 | 로그인 입력·회원가입 진입·회원 전용 안내·원래 화면 복귀 | MVP와 동일 | 로그인·회원가입·복귀 |
| 화면-01 패키지 입력·분석 방법 | 회원 | 실제 패키지명·패키지 확인·존재·자료·관측 기간·방법·포함·제외 | 직접 입력·`package.json` 선택·일반 의존 목록·대상 1개 선택 | 패키지 확인·입력 방식 선택·비교 묶음 이동 |
| 화면-02 비교 묶음과 기간 | 회원 | 운영자 정의 묶음·후보 이유·추가·제외·공통 기간 | AI 제안 묶음·포함·제외 이유·대체 경로 | 후보 수정·기간 선택·분석 시작 |
| 화면-03 분석 결과·보고서 | 회원 | 분석 조건·네 지표·시계열·해설·근거·한계·인쇄 | 이전 버전 유지 현황·패키지 교체 흐름 | 근거 확인·다시 시도·인쇄 |
| 화면-04 패키지 변화 목록 | 확장 공개 | 제공하지 않음 | 변화 종류·역할·기준일·승인 글·상세 이동 | 종류·역할 선택·자세히 보기 |
| 화면-05 패키지 변화 상세 | 확장 공개 | 제공하지 않음 | 최근·이전 값·그래프·대상·제외·탐지 기준·원문·분석 이동 | 원문 보기·이 패키지 분석하기 |

### 화면-00 서비스 소개

1. 비회원과 회원이 같은 서비스 설명을 확인할 수 있어야 한다.
2. 분석 시작을 선택한 비회원은 공통-A로, 회원은 화면-01로 이동해야 한다.
3. 네 가지 지표는 실제 결과가 아니라 제공 항목 설명으로 보여 줘야 한다.
4. 예시 그래프와 수치는 실제 분석 결과가 아니라는 표시가 있어야 한다.
5. 확장에서는 MVP 설명을 유지하고 패키지 변화 메뉴와 공개 글 미리보기만 추가해야 한다.

### 공통-A 가입·로그인

1. 로그인과 회원가입 진입을 명확히 구분해야 한다.
2. 패키지 분석이 회원 전용임을 알려야 한다.
3. 로그인 뒤 원래 요청한 분석 화면으로 돌아가야 한다.
4. 회원 프로필·조직·결제·소셜 활동 메뉴를 추가하지 않는다.

### 화면-01 패키지 입력·분석 방법

1. 실제 npm 패키지명 입력과 `패키지 확인`을 한 구역에서 제공해야 한다.
2. 존재 여부, 분석 가능 여부와 관측 기간을 서로 구분해 보여 줘야 한다.
3. 결과가 만들어지는 쉬운 순서와 포함·제외 자료를 같은 화면에 제공해야 한다.
4. 비회원 접근, 오타, 미존재, 자료 없음과 확인 오류가 서로 다른 상태로 보여야 한다.
5. 확장에서는 직접 입력을 첫 선택으로 유지하고 `package.json 읽기`를 추가해야 한다.
6. `package.json`에서는 파일·붙여넣기, 일반 의존 목록, 대상 1개 선택과 원문 미보관 안내를 제공해야 한다.
7. 결과 생성 방법은 이 화면에서, 실제 근거와 한계는 화면-03에서 제공하며 별도 `방법과 근거` 메뉴를 만들지 않는다.

### 화면-02 비교 묶음과 기간

1. 입력 패키지와 비교 묶음 생성 방식을 표시해야 한다.
2. 후보별 선정 이유와 자료 확인 상태를 보여 줘야 한다.
3. 사용자가 후보를 추가·제외할 수 있어야 한다.
4. 입력 패키지를 포함해 최소 2개 패키지가 필요하다는 조건을 알려야 한다.
5. 최근 8개 완결 분기, 1년·2년·3년과 직접 기간을 제공해야 한다.
6. 모든 후보의 공통 관측 기간 안에서만 기간을 확정할 수 있어야 한다.
7. 확장에서는 AI 포함·제외 이유와 제안 실패 시 대체 경로를 추가해야 한다.

### 화면-03 분석 결과·보고서

1. 입력 패키지, 최종 후보, 묶음 생성 방식, 기간과 자료 기준일을 먼저 보여 줘야 한다. 확장에서는 `package.json` 입력 여부와 AI 제안 사용 여부도 표시해야 한다.
2. 현재 규모·신규 선택·유지·이탈을 별도 결과로 보여 줘야 한다.
3. 후보별 시계열을 같은 기간·단위·축으로 보여 줘야 한다.
4. 근거 수, 대상·제외 수, 자료 부족, 계산 방법과 판단 한계를 확인할 수 있어야 한다.
5. 간단 해설과 주의사항을 제공하되 최종 추천이 아님을 밝혀야 한다.
6. 분석 대기·일부 기간·자료 없음·계산 실패·해설 실패 상태를 제공해야 한다.
7. 화면과 같은 내용의 인쇄 결과를 제공해야 한다.
8. 확장에서는 MVP 결과를 먼저 유지하고 이전 버전 유지 현황과 패키지 교체 흐름을 아래에 추가해야 한다.

### 화면-04 패키지 변화 목록

1. 비회원과 회원이 같은 공개 목록을 조회할 수 있어야 한다.
2. 전체·처음 선택·신규 선택 증가·신규 선택 감소·이탈 증가·공식 저장소 논의로 구분해야 한다.
3. 역할별로 목록을 좁혀 볼 수 있어야 한다.
4. 각 글에 패키지명, 변화 종류, 기간, 근거 수, 자료 기준일과 한 문장 설명을 제공해야 한다.
5. 공개 승인된 글만 제공하고 근거 부족·갱신 실패·미승인 글은 노출하지 않아야 한다.
6. 각 글에서 화면-05로 이동할 수 있어야 한다.

### 화면-05 패키지 변화 상세

1. 제목, 패키지명, 역할, 변화 종류와 자료 기준일을 제공해야 한다.
2. 최근 값·이전 값·근거 수와 기간별 그래프를 제공해야 한다.
3. 같은 역할 후보와 비교할 수 있어야 한다.
4. 계산 기간, 대상 수, 제외 수와 사건을 찾은 기준을 제공해야 한다.
5. 공식 저장소 논의가 있는 경우 원문 목록과 원문 범위를 제공해야 한다.
6. 원인·추천·기술 우열·미래 예측이 아니라는 한계를 표시해야 한다.
7. `이 패키지 분석하기`를 제공하고 로그인 상태에 맞게 화면-01 또는 공통-A로 이동해야 한다.

## 9. 결과와 보고서 표현 기준

### 반드시 함께 표시할 정보

| 결과 | 필수 표시 |
|---|---|
| 전체 분석 | 입력 패키지·최종 비교 묶음·묶음 생성 방식·기간·자료 기준일 |
| 현재 규모 | 값·쉬운 정의·근거 수·기준일 |
| 신규 선택 | 값·비교 대상 수·근거 수·기간·빈 구간 |
| 유지 | 값·비교 대상 수·근거 수·관측 불가 제외 |
| 이탈 | 값·직전 관측 대상 수·근거 수·오류·관측 불가 제외 |
| 시계열 | 후보·기간·단위·같은 축·빈 기간·부분 기간 |
| 이전 버전 유지 현황 | 이전·새 주버전 비중·해석 불가 비중·근거 수·기준 시점 |
| 패키지 교체 흐름 | 제거·추가 패키지·비중·우연한 동시 변경과 비교한 정도·대상 수·종류 이동·인과 아님 |
| 공개 패키지 변화 | 최근·이전 값·기간·대상·제외·근거 수·자료 기준일·탐지 기준·원문 |

### 허용하는 표현

- 공개 의존 관계 선언에서 확인된 규모와 변화
- 최근 기간의 신규 선택이 이전 기간보다 많거나 적음
- 기존 관계가 다음 관측에서도 유지되거나 사라진 흐름
- 같은 역할 후보 안에서 확인된 상대 비중
- 자료가 부족해 방향을 단정하기 어려움
- 추가 검토가 필요한 변화 지점

### 사용하지 않는 표현

- 가장 좋은 패키지·최종 추천·우승자
- 실제 설치량·실행량·사용자 수
- 기술 성능·보안·유지보수 품질 보증
- 특정 패키지 때문에 교체했다는 원인 단정
- 오래된 버전을 사용하는 개발팀의 수준이나 위험 단정
- 커뮤니티 논의 증가를 긍정·부정·품질로 평가
- 곧 사라질 패키지·앞으로 성공할 패키지와 같은 미래 예측
- 처음 공개된 npm 패키지의 선택을 새 회사 프로젝트 전체의 선택으로 확대

### 인쇄 결과

1. 화면의 분석 조건, 값, 그래프, 해설, 근거와 한계를 유지해야 한다.
2. 화면과 인쇄 결과의 숫자와 자료 기준일이 같아야 한다.
3. 메뉴, 입력창과 분석 시작 버튼처럼 검토에 필요 없는 조작 요소는 제외할 수 있다.
4. 해설 실패 상태에서도 기본 설명과 숫자 결과를 인쇄할 수 있어야 한다.
5. 확장 보고서는 MVP 결과를 먼저 보여 준 뒤 추가 분석을 이어서 제공해야 한다.

## 11. 제공하지 않는 기능

다음 항목은 MVP와 확장 요구사항에 포함하지 않는다.

- 기술적으로 가장 우수한 패키지 자동 추천
- 기술 성능·보안·유지보수 품질 점수
- 실제 설치·실행·호출량 추정
- 패키지 교체 이유와 인과관계 단정
- 미래 생존·성공·실패 예측
- 코드 자동 수정·설치·패키지 자동 교체
- 여러 `package.json` 항목의 일괄 자동 분석
- npm 이외 패키지 저장소 지원
- 회원 프로필·조직 권한·결제·요금제
- 즐겨찾기·알림·공동 편집
- 모바일 전용 앱
- 개발·동료·선택·묶음 의존 관계를 핵심 지표에 포함하는 기능

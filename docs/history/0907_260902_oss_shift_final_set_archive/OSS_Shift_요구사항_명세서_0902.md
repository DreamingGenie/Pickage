# OSS Shift 요구사항 명세서 0902

작성 기준일: 2026-09-02

대상 서비스: 공개 npm 패키지 후보 발견·생태계 변화·정확한 버전 기능 근거 비교 서비스  
MVP 목표 기간: 약 4주

이 문서는 사용자가 어느 화면에서 무엇을 보고, 무엇을 선택하며, 그 행동 이후 어떤 정보와 상태가 이어져야 하는지를 정의한다. API, 데이터베이스, 캐시, 분석기와 같은 내부 구현은 개발 구상안에서 다룬다.

## 0. 0902 주요 변경

- 최초 입력은 npm 패키지명으로 한정하고 버전은 보고서 안에서 확인·선택한다.
- 기준 패키지와 관련 후보 상위 2개를 기본 선택하며 비교 대상은 총 3개로 제한한다.
- Dependency 표시 버전과 기능 비교 버전을 서로 다른 상태로 분리한다.
- 기능 비교는 최신 안정 버전 결과를 먼저 보여주고 버전 변경 시 명시적으로 재분석한다.
- 기능 비교 결과는 핵심 표, 진행 상태, 중립 해설, Evidence Drawer로 구성한다.
- 판정은 `지원`, `조건부 지원`, `제한적 지원`, `미확인`을 기본으로 한다.
- Version Share를 MVP 1페이지에 포함한다.
- Issue 시계열은 1페이지 Activity, GitHub 논의 해설은 확장 3페이지에 배치한다.
- PDF는 완료된 전체 보고서를 재구성하는 문서로 정의하고 생성 상태와 차단 조건을 추가한다.
- 최종 재검수에서 기준 패키지 고정, 확장 페이지의 패키지 전환, 모바일 조작, PDF 세부 구성을 명시했다.

## 1. 서비스 범위와 원칙

### 1.1 서비스 한 문장

OSS Shift는 사용자가 검토 중인 npm 패키지를 입력하면 관련 후보를 보여주고, 사용자가 확정한 최대 3개 패키지의 생태계 변화와 정확한 버전 기능 차이를 근거와 함께 비교하도록 돕는 서비스다.

### 1.2 사용자

| 사용자 | 사용 상황 | 필요한 결과 |
|---|---|---|
| 주 사용자 | 새 프로젝트 도입 또는 기존 npm 패키지 교체 검토 | 관련 후보, 공개 생태계 변화, 정확한 버전의 기능·조건·근거 |
| 확장 사용자 | 저장소의 현재 논의와 진행 작업 추가 검토 | 검증된 저장소의 수치 요약과 글 중심 커뮤니티 현황 |

회원가입·로그인은 전제로 하지 않는다.

### 1.3 MVP와 확장

| 구분 | MVP | 확장 |
|---|---|---|
| 입력 | npm 패키지명 | 동일 |
| 후보 | 관련 후보 최대 3개 표시 | 동일 |
| 비교 대상 | 기준 패키지 포함 총 3개 | 동일 |
| 보고서 1 | Dependency, Downloads, 관계 변화, Version Share | Issues, 버전 고착 심화, 관측된 교체 흐름 |
| 보고서 2 | 핵심 비교표, 정확한 버전 선택·재분석, 중립 해설, 근거 Drawer | 동일 |
| 보고서 3 | 없음 | GitHub 커뮤니티 현황 |
| PDF | 완료된 1·2페이지와 근거 요약 | 제공 가능한 3페이지 자동 포함 |

### 1.4 적용 원칙

1. 후보 추천은 관련 패키지 발견 기능이며 기술 우열이나 최종 선택을 의미하지 않는다.
2. 후보 이름 생성·후보 순서 변경에 생성형 AI를 사용하지 않는다.
3. 기준 패키지는 비교의 출발점으로 고정하고, 상위 후보 2개는 기본 선택 상태로 제공하되 사용자가 변경할 수 있다.
4. 최종 비교 대상은 기준 패키지를 포함해 최대 3개다.
5. 후보 단계에서는 버전을 선택하거나 확정하지 않는다.
6. Dependency 표시 버전과 기능 비교 버전은 서로 영향을 주지 않는다.
7. 화면에 표시하는 숫자 0, 자료 없음, 부분 자료, 처리 오류를 구분한다.
8. 기능 근거가 없거나 충돌하면 임의로 지원 또는 미지원으로 판정하지 않는다.
9. 보고서에서는 추천, 순위, 승자, 최종 선택을 제시하지 않는다.
10. 화면과 PDF는 완료된 동일 보고서 결과를 사용한다.
11. 색상만으로 선택·판정·자료 상태를 구분하지 않고 문구·아이콘을 함께 사용한다.
12. 저장소 주소와 출처 위치는 식별 정보로만 표시하며 사용자 화면에서 외부 링크로 연결하지 않는다.

## 2. 공통 용어와 상태

| 용어 | 의미 |
|---|---|
| 기준 패키지 | 사용자가 화면-01에 입력한 npm 패키지 |
| 관련 후보 | 설명·키워드가 가까운 실제 npm 패키지. 완전한 대체재나 품질 순위가 아님 |
| 비교 대상 | 기준 패키지를 포함해 사용자가 최종 선택한 최대 3개 패키지 |
| Dependency 표시 버전 | 보고서 1페이지 그래프에 표시할 `Total` 또는 특정 버전 |
| 기능 비교 버전 | 보고서 2페이지의 기능 근거를 분석하는 정확한 버전 |
| 미확인 | 확보한 자료로 기능을 확정할 수 없거나 같은 버전 근거가 충돌하는 상태 |
| 자료 없음 | 해당 지표를 구성할 관측 자료가 없는 상태 |
| 부분 완료 | 일부 자료나 일부 기능만 확인됐지만 확인 가능한 결과는 제공되는 상태 |
| 근거 충돌 | 같은 버전에 관한 근거가 서로 다른 결론을 가리키는 상태 |
| Evidence Drawer | 기능 비교표의 한 셀에 대한 판정 이유와 근거를 보여주는 우측 패널 |
| 최신 안정 버전 | 사전 배포 표시가 없는 가장 최근 정식 버전. 정식 버전이 없으면 자동 선택하지 않음 |

사용자 화면에서는 `확인 불가` 대신 `미확인`을 사용한다.

## 3. 전체 사용자 흐름

1. 사용자는 서비스 소개에서 제공 범위와 판단 한계를 확인한다.
2. 화면-01에서 npm 패키지명을 입력하고 존재 여부를 확인한다.
3. 화면-02에서 기준 패키지와 기본 선택된 관련 후보 2개를 확인한다.
4. 후보를 해제하거나 다른 npm 패키지를 추가해 총 3개 이내로 비교 대상을 확정한다.
5. 보고서 1페이지에서 Dependency, Activity, Version Share를 확인한다.
6. Dependency는 패키지별 `Total`로 시작하며 필요하면 특정 버전의 추이로 바꾼다.
7. 보고서 2페이지에서는 최신 안정 버전 결과와 핵심 기능 비교표를 먼저 확인한다.
8. 필요하면 패키지별 기능 비교 버전을 바꾸고 `선택한 버전으로 재분석`을 실행한다.
9. 기능 셀을 선택해 Evidence Drawer에서 판정 이유와 근거를 확인한다.
10. 완료된 보고서에서 중립 해설과 자료 상태를 확인한다.
11. PDF 내보내기 조건을 만족하면 전체 보고서 PDF를 생성하고 다운로드한다.

확장 3페이지가 제공되는 경우 사용자는 보고서 탭에서 GitHub 커뮤니티 현황으로 이동하고, 저장소 연결이 검증된 비교 패키지를 전환해 각 커뮤니티 내용을 확인한다.

## 4. 공통 요구사항

| 번호 | 사용자 요구사항 | 표시·동작 기준 | 완료 판단 |
|---|---|---|---|
| 공통-R01 | 현재 비교 대상을 항상 확인할 수 있어야 한다. | 보고서 상단에 패키지명 표시 | 화면 전환 후에도 같은 목록 유지 |
| 공통-R02 | 각 정보의 시점과 범위를 이해할 수 있어야 한다. | 그래프·표·해설에 기준일, 기간 또는 분석일 표시 | 출처별 시점 차이가 숨겨지지 않음 |
| 공통-R03 | 실제 0과 자료 부족을 구분할 수 있어야 한다. | `0`, `자료 없음`, `부분 자료`, `오류`를 다른 표현으로 표시 | 상태별 시각·문구 구분 |
| 공통-R04 | 보고서에서 자동 추천을 받는다고 오해하지 않아야 한다. | 추천·순위·승자 없음 안내 | 보고서와 PDF에 우열 표현 없음 |
| 공통-R05 | 페이지별 버전 역할을 구분할 수 있어야 한다. | Dependency 표시 버전과 기능 비교 버전을 각 영역 안에서 표시 | 한 버전 변경이 다른 영역을 바꾸지 않음 |
| 공통-R06 | 완료된 결과가 새 요청 중 사라지지 않아야 한다. | 재분석 중 이전 결과 유지 | 성공 시에만 결과 교체 |
| 공통-R07 | 기능 판정의 근거를 확인할 수 있어야 한다. | 기능표 셀과 evidence ID 연결 | 모든 확정 문장에 근거 ID 존재 |
| 공통-R08 | 외부 원문으로 이동하지 않고 근거를 검토할 수 있어야 한다. | Drawer 내부에 출처 유형·위치·발췌 표시 | 외부 원문 보기 버튼 없음 |
| 공통-R09 | 부분 결과도 확인할 수 있어야 한다. | 정상 결과와 미확인·부분 결과를 함께 표시 | 일부 실패가 전체 결과를 숨기지 않음 |
| 공통-R10 | 화면과 PDF 결과가 일치해야 한다. | PDF는 완료된 보고서 스냅샷 사용 | 패키지·필터·버전·기준일·근거 일치 |
| 공통-R11 | 키보드만으로 주요 조작을 완료할 수 있어야 한다. | 입력·카드·탭·표 셀·Drawer·PDF 행동에 순차 포커스 제공 | 포커스 유실·키보드 함정 없음 |
| 공통-R12 | 상태를 색상만으로 해석하지 않아야 한다. | 판정·선택·오류에 문구와 아이콘 병행 | 흑백에서도 상태 구분 |
| 공통-R13 | 서비스 화면에서 외부 사이트로 예기치 않게 이동하지 않아야 한다. | 저장소·출처·경로는 읽기 전용 식별 정보로 표시 | 외부 링크·새 창 동작 없음 |

## 7. 화면-02 후보 선택

### 7.1 후보 카드와 기본 선택

| 번호 | 위치 | 요구사항 | 완료 판단 |
|---|---|---|---|
| 기능-03-R01 | 상단 | 기준 패키지명을 표시한다. | 입력값과 일치 |
| 기능-03-R02 | 후보 카드 영역 | 기준 패키지를 제외한 관련 후보를 최대 3개 카드로 표시한다. | 실제 npm 패키지만 표시 |

### 10.3 분석 진행 상태

버전 선택 영역 바로 아래에 분석 상태를 표시한다. 최초 분석 중에는 결과 위치에 빈 완성 문장을 만들지 않고 다음과 같은 실제 완료 단계를 순차 표시한다.

- 정확한 버전과 배포 자료를 확인하고 있습니다.
- 실행 환경과 공개 진입 정보를 확인하고 있습니다.
- 기능 근거를 정리하고 있습니다.
- 근거를 기능 판정과 연결하고 있습니다.
- 비교 해설을 작성하고 있습니다.

완료되지 않은 단계는 완료된 것처럼 표시하지 않는다. 해설 생성만 실패하면 비교표와 근거는 계속 제공한다.

### 11.2 표시 정보

1. 상단 신뢰 요약
   - 패키지와 정확한 버전
   - 기능과 판정
   - 한 문장 판정 이유
   - 공식 근거·정적 확인 수
   - 분석일
   - 자료 상태

   - 지원 근거
   - 조건·제한 근거
   - 추가 확인
   - 충돌 근거
4. 기술 정보 접힘 영역
5. 허용 복사 동작
   - 근거 ID 복사
   - 분석 정보 복사

복사가 완료되면 같은 버튼 주변에 짧은 완료 문구를 표시하며, 복사 동작으로 Drawer가 닫히거나 외부 화면이 열리지 않는다.

### 13.2 적격성과 상태

| 상태 | 진입 조건 | 표시와 행동 |
|---|---|---|
| READY | 보고서가 완료되고 현재 선택과 결과가 일치 | 내보낼 패키지·버전·기간·필터·자료 상태 확인, `PDF 생성` |
| GENERATING | 생성 요청 완료 | 생성 단계와 진행 안내, 창을 닫아도 계속됨 |
| COMPLETE | 파일 생성 완료 | 자동 다운로드, 파일명·생성 시각·크기 표시, `PDF 다시 받기` |

다운로드만 실패한 경우 보고서를 다시 만들지 않고 준비된 동일 파일을 다시 받는다.

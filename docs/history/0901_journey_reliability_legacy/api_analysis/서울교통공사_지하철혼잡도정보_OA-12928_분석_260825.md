05:30~06:00=8.78, 06:00~06:30=22.45, 07:30~08:00=70.64, 08:00~08:30=73.77, ...

## 6. 시간 데이터 해석

- 예측시각 또는 실제시각 여부: **분기 단위로 집계된 historical 평균값**(당해 분기 관측치의 요일유형별 평균으로 추정) — 공식 설명문 근거. 정확한 산출 방법론(단순평균/가중평균, 표본 분기 범위)은 **미확인**
- 시간대: **30분 단위, `05:30~06:00`부터 `24:30~25:00`까지 39구간** — 정시가 아니라 30분 단위이며, **`OA-12252`(정시 1시간)와도, `OA-12913`(정시 1시간)과도 시간 해상도가 다르다** — 세 데이터셋을 시간축으로 조인하려면 30분 구간을 1시간으로 합산하거나 반대로 세분화 가정이 필요
- 05:30 이전(막차~첫차 사이 심야) 시간대는 **데이터 자체가 없다**(컬럼이 아예 없음, 결측이 아니라 수집 대상 외) — 심야 시간대 혼잡도가 필요하면 이 데이터로는 불가
- 갱신 주기: 분기별 — 공식, 최신 파일 기준 실측 정합
- 자정 이후 처리: **`24:00~24:30`, `24:30~25:00`로 표기**(즉 24시를 0시로 되돌리지 않고 24~25시로 그대로 연장 표기) — `OA-12252`가 00~03시로 표기한 것과 **다른 관례**. 조인 시 `24:xx` 표기를 `00:xx`(익일)로 변환해야 한다

- 다른 API와 ID 동일 여부: **동일한 코드가 하나도 없다.** 통합하려면 `(역명, 호선)` 텍스트 매칭이 유일한 경로 — `OA-12252`와 동일한 매핑 필요성을 공유하지만, **크로스워크 소스 자체는 아직 검증되지 않았다**
- 내부 표준 ID 매핑 필요 여부: **예, 필수**

## 8. 수집 계획 (설계안)

- 수집 방식: **분기별 파일 다운로드**(파일 적재) 1차, Open API 보조 검증. 8088 첫 페이지 1,000행 호출은 성공했지만 전체 1,671행 적재 계약은 미검증
- 수집 주기: **분기 1회**, 분기 종료 후 약 1개월 시점(실측 지연 24일 근거) 확인 후 다운로드
- 수집 범위: 최신 분기 파일 신규 게시 시마다 수집. 과거 17개 파일 전체 backfill 여부는 파일 형식(xlsx/csv 혼재, §4) 차이 확인 후 결정
- 원문 저장 여부: **저장하되 가공·변형 금지**(공공누리 제3유형, §1) — 원본 그대로 보관, 파생 변수는 별도 계산 결과로만 저장(원본 파일 자체를 수정해 재배포하지 않음)
- 저장 위치(설계안): 원문 `raw/seoul_subway_congestion/quarter=YYYYQn/원본파일명`, 파싱본 RDB `subway_congestion_halfhour`
- 중복 판정 기준: `(요일유형, 호선, 역번호, 상하구분, 시간대)` — 이번 분석에서 **중복 0건**으로 매우 깨끗함(§10), `OA-12252` 같은 dedup 긴급성은 없음

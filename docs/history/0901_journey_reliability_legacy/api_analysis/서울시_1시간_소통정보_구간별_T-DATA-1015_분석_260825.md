`avgSpd`는 버스 구간 운행시간이나 ETA가 아니다. 속도 단위와 링크 길이·geometry를 확인하고 버스 노선 구간과 mapping한 뒤에만 도로 교통상황 보조 feature 또는 링크 통행시간 후보로 사용한다.

- 제공기관: **교통정보시스템(TOPIS)**
  - 제공부서: 서울특별시 미래첨단교통과
  - T-DATA 담당자 표시: 소관수
- 공식 문서: [1시간 소통정보(구간별) data_id=1015](https://t-data.seoul.go.kr/dataprovide/trafficdataviewopenapi.do?data_id=1015)
- 데이터 분류: **도로 / Open API / JSON**
- 데이터 유형: **과거 이력·시간대 집계**
  - 포털의 업데이트 주기 표시는 `실시간`이다.
  - 실제 데이터 grain은 기준일·요일·도로 링크·시간대별 평균속도다.
  - 현재 차량 위치, 개별 차량 운행시간, ETA, 사고 이벤트 또는 운행시간표가 아니다.
  - 현재 일자의 최신 시간 bucket 제공 여부와 확정 시점은 승인키로 검증해야 한다.
- 프로젝트 활용 목적:
  - 도로 링크·방향·요일·시간대별 평균속도 이력 적재
  - 노선 구간과 도로 링크를 mapping해 버스 `RIDE` 분포의 교통상황 보조 feature 생성
  - 링크 길이와 속도 단위가 검증된 경우 도로 링크 통행시간 후보 생성
  - 시간대 baseline 대비 속도 저하율·교통 regime을 생성해 현재 출발 분석과 목표시각 역산을 보정
  - 버스 위치·도착·운행이력의 관측이 부족한 구간에서 도로 혼잡 proxy로 제한적 활용
- 적용 기능:
  - [x] 현재 출발 시 도착확률 — **시간대별 도로속도 baseline·교통상황 보조 feature로 조건부 적용**
  - [x] 목표 도착시각 기준 출발 추천 — **후보 출발시간의 도로속도 분포 입력으로 조건부 적용**

> 두 기능 모두 이 API 응답만으로 계산하지 않는다. 링크→노선 구간 mapping, 링크 길이, 속도 단위, 버스 정차·대기·환승 분포, 현재 운행상태를 결합해야 하며 근거가 부족하면 `INSUFFICIENT`로 처리한다.

## 2. 제공 범위

- 지역 범위:
  - TOPIS가 제공하는 도로 링크의 교통속도 통계다.
  - 상세 페이지는 정확한 행정구역 경계, 전체 서울 도로 포함 여부, 서울 외 연결 링크 포함 여부를 공개하지 않는다.
  - 따라서 “서울 전 도로 완전 coverage”라고 표현하지 않고 실제 `linkId` distinct set과 도로 링크 마스터를 대조한다.
- 노선·운영기관 범위:
  - 대중교통 노선·차량·운영기관 데이터가 아니라 도로 링크 데이터다.
  - 도로명 `axisName`, 도로코드 `axisCd`, 링크 ID, 도로구분, 방향, 시·종점명 단위로 제공된다.
  - 포함 도로등급·링크 수·원천 센서·제외 링크 목록은 공식 미공개다.
- 제공 기간:
  - API 공개일: `2021-12-01`
  - 공식 요청 샘플: `stndDt=20210101`
  - 공식 출력표 샘플: `stnd_dt=20211020`
  - 공식 JSON 미리보기 샘플: `stndMon=20211217`
  - 샘플 날짜는 문법 예시일 뿐 실제 조회 가능한 최초일·최종일 또는 보유 시작일을 증명하지 않는다.
- 과거 이력 제공 여부: **날짜별 조회 구조는 제공, 실제 보유범위는 미확인**
  - 필수 요청인자 `stndDt`로 기준일을 지정한다.
  - 과거 샘플이 공식 페이지에 있지만, retention 기간·backfill·수정 재배포 정책은 공개되지 않았다.
- 데이터 갱신 주기:
  - **[공식 메타데이터] 실시간**
  - **[데이터 grain] 1시간 평균속도 통계**
  - 정확한 집계 window, 매시 갱신 시점, 현재시각 bucket의 부분집계 여부, 일 마감 시점은 미공개다.
  - `실시간` metadata를 초·분 단위 freshness 또는 1시간 이내 제공 SLA로 해석하지 않는다.
- 실제 데이터 지연시간: **미확인**
  - 응답에 생성시각·게시시각·수정시각 필드가 없다.
  - `stndDt + timeCd`는 통계 대상 bucket이지 API 게시시각이 아니다.
  - 승인키 수집 후 `first_seen_at - bucket_end_candidate`를 측정하되, bucket 경계가 공식 확인된 뒤에만 publication lag로 명명한다.

## 3. 인증 및 호출 제한

- 인증 방식:
  - T-DATA가 발급한 application key를 요청인자 `apikey`로 전달한다.
  - OAuth 또는 Header key 방식은 공식 페이지에 안내되지 않았다.
  - 실제 키는 브라우저, 저장소, URL 예시, proxy/APM 로그에 노출하지 않는다.
- API 키 발급처:
  - T-DATA에서 서울시 통합계정으로 로그인
  - data_id=1015 상세 페이지에서 **활용신청**
  - Open API 이용안내의 절차: 통합로그인 → API 검색 → 인증키 신청 → 활용
- 기본 일일 호출 한도: **개발자 활용신청 기준 하루 최대 1,000건**
  - quota가 key 단위인지 API 단위인지, reset 시각과 사용량 조회 방식은 공개되지 않았다.
- 초당 호출 한도: **공식 미공개**
- 호출량 증액 가능 여부: **현재 공개 안내로는 미확인**
  - 현재 보이는 Open API 안내에는 개발자 1,000건/일만 명시돼 있다.
  - 페이지 HTML의 비활성 주석에 과거 운영자 안내 문구가 남아 있어도 현재 계약으로 사용하지 않는다.
  - 대량 backfill이 필요하면 담당부서에 별도 문의하고 승인 내용을 기록한다.
- 이용요금:
  - T-DATA 정책은 공공데이터의 무료 제공을 원칙으로 한다.
  - data_id=1015 상세 페이지에는 별도 과금 표시가 없다.
  - 무료 원칙을 무제한 호출 또는 지속 제공 SLA로 해석하지 않는다.
- 이용약관·라이선스:
  - 데이터셋별 표시: **저작권자표시(BY)**
  - 이용·변경·2차적 저작물 작성이 허용되며 출처표시가 필요하다.
  - T-DATA 정책은 CCL을 적용한다고 설명하지만 이 데이터의 CC 버전은 표시하지 않는다.
  - provenance에 제공기관, 데이터명, 상세 URL, 취득일, 라이선스 상태를 저장한다.

### 보안 규칙

- backend collector만 API를 호출한다.
- `apikey`는 secret manager 또는 runtime secret injection으로 주입한다.
- query string·HTTP access log·error trace에서 키를 마스킹한다.
- HTTP `403/404` 인증 오류에 임의 키를 바꿔 반복 호출하지 않는다.

## 4. 요청 방법

- HTTP Method: **공식 미기재 / `GET` gateway 도달 확인**
  - 상세 페이지는 base URL과 query parameter 표만 제공하며 method를 명시하지 않는다.
  - 2026-08-25 `GET` 요청이 gateway까지 도달한 사실은 확인했지만, 승인키의 정상 GET 계약은 아직 미검증이다.
- 공식 Endpoint:

```text
http://t-data.seoul.go.kr/apig/apiman-gateway/tapi/TopisIccStTimesLinkTrfSectionStats/1.0
```

- 운영 검증 후보 Endpoint:

```text
https://t-data.seoul.go.kr/apig/apiman-gateway/tapi/TopisIccStTimesLinkTrfSectionStats/1.0
```

  - 공식 페이지는 HTTP URL을 표시한다.
  - 현재 HTTP 호출은 같은 query를 유지해 HTTPS로 `302` redirect한다.
  - HTTPS gateway 도달은 확인했지만 승인된 key의 HTTPS 정상 데이터 응답은 별도 smoke test가 필요하다.
- 응답 형식: **JSON**
  - XML·CSV 지원은 표시되지 않는다.
  - 성공 response envelope, 배열명, pagination metadata는 공개되지 않았다.
- 필수 파라미터:

| 파라미터 | 설명 | 예시 | 공식 필수 여부 | 수집기 기준 |
| --- | --- | --- | --- | --- |
| `apikey` | T-DATA 인증키 | `{MASKED_T_DATA_API_KEY}` | 필수 | 필수, 로그 마스킹 |
| `stndDt` | 기준일, 공식 샘플상 `YYYYMMDD` | `20210101` | 필수 | 필수 |
| `startRow` | 시작행번호 | `1` | 선택 | pagination 시 명시 |
| `rowCnt` | 한 페이지 결과 수 | `10` | 선택 | pagination 시 명시 |

공식 변수 크기는 `apikey=100`, `stndDt=8`, `startRow=4`, `rowCnt=10`으로 표시된다. 변수 크기를 최대 페이지 크기나 숫자 최댓값으로 해석하지 않는다.

### 요청 예시

다음은 현재 gateway가 인식한 **GET/query-string 후보 형식**이다. 승인키 성공 검증 전에는 정상 호출 계약으로 확정하지 않는다.

```http
GET https://t-data.seoul.go.kr/apig/apiman-gateway/tapi/TopisIccStTimesLinkTrfSectionStats/1.0?apikey={MASKED_T_DATA_API_KEY}&stndDt=20210101&startRow=1&rowCnt=10
Accept: application/json
```

PowerShell에서는 실제 키가 shell history에 남지 않도록 runtime secret을 주입한다.

```powershell
$apiKey = '<MASKED_T_DATA_API_KEY>'
$endpoint = 'https://t-data.seoul.go.kr/apig/apiman-gateway/tapi/TopisIccStTimesLinkTrfSectionStats/1.0'
curl.exe --get --silent --show-error `
  --data-urlencode "apikey=$apiKey" `
  --data-urlencode 'stndDt=20210101' `
  --data-urlencode 'startRow=1' `
  --data-urlencode 'rowCnt=10' `
  $endpoint
```

### 인증 전 관측 응답

키를 보내지 않은 HTTPS 요청은 데이터가 아니라 다음 gateway 오류를 반환했다.

```http
HTTP/1.1 403
Content-Type: application/json
X-Gateway-Error: API not public
```

```json
{
  "responseCode": 403,
  "message": "관리자에게 문의 바랍니다.",
  "trace": ""
}
```

invalid key는 HTTP `404`와 같은 일반 메시지를 반환했다. 이 API에서 `404`를 곧바로 resource 미존재로 처리하면 안 된다.

## 5. 응답 데이터

공식 출력표는 snake_case와 camelCase를 혼용하고, 같은 페이지의 JSON 미리보기는 다시 다른 camelCase 이름을 사용한다. 아래 표는 **출력표와 미리보기를 병기한 문서상 후보 schema**이며 실제 성공 응답 계약이 아니다.

| 공식 출력표 필드 | 공식 JSON 미리보기 키 | 의미 | 공식 타입/크기 | 샘플 | 저장 여부·권장 타입 |
| --- | --- | --- | --- | --- | --- |
| `axisName` | 미표시 | 도로명 | 타입 미기재 / 100 | `4.19로` | 예, nullable string |
| `time_nm` | `timeNm` | 시간대 설명 | 타입 미기재 / 100 | `~17시` | 예, raw string |
| `time_grp_nm` | `timeGrpNm` | 첨두시 구분. 표 설명은 T1/T2/T3=오전/낮/오후 | 타입 미기재 / 100 | `N` | 예, enum 미확정 string |
| `stnd_dt` | `stndMon` | 기준일자 후보 | 타입 미기재 / 8 | `20211217` | 예, raw string + date 후보 |
| `time_cd` | `timeCd` | 시간코드 | 타입 미기재 / 50 | `17` | 예, string |
| `road_div_nm` | `roadDivNm` | 도로구분명 | 타입 미기재 / 100 | `보조간선도로` | 예, string |
| `link_seq` | `linkSeq` | 구간순서 | 타입 미기재 / 4 | `1` | 예, raw string + integer 후보 |
| `link_id` | `linkId` | 구간 ID(링크 ID) | 타입 미기재 / 10 | `1080012200` | 예, string |
| `st_node_nm` | `stNodeNm` | 시점명 | 타입 미기재 / 100 | `아카데미하우스` | 예, string |
| `road_div_cd` | `roadDivCd` | 도로구분코드 | 타입 미기재 / 50 | `04` | 예, string |
| `avgSpd` | `avgSpd` | 평균속도 | decimal 의미 / `(6,2)` | `40.42` | 예, raw string + decimal; 단위 미확정 |
| `axisCd` | `axisCd` | 도로코드 | 타입 미기재 / 10 | `1` | 예, string |
| `axisDirDivCd` | 미표시 | 도로방향구분코드 | 타입 미기재 / 50 | 표 샘플 `1` | 예, nullable string |

| `dayGrpCd` | `dayGrpCd` | 요일그룹. `01=주중`, `02=주말` | 타입 미기재 / 100 | `01` | 예, string |
| `edNodeNm` | `edNodeNm` | 종점명 | 타입 미기재 / 100 | `국립4.19묘지` | 예, string |
| 표에 없음 | `timeDirDivCd` | 의미가 문서화되지 않은 샘플 전용 필드 | 미기재 | `1` | 원문 저장, 사용 보류 |

### 성공 응답에서 미확인인 계약

- 최상위 JSON이 객체인지 배열인지
- 실제 데이터 배열 필드명과 전체 건수 field
- `startRow`가 절대 행번호인지 page 번호처럼 동작하는지
- `rowCnt` 최댓값과 마지막 페이지 판정 방법
- 출력표와 샘플 중 실제 field casing
- `stnd_dt`, `stndDt`, `stndMon`의 관계
- `axisDirDivCd`와 샘플의 `timeDirDivCd` 관계
- `null`, 빈 문자열, field 누락, 숫자형·문자열형 표현
- 정상·오류 application code와 성공 HTTP status

페이지의 `메시지 설명` 탭은 비어 있어 별도 정상·오류 메시지 계약을 제공하지 않는다. 첫 승인키 응답을 raw fixture로 저장하기 전에는 parser를 고정하지 않는다.

## 6. 시간 데이터 해석

- 제공기관 데이터 생성시각 필드: **없음**
  - `stndDt` 요청값과 응답의 `stnd_dt`/`stndMon` 후보는 통계의 기준일이다.
  - `timeCd`·`timeNm`은 1시간 시간대 bucket의 코드·표시명이다.
  - 생성시각, 게시시각, 최종수정시각은 응답 명세에 없다.
- 예측시각 또는 실제시각 여부:
  - ETA나 미래 예측시각이 아니다.
  - 개별 차량의 실제 통과시각도 아니다.
  - `avgSpd`는 해당 날짜·시간대·링크의 **집계된 관측 통계 후보**다. 원천 센서, 표본 수, 이상치 처리, 보정 방식은 공개되지 않았다.
- 시간대: **공식 미공개**
  - 서울 TOPIS 자료라는 이유만으로 API 계약에 timezone이 명시됐다고 간주하지 않는다.
  - 원문 날짜·시간코드를 보존하고, 승인키 데이터와 담당부서 확인 후 `Asia/Seoul` normalization을 승인한다.
- 자정 이후 운행일 처리 방식:
  - 도로 통계이므로 버스·지하철 service-day 규칙은 직접 제공하지 않는다.
  - `stndDt`는 provider 기준일 원문으로 보존한다.
  - `timeCd=00/24` 표현, 자정 bucket 귀속, 심야 운행 연결 방식은 실제 값으로 검증한다.
  - 이후 버스 trip과 결합할 때만 별도 transit `service_date` crosswalk를 적용한다.
- 수집시각과 제공시각의 차이:
  - source publish timestamp가 없어 정확한 API delivery lag를 계산할 수 없다.
  - 수집기는 `requested_at`, `received_at`, `fetched_at`, 요청 기준일, 응답 최대 시간 bucket을 각각 저장한다.
  - `fetched_at - stndDt/timeCd`는 데이터 bucket 이후 경과시간이지 provider 처리지연이라고 단정하지 않는다.
- 시간표 기준인지 실제 관측값인지:
  - 시간표·계획값이 아니다.
  - 미래 예측값도 아니다.
  - 교통정보시스템의 도로 링크별 1시간 평균속도 집계값으로 설명되므로 historical aggregate observation으로 취급한다.

> 도착시간 구분: 이 API에는 **계획 도착시각, 예측 도착시각, 실제 차량 도착시각이 모두 없다.** 날짜·시간대는 평균속도 통계의 집계 bucket이다. 버스 도착확률이나 추천 출발시각은 링크 mapping과 별도 운행·시간표·실시간 데이터로 계산한다.

## 7. 식별자

- 노선 식별자: **없음**
  - `axisCd`는 도로코드이고 대중교통 노선 ID가 아니다.
  - 버스 노선과 결합하려면 노선 shape/정류장 구간을 도로 link set으로 map해야 한다.
- 차량·열차 식별자: **없음**
  - 차량·운행 인스턴스·열차번호 필드가 없다.
- 정류장·역 식별자: **없음**
  - `stNodeNm`, `edNodeNm`은 도로 링크의 시·종점명이며 대중교통 정류장 ID가 아니다.
  - node ID 자체는 출력표에 없다.
- 도로 링크 식별자:
  - `linkId/link_id`: 구간 ID
  - `linkSeq/link_seq`: 구간순서
  - `axisCd`: 도로코드
  - `roadDivCd`: 도로구분코드
- 방향 식별 방식:
  - `axisDirDivCd`, `axisDirDivNm` 후보로 도로 방향을 구분한다.
  - 공식 샘플에는 방향명 `상행`이 있지만 코드 대신 문서에 없는 `timeDirDivCd`가 존재해 실제 field mapping 검증이 필요하다.
  - `상행/하행`을 버스 노선의 상·하행과 자동 동일시하지 않는다.
- 다른 API와 ID가 동일한지: **공식 보장 미확인**
  - TOPIS·서울 열린데이터광장·국가표준노드링크의 link ID와 동일하다는 계약이 없다.
  - `linkId` 길이나 값 모양만으로 다른 source와 direct join하지 않는다.
- 내부 표준 ID 매핑 필요 여부: **필요**
  - `provider=tdata-topis`, `dataset=1015`, `provider_link_id`, direction, 유효기간을 포함한 versioned crosswalk를 둔다.
  - 도로 링크 geometry·길이·시종점과 버스 route shape를 결합해 `internal_road_link_id`와 `internal_transit_leg_id`를 연결한다.

## 8. 수집 계획

- 수집 방식: **일자별 배치 적재 + pagination**
  - 현재 단계에서는 사용자 요청 시 호출하거나 고빈도 실시간 폴링하지 않는다.
  - 과거 날짜 backfill과 일별 갱신을 quota ledger가 있는 batch job으로 수행한다.
- 수집 주기:
  - **초기:** 승인키로 제공기간·최신 bucket·pagination을 검증하는 소규모 smoke test
  - **운영 후보:** 전일 `D-1` 1회 batch + 일정 시간 뒤 동일 파티션 1회 revision 확인
  - 정확한 일 마감·갱신 시각을 최소 30일 측정한 뒤 schedule을 확정한다.
  - current-day partial 데이터가 제공되더라도 일 마감 규칙과 correction rate가 확인되기 전에는 사용자 실시간 feature로 승격하지 않는다.
- 수집 범위:
  - 1단계: 샘플 기준일, `rowCnt=1/10`, `startRow=1/2`로 성공 envelope·페이지 의미 확인
  - 2단계: 프로젝트 대상 corridor에 포함되는 link를 찾기 위한 제한된 날짜 backfill
  - 3단계: link crosswalk와 quota 산정 후 필요한 기간·도로범위로 확장
  - 요청에 link filter가 없으므로 날짜 한 번의 전체 페이지 수가 수집비용을 결정한다.
- 원문 저장 여부: **예**
  - HTTP status, 허용된 response headers, raw body bytes, 요청 fingerprint, `requested_at`, `received_at`, `body_sha256`, collector/parser version을 저장한다.
  - `apikey`와 전체 query string은 저장하지 않는다.
- 저장 위치 설계안:

```text
raw/road-link-hourly-speed/
  provider=tdata/dataset=1015/ingestion_date=YYYY-MM-DD/
  stnd_dt=YYYYMMDD/start_row={startRow}/body_sha256={sha256}.json.gz
```

  - Silver: `road_link_hourly_speed_observation`
  - Gold: `road_link_speed_distribution`, 검증 후 `transit_leg_traffic_feature`
- 재시도 정책:
  - timeout·connection reset·HTTP `429`·`5xx`: exponential backoff + jitter, 최대 3회
  - HTTP `401/403/404`: 자동 재시도 금지, key·활용승인·endpoint·method를 점검
  - body JSON parse 실패 또는 schema drift: raw를 보존하고 해당 page를 quarantine, 같은 요청 무한 재시도 금지
  - 하루 900회에서 신규 backfill을 중단하고 100회를 재시도·계약 테스트 여유로 보존
  - 공식 quota reset 시각이 미공개이므로 자정에 실패 cursor를 자동 초기화하지 않는다.
- 중복 판정 기준:
  - raw: 동일 body hash여도 각 수집의 provenance를 보존한다.
  - normalized: 시간대 링크 관측 후보 키로 중복을 표시한다.
  - 같은 후보 키와 같은 `avgSpd`면 exact duplicate 후보, 같은 키에 다른 값이면 provider correction/revision 후보로 저장한다.
  - pagination page overlap은 별도 `PAGE_OVERLAP` flag로 기록한다.
  - 공식 unique key가 확정되기 전에는 물리 삭제 또는 destructive upsert를 하지 않는다.

### 최초 키 발급 후 계약 테스트 순서

1. 샘플 `stndDt=20210101`, `rowCnt=1`, `startRow=1`로 승인·HTTPS·GET 성공 여부 확인
2. status, headers, exact body bytes, 최상위 JSON 구조, 필드 casing을 fixture로 저장
3. `rowCnt=1/10/100`, `startRow=1/2/11`로 시작행·페이지·최대 크기 계약 확인
4. 없는 날짜, 잘못된 날짜, 미래 날짜, 파라미터 누락으로 오류 계약 확인
5. 같은 날짜·page를 반복 조회해 응답 안정성·수정 재배포 여부 확인
6. 과거 날짜를 이분 탐색해 실제 최초·최종 조회 가능일과 retention 확인
7. 최신 날짜를 매시간 제한 조회해 bucket first-seen·수정 시각을 측정
8. portal usage에서 quota 집계 단위와 reset 시각을 대조

## 9. 전처리 및 활용

- 생성할 데이터:
  - [x] 구간 운행시간 — `avgSpd` 단위와 도로 link 길이가 검증된 경우의 **도로 링크 통행시간 후보**
  - [ ] 정차시간 — 차량·정류장 도착·출발 이벤트가 없음
  - [ ] 실제 배차간격 — 노선·차량·도착 이벤트가 없음
  - [ ] 계획 대비 지연 — 계획시간과 대중교통 실제 운행시간이 없음
  - [ ] 사고·운행장애 이벤트 — 사고·통제·장애 field가 없음
- 전처리 규칙:
  1. 성공 응답의 정확한 envelope·field casing을 확보하기 전 상태를 `STRUCTURE_ONLY`로 둔다.
  2. raw JSON과 원문 field 이름을 먼저 저장한다.
  3. 출력표의 snake_case와 샘플의 camelCase는 alias 후보로만 두고, 첫 성공 fixture로 검증된 alias만 활성화한다.
  4. `linkId`, `axisCd`, 방향·도로구분·요일 코드는 선행 0을 보존하는 string으로 저장한다.
  5. `avgSpd`는 raw string을 보존하고 finite·non-negative decimal인지 검사한다. 공식 단위 확인 전 통행시간 계산을 금지한다.
  6. `stndDate`, `timeCode`, `dayCd`, `dayGrpCd` 일관성을 검사하되 공휴일·특수일 처리가 미확인인 동안 불일치 행을 삭제하지 않는다.
  7. `timeNm`의 `~17시`를 임의로 `[16:00,17:00)` 또는 `(16:00,17:00]`로 확정하지 않는다. bucket boundary를 provider에 확인한다.
  8. `timeGrpNm=N`처럼 문서 enum T1/T2/T3 밖의 값은 `UNKNOWN_TIME_GROUP`으로 보존한다.
  9. `timeDirDivCd`는 의미가 확인될 때까지 `extra_fields`에 저장하고 방향 feature로 사용하지 않는다.
  10. link geometry·길이·방향·유효기간 mapping을 통과한 데이터만 road travel time으로 파생한다.
  11. 버스 노선 shape와 road link map-matching confidence가 기준을 넘은 link만 transit leg feature에 반영한다.
  12. 학습·평가 분할은 시간 순서를 보존하고 미래 날짜 통계가 과거 예측에 유입되지 않도록 temporal hold-out을 적용한다.
  13. 현재 출발 분석에는 데이터가 제공된 시점과 bucket age를 feature/quality flag로 전달한다.
- 다른 데이터와 결합할 키:
  - TOPIS/T-DATA 도로 링크 마스터: `linkId + direction + valid_time`
  - 도로축·도로명: `axisCd`, 보조적으로 `axisName`
  - 노드·geometry: provider link crosswalk의 start/end node ID와 shape
  - 버스 노선 경로: versioned map-matching 결과 `internal_transit_leg_id ↔ internal_road_link_id[]`
  - 시간: `stnd_date + time_code`, 이후 확인된 timezone·bucket rule
  - 버스 위치·도착·운행이력: internal leg + observation time window
- 모델 입력 변수:
  - 원천: `avgSpd`, `roadDivCd`, `axisCd`, `axisDirection`, `linkId`, `timeCd`, `dayCd`, `dayGrpCd`, 검증 후 `timeGrpNm`
  - 파생: 링크 통행시간 후보, 동일 link·요일·시간대 평균/분산/quantile, baseline 대비 속도비, corridor congestion index
  - 품질: sample count, missing rate, revision rate, mapping confidence, source age, schema version, unknown-enum flags
  - 결합: 버스 segment travel-time 이력, 정차시간, 배차간격, 버스 위치·도착 ETA residual, 기상·공휴일

### Journey Reliability 활용 Gate

| 단계 | 자격 | 사용자 지표 사용 |
| --- | --- | --- |

포털의 `실시간` label만으로 `realtimeContextCoverage`를 높이지 않는다. current-day 최신 bucket의 first-seen lag와 correction rate가 검증된 뒤 별도 결정한다.

## collector 에 대해

마지막 운영 상태는 V3이고, `collector/README.md` 와 `collector/OPERATIONS.md` 에 실행법이 남아 있습니다.
운영 중 확인한 것 중 기록해 둘 만한 것:

- data.go.kr 버스 API의 요청 한도는 **포털 표기(10,000/일)와 상세기능별 실측이 달랐습니다.**
  `getBusPosByRouteSt` · `getArrInfoByRouteAll` 은 키마다 ~1,950건에서 401(요청제한 초과)이 왔고,
  `getBusPosByRtid` 는 2,619건까지 차단이 없었습니다. 운영계정 승급이 상세기능 단위로 개별 적용된 것으로 보입니다.
- `targets.toml` 의 `[key_caps]` 는 인증키(env) 단위라 상세기능별로 한도를 나눌 수 없습니다.
  실제 차단은 스케줄러의 401 → `ledger.exhaust()` 경로가 처리합니다.
- `targets.toml` 에 남은 도착 주기(150노선 240초 = 54,000/일)는 위 실측 상한의 4.6배로 **과구독 상태**입니다.
  주제를 접으면서 조정하지 않았습니다.
- 수집한 Bronze 원문은 저장소에 없습니다. `.gitignore` 의 `/data/` 규칙에 따라 로컬에만 보관했습니다.
  `collector/data/` 의 CSV 5종은 그것과 별개인 **정적 기준·통계 원천 데이터**라 추적 대상입니다.

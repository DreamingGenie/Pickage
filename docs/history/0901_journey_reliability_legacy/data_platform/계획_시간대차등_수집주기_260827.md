# 계획 — 시간대 차등 수집 주기 (Time-of-Day Adaptive Interval)

> 날짜: 2026-08-27
> 상태: **계획만.** 아직 구현하지 않는다.
> 목적: 같은 하루 예산으로 러시아워 관측 밀도를 높인다(위치 약 2.3배 효과).

## 1. 왜 하나

지금은 대상마다 **하루 종일 같은 간격**으로 호출한다. 그런데 실제로는:

- **낮(특히 출퇴근)** 에는 열차·버스가 자주 다니고 지연 변동도 크다 → 촘촘히 봐야 한다.
- **새벽·심야** 에는 운행이 거의 없다 → 촘촘히 봐도 얻을 게 없다.

즉 지금은 새벽에 낭비하고 낮에 부족하다. **시간대별로 간격을 다르게** 주면, 같은
하루 예산을 낮에 몰아써서 러시아워를 훨씬 촘촘히 볼 수 있다.

## 2. 얼마나 이득인가 (대략)

하루를 세 구간으로 나눈다고 하자.

| 구간 | 시간 | 운행 | 원하는 밀도 |
|---|---|---|---|
| 러시 | 07~10, 17~20 (6시간) | 최다 | 가장 촘촘 |
| 평시 | 10~17, 20~24 (11시간) | 보통 | 보통 |
| 심야 | 00~07 (7시간) | 거의 없음 | 성기게 |

같은 하루 예산을 러시아워에 몰면, 러시아워 구간의 호출 간격을 지금보다
**약 2배 이상** 촘촘하게 가져갈 수 있다(심야에서 아낀 몫을 낮으로 이동). 위치의
경우 대략 2.3배 밀도라는 추정이 이 계산에서 나온다.

## 3. 어떻게 만들 것인가

핵심은 **"대상의 간격을 고정값이 아니라 지금 시각에 따라 바뀌는 값으로"** 만드는 것이다.

### 설정 (targets.toml)

지금은 한 대상에 `interval_seconds = 60` 하나만 준다. 이걸 시간대별로 줄 수 있게 한다.

```toml
[[targets]]
name = "bus_position"
source = "bus-position"
# 기존: interval_seconds = 60
# 신규: 시간대별 간격 (KST 기준, 겹치지 않게)
interval_by_time = [
  { from = "07:00", to = "10:00", seconds = 40 },   # 아침 러시 — 촘촘
  { from = "17:00", to = "20:00", seconds = 40 },   # 저녁 러시 — 촘촘
  { from = "00:00", to = "05:00", seconds = 600 },  # 심야 — 성기게
]
interval_seconds = 90   # 위 구간에 안 걸리는 나머지 시간(평시) 기본값
enabled = true
params = { ... }
```

- 기존 `interval_seconds` 하나만 있으면 지금과 똑같이 동작한다(하위 호환).
- `interval_by_time` 가 있으면, **호출 직전에 "지금 몇 시인가"를 보고** 해당 구간의
  간격을 쓴다. 어느 구간에도 안 걸리면 기본 `interval_seconds`.

### 스케줄러 (scheduler.py)

지금은 다음 실행 시각을 `현재 + 고정간격` 으로 정한다. 이걸 `현재 + 지금시각의_간격`
으로만 바꾸면 된다. 구조가 이미 "다음 실행 시각을 매번 다시 계산"하는 방식이라,
**한 곳(`_advance`)만 고치면 되고 나머지는 그대로**다.

바뀌는 곳:
- `Target` 에 `interval_by_time` 필드 추가, 로딩·검증(구간 겹침 금지, 24시간 표기).
- `Target.interval_at(now_kst)` 헬퍼: 지금 시각에 맞는 간격을 돌려준다.
- `_advance`: `interval = target.interval_at(지금)` 으로 계산.
- 예산 검증(`budget_report`): 하루를 구간별로 나눠 `Σ(구간길이 ÷ 구간간격)` 으로
  계산하도록 확장(지금은 단일 간격 가정).

## 4. 주의할 점

- **예산 계산이 복잡해진다.** 지금은 "하루 = 하나의 간격"이라 `86400 ÷ 간격`으로
  끝나는데, 시간대별이면 구간마다 따로 더해야 한다. 검증 로직을 여기에 맞춰야
  잘못된 오버구독을 못 잡는 사고를 피한다.
- **경계 시각 처리.** 구간 경계(예: 10:00 정각)에서 간격이 바뀔 때 중복/누락이 없게
  한다. 운행일 경계(04:00)와도 어긋나지 않게 본다.
- **KST 고정.** 시간대 판단은 서버 로컬이 아니라 KST로 한다(이미 `service_day`가 KST 변환을 함).
- **로그.** 지금 어느 구간의 간격을 쓰는지 상태 로그에 찍어 헷갈리지 않게 한다.

## 5. 우선순위 메모

- 이 작업은 **위치(bus/subway position)에 효과가 크다** — 러시아워 지연 변동이 관측
  대상이기 때문. 도착(예측값)에는 이득이 적으니 우선 위치만 적용해도 된다.
- getBusPosByRtid 독립 풀(위치 2배)·트래픽 증량 등 **다른 증량 수단이 먼저 들어오면
  이 작업의 필요성이 줄어든다.** 그 결과를 본 뒤 착수 여부를 정한다.

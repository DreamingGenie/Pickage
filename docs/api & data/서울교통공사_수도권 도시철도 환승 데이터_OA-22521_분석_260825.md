  - 서울 열린데이터광장은 **공공누리 제1유형**으로 표시한다.

### 선택하지 않은 경로: 공공데이터포털 자동변환 OpenAPI

- 공공데이터포털은 파일데이터를 JSON/XML OpenAPI로 자동변환해 제공할 수 있다고 안내한다.
- 이 경로는 회원가입, 활용신청, 서비스키가 필요할 수 있다.
- 숫자로 된 일일·초당 한도와 증액 조건은 해당 파일데이터 화면에서 확인하지 못했다.
- 정적 파일의 버전·무결성 관리가 더 중요한 데이터이므로 초기 구현은 원본 CSV 적재를 선택한다.

> 자동변환 OpenAPI가 존재하더라도 이 데이터가 실시간 API로 바뀌는 것은 아니다.

### 전처리 규칙

1. CP949로 디코딩하고 정확히 14개 헤더인지 검사한다.
2. 역 코드는 정수 변환하지 않고 4자리 문자열로 유지한다.
3. 호선은 제공기관 원문과 내부 <code>line_id</code>를 함께 저장한다.
4. 방면 텍스트는 원문을 보존하고 노선 topology 기반 내부 방향 ID를 별도 생성한다.
5. <code>소요시간</code>은 원문을 보존하며 <code>MM:SS</code> 검증 후 초로 변환한다.
6. 빈 소요시간은 null로 유지한다. 0, 평균, 중앙값으로 자동 대체하지 않는다.
7. <code>모든 호차</code>, <code>모든 문</code>은 null이나 숫자 0이 아닌 명시적인 <code>ANY</code> enum으로 변환한다.
8. <code>총신대입구</code>↔<code>이수</code> 등 노선별 별칭을 물리적 환승역 crosswalk와 분리 관리한다.
9. <code>TRANSFER</code>는 이전 교통수단의 하차 지점부터 다음 교통수단의 승차 준비 지점까지로 정의하고, 이후 열차 <code>WAIT</code>를 제외한다.
10. 다른 환승 참조자료와 값이 다르면 직접 적용할 기준 하나를 선택하고 나머지는 sanity check로만 사용한다. 서로 평균하지 않는다.

## 12. 결정 사항 및 TODO

### 결정 사항

- **조건부 채택**: <code>SUBWAY_TO_SUBWAY</code> 환승의 정적 기준정보로 사용한다.
- <code>소요시간</code>은 계획·예측·실제 관측시각이 아니라 정적 환승 참고 지속시간으로 분리한다.
- <code>TRANSFER</code>에는 다음 열차의 <code>WAIT</code>를 포함하지 않는다.
- 이 파일만으로 확률분포, P50/P90, 환승 실패확률, 도착확률을 생성하지 않는다.

- 서로 다른 환승 참고자료의 값을 평균하지 않는다.

## 최종 판단

OA-22521은 **환승 경로와 승하차 위치를 설명하고, 지하철↔지하철 TRANSFER의 정적 기준시간을 제공하는 데 유용하다.** 그러나 실시간 운행정보나 개별 승객의 관측자료가 아니므로 이 값만으로 현재 출발 시 도착확률 또는 목표 도착시각 기준 추천 출발시각을 만들면 안 된다.

초기 적용은 원본 CSV를 버전·해시와 함께 보존하고, 14열 스키마와 코드·별칭을 엄격히 매핑하며, 32건의 결측을 0으로 대체하지 않는 방식이 적절하다. 이후 최신 2026-03-03 파일과의 diff, 실제 환승시간 분포, 접근성·혼잡 변수를 확보할 때에만 확률 모델의 불확실성을 단계적으로 줄인다.

- 지역 범위:
  - 공식 범위는 서울특별시가 제공하는 버스 노선 기본정보다.

  - 분석 파일에는 노선 723개가 있다.
  - `노선명`, `ROUTEID`만 있어 노선유형·운수사·운영상태를 파일 자체에서 구분할 수 없다.

- 제공 기간:
  - 분석 스냅샷 기준일: 2026-08-04
  - 포털 게시 수정일: 2026-08-05
  - 공식 파일 목록은 2021년 각 월 기준자료부터 2026-08-04 스냅샷까지 과거 파일을 제공한다.
- 과거 이력 제공 여부: **있음 — 시점별 파일 스냅샷**

  - 이는 이번 파일의 게시 시차이며 일반적인 배포 SLA로 확대하지 않는다.

분석한 workbook은 `Data` 시트 하나와 Excel table 하나로 구성돼 있다. 실제 사용 범위는 `A1:B724`이며 헤더 1행과 데이터 723행이다. 수식은 없다.

## 7. 식별자

- 노선 식별자: `ROUTEID`
  - 공식 Open API에서는 `RTE_ID`
  - 분석 파일의 723개 값은 모두 9자리 정수 셀이며 중복이 없다.
  - ID 의미에 산술 순서가 없으므로 문자열로 변환하고 연속형 모델 변수로 사용하지 않는다.
- 차량 식별자: 없음
- 정류장 식별자: 없음
- 방향 식별 방식: 없음
  - 같은 `ROUTEID`의 상·하행/회차/정류장 순서를 표현하려면 별도 노선별 경유정류소·노선경로 데이터가 필요하다.
- 다른 API와 ID가 동일한지:
  - 서울 버스 도착·위치 API는 `busRouteId`를 사용하며 프로젝트 실측의 `100100001`은 이 파일의 `01A` 행과 일치한다.
  - 파일 `ROUTEID`, OA-15262 API `RTE_ID`, 다른 API `busRouteId`의 영속적 동일성을 보장하는 별도 공식 계약은 확인하지 못했다.
  - 명칭이 다르므로 first/last/mid 표본과 전체 referential-integrity test를 통과한 뒤 같은 내부 ID로 승격한다.
- 내부 표준 ID 매핑 필요 여부: **필요**

권장 내부 키:

```text
RouteRef(
  provider="SEOUL_BUS",
  providerRouteId=String(ROUTEID),
  canonicalRouteId,
  sourceVersion,
  mappingVersion,
  mappingStatus
)
```

노선명은 현재 스냅샷에서 723개 모두 고유하지만 버전 간 이름 변경과 재사용 가능성을 배제할 수 없다. 노선명 단독 조인을 금지하고 `provider + route_id + mapping_version`을 기본 identity로 사용한다.

## 8. 수집 계획

- 수집 방식: **파일 적재**
  - 공식 페이지의 최신 파일 metadata를 1일 1회 또는 배포 전 확인
  - 파일명·포털 수정일·hash가 바뀐 경우에만 새 version을 다운로드·검증·적재
  - 사용자 요청마다 다운로드하거나 실시간 polling하지 않음
- 수집 주기:
  - 공식 갱신주기가 `수시`이므로 metadata check는 일 1회
  - 신규 파일이 없으면 데이터 재적재 없음
- 수집 범위: 최신 파일 전체 + 이전 버전과의 diff에 필요한 직전 snapshot
- 원문 저장 여부: **정책 승인 후 versioned 보존**
  - `ProviderPolicyRegistry`의 raw retention 승인 전에는 persistent raw 저장을 default-deny
  - 승인 후 원본 XLSX는 수정하지 않고 hash와 함께 immutable 저장
  - Share에는 원본 파일이나 전체 route master를 포함하지 않음
- 저장 위치:
  - 논리 Bronze: `bronze/seoul-bus-route-master/source_version=20260804/source.xlsx`
  - 정규화 Silver: `silver/bus_route_master`
  - crosswalk: `silver/canonical_route_mapping`
  - 물리 저장소·TTL: G5/배포 ADR 확정 전 `TBD`
- 재시도 정책:
  - 다운로드 timeout·HTTP 5xx만 exponential backoff+jitter로 최대 2회
  - XLSX parsing 실패, column mismatch, hash 불일치, 중복 ID는 자동 재시도하지 않고 quarantine
  - 기존 검증 버전은 유지하되 신규 버전 실패를 숨기지 않고 source freshness를 표시
- 중복 판정 기준:
  - 원본 파일 중복: SHA-256
  - 버전 중복: `source_version + file_sha256`
  - 행 중복: `source_version + route_id_source`
  - 이름 충돌: 같은 version의 normalized route name이 둘 이상의 ID에 연결되면 mapping conflict
  - 버전 간 변경: route ID별 `ADDED`, `REMOVED`, `RENAMED`, `UNCHANGED` diff 생성

이 파일에서 생성하는 것은 위 운행지표가 아니라 **versioned route master와 canonical crosswalk**다.

- 전처리 규칙:
  1. workbook·sheet·header 구조를 `Data!A1:B724`, `노선명`, `ROUTEID` 기대값과 비교
  2. `노선명`을 문자열로 읽고 trim 전 원문을 별도 보존
  3. `ROUTEID` 숫자 셀을 정수 검증 후 소수점 없이 문자열로 변환
  4. 노선명 `0017`, `040`, `0411`, `01A`, `01B`의 선행 0을 보존
  5. 영문 대소문자, 한글 suffix, 하이픈, 괄호를 임의 삭제하지 않음
  6. 같은 version에서 route ID·raw route name·trim+case-normalized name의 중복을 각각 검사
  7. `source_version`, `published_at`, `file_sha256`, parser version을 모든 적재 batch에 기록
  8. 이전 version과 diff하되 삭제된 ID를 물리 삭제하지 않고 비활성 후보로 기록
  9. OA-15262 `RTE_ID`와 버스 도착·위치 API `busRouteId`의 표본·전체 foreign-key coverage를 검증
  10. 공식 의미가 없는 `ROUTEID` prefix를 노선유형·운영기관으로 해석하지 않음
- 다른 데이터와 결합할 키:
  - 서울 버스 도착·위치 API: `String(busRouteId) = route_id_source`
  - 버스 노선별 경유정류소·경로 데이터: `route_id_source`
  - historical artifact: `canonical_route_id + service_date/day_type + time_bucket + stop/direction`
  - 선택 경로: versioned `canonical_route_id`
- 모델 입력 변수:
  - 직접 수치 feature 없음
  - 허용: `canonical_route_id`, route mapping status/version, route support group의 categorical key
  - 금지: 9자리 ID의 크기·prefix를 연속형 수치나 노선유형 proxy로 사용

## 10. 데이터 품질 및 제약

- 결측값 발생 조건:
  - 분석 파일에서는 두 컬럼 모두 결측 0건
  - 향후 파일의 blank row, schema drift, parsing 실패는 ingestion quality error로 처리
- 중복 데이터 가능성:
  - 분석 파일에서 완전 중복 행 0건, 중복 노선명 0건, 중복 `ROUTEID` 0건
  - 과거 파일을 합치면 동일 route가 여러 version에 반복되는 것이 정상이며 version 없이 중복 제거하면 안 됨
- 잘못된 값 또는 특수값:
  - `노선명`은 숫자처럼 보여도 문자열이다.
  - 선행 0으로 시작하는 명칭 5건이 있으며 숫자 변환 시 의미가 바뀐다.
  - 숫자만인 노선명 391건, ASCII 영숫자만인 명칭 425건, 한글 포함 296건으로 문자 유형이 혼재한다. 이 집계는 서로 중복될 수 있다.
  - 하이픈 포함 19건, 괄호 포함 3건이 있어 구두점을 일괄 제거하면 충돌할 수 있다.
  - `ROUTEID`는 XLSX에서 Number지만 Open API에서는 String이므로 source별 타입 drift를 허용해야 한다.
  - `ROUTEID` 범위는 `100000017`~`124900003`, 모두 9자리 정수다. 범위·prefix에 공식 분류 의미를 부여하지 않는다.
- 데이터 제공 제외 구간:
  - 정류장 topology, 방향, 기·종점, 운수사, 노선유형, 운행상태, 배차·시간 정보는 분석 파일에 없음
  - 서울 밖 구간 포함 여부도 판정 불가
- 실시간 데이터 과거 보관 여부:
  - 실시간 데이터가 아님
  - 포털이 과거 스냅샷 파일을 제공하지만 모든 변경 시점·삭제 사유를 보장하지 않음
- API 장애 시 대체 데이터:
  - 가장 최근 검증된 versioned XLSX를 사용하고 freshness limitation 표시
  - 선택적으로 `busRoute` Open API를 cross-check하되 같은 원천일 수 있어 독립 장애 대체로 보장하지 않음
  - route ID가 없는 신규 후보는 이름으로 자동 매핑하지 않고 `MAPPING_PENDING`/`NOT_COMPUTED` 처리
- 확인된 문제:
  1. 데이터셋 설명은 다양한 노선 기본정보를 언급하지만 실제 최신 XLSX와 Open API는 노선명·노선 ID 두 필드만 제공
  2. 사용자 요청의 “CSV”와 실제 파일 형식 XLSX가 다름
  3. 파일명 기준일과 포털 게시 수정일이 다르고 provider 생성시각 필드가 없음
  4. XLSX `ROUTEID` Number와 Open API `RTE_ID` String의 타입 drift
  5. 방향·정류장·노선유형·운수사·유효기간·삭제표시가 없음
  6. 노선 ID의 API 간 영속적 동일성과 prefix 의미가 공식 계약으로 명시되지 않음
  7. 과거 파일 배포 간격이 불규칙하고 change event log가 없음

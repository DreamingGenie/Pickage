## 6. 시간 데이터 해석

- 제공기관 데이터 생성시각 필드: **없음**
  - 파일명·포털 수정일의 <code>250930</code>을 source version으로만 보존한다.
- 예측시각 또는 실제시각 여부: **둘 다 아님**
  - <code>STT</code>와 <code>EDT</code>는 각각 계획된 열차도착시간·열차출발시간이다.
- 시간대:
  - CSV에 timezone 정보는 없다.
  - 서울 도시철도 영업일 시각이므로 내부에서는 <code>Asia/Seoul</code>로 파싱하되 <code>timezone_assumed=true</code>를 보존한다.
- 자정 이후 운행일 처리 방식:
  - 공식 설명에 따라 <code>24:xx</code>는 익일 <code>00:xx</code>, <code>25:xx</code>는 익일 <code>01:xx</code>로 해석한다.
  - 달력 날짜를 먼저 붙이지 말고 <code>service_seconds = hour × 3600 + minute × 60 + second</code>로 변환한다.
  - <code>day_offset = floor(service_seconds / 86400)</code>를 별도 저장한 뒤 service date에 적용한다.
- 수집시각과 제공시각의 차이:
  - 실시간 제공시각이 없어 계산할 수 없다.
  - <code>downloaded_at</code>, <code>catalog_modified_at</code>, <code>source_version</code>을 서로 다른 필드로 저장한다.
- 시간표 기준인지 실제 관측값인지: **시간표 계획값**

> <code>STT</code>/<code>EDT</code>를 예측 ETA나 실제 도착·출발시각으로 사용하지 않는다. 계획 대비 지연은 별도 Actual 관측을 결합해 계산한 파생값이다.

### 시간값 관측 결과

| 항목 | <code>STT</code> | <code>EDT</code> |
| --- | ---: | ---: |
| 결측 | 15,184 | 15,181 |
| <code>00:00:00</code> | 9,562 | 53 |
| 24시 이상 | 4,315 | 3,976 |
| 최댓값 | <code>25:14:00</code> | <code>25:11:30</code> |

- 두 시간 중 하나라도 24시 이상인 행은 4,475건(0.84%)이다.
- 분·초 범위를 벗어나거나 <code>HH:MM:SS</code> 형식을 어긴 비공백 값은 발견되지 않았다.
- <code>00:00:00</code>의 정확한 의미는 공식 설명에 없다. 실제 자정과 미정·시작역 특수값을 구분할 근거가 생기기 전까지 <code>zero_time_ambiguous=true</code>를 남긴다.
- 특수값을 정규화하지 않고 <code>EDT-STT</code>를 계산하면 음수가 되는 행이 54건 있다.

## 7. 식별자

- 노선 식별자:
  - source: <code>LINE</code> (<code>1</code>~<code>9</code>)
  - 내부 <code>canonical_line_id</code> 및 실시간 API의 <code>subwayId</code>와 명시적 crosswalk가 필요하다.
- 차량·열차 식별자:
  - <code>TRAIN_NO</code>는 열차코드이며 차량 편성의 영구 식별자로 보장되지 않는다.
  - 최소 운행 패턴 키 후보는 <code>source_version + WEEKTAG + LINE + INOUTTAG + GUBHANG + TRAIN_NO + ST_STT_NM + ED_STT_NM</code>다.
  - 실제 운행과 결합할 때는 <code>service_date</code>와 관측 시간 window를 추가한다.
- 정류장·역 식별자:
  - <code>SI_ID</code>는 역사코드다.
  - 각 비공백 <code>SI_ID</code>는 파일 안에서 하나의 <code>STATION_NM</code>에만 대응한다.
  - 환승역처럼 같은 역명이 여러 호선별 코드에 대응할 수 있으므로 역명→코드는 1:1이 아니다.
  - 동일 역명 다중 노선을 구분하기 위해 이름만으로 조인하지 않는다.
- 방향 식별 방식:
  - <code>IN</code> 내선, <code>OUT</code> 외선, <code>UP</code> 상행, <code>DOWN</code> 하행

- 다른 API와 ID가 동일한지: **보장되지 않음**
  - 실시간 위치·도착 API와 산술 변환이나 이름만으로 ID를 추정하지 않는다.
- 내부 표준 ID 매핑 필요 여부: **필요**
  - versioned <code>canonical_station_crosswalk</code>와 <code>canonical_line_crosswalk</code>를 관리한다.
- <code>ROWNUM</code>:
  - 현재 파일 버전 안에서는 고유하다.
  - 새 버전에서 같은 운행을 가리키는 영구 ID로 사용하지 않는다.

  - [ ] 사고·운행장애 이벤트 — 관련 필드 없음

### 전처리 규칙

1. <code>LINE</code>, <code>SI_ID</code>, <code>GUBHANG</code>, <code>TRAIN_NO</code>는 문자열로 읽고 선행 0과 문자 접두사를 보존한다.
2. 빈 문자열은 null로 정규화하되 raw 값과 결측 원인을 별도 보존한다.
3. <code>WEEKTAG</code>는 <code>DAY</code>/<code>SAT</code>/<code>END</code>/<code>UNKNOWN</code>으로 정규화한다. 빈 값을 임의 요일로 보간하지 않는다.
4. <code>INOUTTAG</code>와 <code>GUBHANG</code>은 공식 enum을 보존하고 versioned mapping을 적용한다.
5. <code>STT</code>/<code>EDT</code>는 0~25시를 허용하는 service-time parser로 변환한다. <code>24:00</code> 이후는 같은 영업일의 익일 offset으로 처리한다.
6. <code>00:00:00</code>은 의미가 확정되기 전까지 실제 자정으로 단정하지 않고 품질 플래그를 둔다.
7. 계획 정차시간은 같은 행의 <code>EDT-STT</code>로 계산하되 두 값이 유효하고 0시 특수값이 아닌 경우만 사용한다.
8. 계획 구간 운행시간은 현 역의 출발 <code>EDT</code>와 다음 역 도착 <code>STT</code>를 비교한다. 파일에 역 순번이 없으므로 공식 노선 topology와 분기 매핑이 선행돼야 한다.
9. 계획 배차간격은 같은 source version·요일유형·노선·역·방향·급행 구분의 연속 유효 시각 간격으로 계산한다.
10. 실제 지연·실제 배차간격·Actual event는 이 파일에서 생성하지 않는다.

### 다른 데이터와 결합할 키

- 역·노선 기준정보: <code>LINE + SI_ID → canonical_line_id + canonical_station_id</code>
- 실시간 도착·위치정보의 최소 raw identity: 같은 service date 안의 <code>subwayId + statnId + trainNo</code>
- 시간표 결합: <code>service_date + subwayId + statnId + trainNo + direction + observed_time_window</code>
  - <code>LINE + SI_ID</code>를 <code>subwayId + statnId</code>로 바꾼 versioned explicit crosswalk의 버전·매핑 근거를 함께 저장한다.
  - canonical ID는 이 raw identity와 crosswalk provenance를 대체하지 않는다.
- 운행 topology: <code>canonical_line_id + branch + direction + station_sequence</code>
- 내부 여정 leg: <code>canonical_line_id + from_station_id + to_station_id + direction</code>

### 모델 입력 변수

- 계획 서비스: 노선, 역, 방향, 급행 여부, 열차코드, 출발역, 종착역
- 시간: service day type, 계획 도착·출발, day offset, 시간대
- 파생 계획값: 계획 WAIT, 계획 정차시간, 계획 구간시간, 계획 배차간격
- 품질·provenance: source version, file hash, version age, mapping status, 결측·특수시간 flag
- 결합 후 입력: 실시간 열차상태, 실제/추정 event, 시간표 대비 residual, 역사적 지연분포, 환승·보행 분포

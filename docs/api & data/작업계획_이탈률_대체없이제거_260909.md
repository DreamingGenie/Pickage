## 0. 무엇이 빠져 있고 왜 필요한가

목표 화면은 **"X를 떠난 사람들은 어디로 갔나"의 분포**다. 막대는 이렇게 서야 한다.

1. 대체 없이 떠남 (X를 뺐지만 같은 버전에서 아무것도 새로 넣지 않음)
2. Y1로 · 3. Y2로 · … · top-5
4. 그 밖(etc)

지금 `datasets/migration_pairs_260908/`에는 2~4번만 있다. 빌더(`pipeline/duckdb/build_migration_pairs.py`)가 "X를 뺀 전이" 중 **다른 것을 넣은 전이만** `events`로 남기고, 원본이 되는 전이 표 `trans`는 메모리 절약을 위해 중간에 지우기 때문이다. 1번을 세려면 지우기 전에 집계를 하나 더 뽑아야 한다.

같은 표에서 **연도별 이탈 수**(X를 뺀 전이가 해마다 몇 건인지)도 나오므로 함께 뽑는다. 이것이 "이탈 추이" 그래프의 재료다.

추가로, 지금 점유율(`share_pct`)은 **표(votes)** 기준이라 한 조직이 수십 개 패키지를 한 달에 일괄 변경하면 그 Y가 1위로 올라온다(`node-fetch → form-data`: 표 358, 배포주체·월 8). 화면용으로는 **배포주체·월 수 기준 점유율**을 나란히 두는 것이 안전하다.

## 1. 바꿀 곳 (빌더)

`build_migration_pairs.py`의 단계 번호 기준.

### 1-1. 3단계 뒤, `DROP TABLE trans` 앞에 집계 두 개 추가

`trans`의 `removed` 열은 이미 "peer/optional로 옮겨진 이름"을 제외한 진짜 제거만 담고 있다(설계 5-1). 그러므로 그대로 쓰면 된다.

```sql
-- X별 이탈 요약 (X = 제거된 패키지)
CREATE OR REPLACE TABLE removal_stats AS
SELECT x AS removed_pkg,
       count(*)                                   AS removals_total,          -- X를 뺀 전이 수 (추가 여부 무관)
       count(*) FILTER (WHERE len(added) = 0)     AS removals_no_replacement, -- 대체 없이 제거
       count(*) FILTER (WHERE len(added) > 0)     AS removals_with_replacement,
       count(DISTINCT Name)                       AS dependents,              -- X를 뺀 패키지 수
       count(DISTINCT publisher || '|' || strftime(to_ts, '%Y-%m')) AS publisher_months,
       min(to_ts) AS first_seen, max(to_ts) AS last_seen
FROM trans, unnest(removed) AS u(x)
GROUP BY 1;

-- X × 연도 이탈 추이
CREATE OR REPLACE TABLE removal_by_year AS
SELECT x AS removed_pkg, year(to_ts) AS year,
       count(*) AS removals,
       count(*) FILTER (WHERE len(added) = 0) AS removals_no_replacement,
       count(DISTINCT Name) AS dependents
FROM trans, unnest(removed) AS u(x)
GROUP BY 1, 2;
```

`removals_with_replacement`는 기존 `pairs.removal_events`와 같아야 한다(검증 §3-1).

### 1-2. 6단계 `pairs_out`에 점유율 열 추가

```sql
publisher_months / sum(publisher_months) OVER (PARTITION BY from_pkg) AS share_pm
```
CSV 출력(`SELECT_COLS`)에 `round(share_pm*100,1) AS share_pm_pct`를 `share_pct` 옆에 추가한다. 기존 열은 그대로 둔다(AI 팀이 이미 받아 간 파일과 호환).

### 1-3. 7단계 출력 추가

| 산출물 | 내용 | 위치 |
|---|---|---|
| `removal_stats.csv` | X 1행. `removals_total ≥ 3`만 (그 아래는 통계로 의미가 없고 행이 10만 개 넘게 늘어남) | `datasets/migration_pairs_260908/` (추적) |
| `removal_by_year.csv` | X × 연도 1행. 같은 X 기준 | `datasets/migration_pairs_260908/` (추적) |
| `removal_stats.parquet`, `removal_by_year.parquet` | 필터 없이 전부 | `data/migration_pairs/` (미추적) |
| 기존 CSV 3종 | `share_pm_pct` 열 추가 | 갱신 |
| `stats.json` | 자동 갱신. 이번엔 `recommended_*` 키가 들어간다 | 갱신 |

`stats`에 `removed_pkgs_any`(추가 여부 무관 제거된 X 종류), `removals_no_replacement_total`을 추가한다. UTF-8 BOM 처리 반복문에 새 CSV 두 개를 넣는다.

### 1-4. 실행

## 3. 검증

1. `removal_stats.removals_with_replacement` = 기존 `pairs.removal_events` (X별 완전 일치). moment는 1,969.
2. `removals_total = removals_no_replacement + removals_with_replacement` (전 행).
3. `removal_by_year`를 X별로 합치면 `removals_total`과 같다.
4. 표본 눈검사: `left-pad`(내장 기능 대체 → 대체 없이 제거 비율 높아야 함), `request`(대체 동반 비율 높아야 함).
5. `share_pm_pct` 상위 1위가 `node-fetch`에서 `form-data`가 아닌 `axios`로 바뀌는지.

결과 숫자는 이 문서 §5에 적는다.

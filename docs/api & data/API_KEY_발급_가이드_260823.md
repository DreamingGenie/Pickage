# API Key 발급 가이드

> 아래 5개 key를 어디서, 어떻게 발급받는지 정리한다. 실제 key 값은 이 문서나 Git에 절대 커밋하지 않는다(`docs/README.md` Secret Hygiene 참고). 여기 적힌 URL은 root 정본 문서(`SERVICE_PLAN_260823.md` §2.5/§18.4)에서 이미 인용·확인된 공식 출처만 사용했다. 확인되지 않은 URL은 추측해서 적지 않고 "미확인"으로 표시했다.

## 요약

| `.env` 변수 | Provider | 발급처 |
|---|---|---|
| `SEOUL_OPEN_API_KEY` | 서울 열린데이터광장(일반 인증키) | data.seoul.go.kr |
| `SEOUL_SUBWAY_REALTIME_KEY` | 서울 열린데이터광장(지하철 실시간 전용) | data.seoul.go.kr |
| `DATA_GO_BUS_API_KEY` | data.go.kr(서울시 버스 도착·위치정보) | data.go.kr |
| `KAKAO_MAP_REST_API_KEY` | Kakao Developers | developers.kakao.com |
| `TMAP_APP_KEY` | TMAP Open API | 미확인 — 아래 참고 |

## 1. `SEOUL_OPEN_API_KEY` / `SEOUL_SUBWAY_REALTIME_KEY` — 서울 열린데이터광장

공식 인증키 안내 페이지: https://data.seoul.go.kr/together/mypage/actkeyMain.do

1. 서울 열린데이터광장(data.seoul.go.kr)에 회원가입·로그인한다.
2. 마이페이지 > 인증키 안내(위 URL)에서 **일반 인증키**를 발급받는다. 일반 인증키는 호출 "횟수" 제한이 없고, 1회당 최대 1,000건 조회 cap만 있다(2026-08-23 확인, `SERVICE_PLAN_260823.md` §18.4).
3. **실시간 지하철 API**는 별도로 확인해야 하는 제약이 있다: 이 open API는 인증키 1개당 **1일 1,000회**의 계정 단위 공유 한도가 걸린다(활용사례 갤러리 등록 시 무제한 전환 가능, 이 프로젝트는 2026-08-23 기준 미등록). 마이페이지에서 지하철인증키 상태를 확인한다.
4. 활용사례 갤러리 등록 절차(무제한 전환)는 release 전 별도 검토 대상이다(`SERVICE_PLAN_260823.md` §18.4 Quota Budget v1).
5. 발급받은 key를 로컬 `.env`의 `SEOUL_OPEN_API_KEY`(일반 API용)와 `SEOUL_SUBWAY_REALTIME_KEY`(지하철 실시간 전용, 동일 키일 수도 있고 별도 발급일 수도 있으므로 마이페이지에서 실제 서비스별 키 상태를 확인)에 나눠 넣는다.

## 2. `DATA_GO_BUS_API_KEY` — data.go.kr (서울시 버스 도착·위치정보)

포털: https://www.data.go.kr

1. data.go.kr에 회원가입·로그인한다.
2. 아래 두 서비스를 검색해 각각 활용신청한다(2026-08-23 콘솔에서 확인된 정확한 서비스명, `DECISION_SHEET_260823.md` 참고):
   - `[개발계정]서울특별시_버스도착정보조회 서비스` — `getArrInfoByRouteAllList` 등 4개 상세기능, 각각 **1,000/day**(서비스 단위 독립 quota)
   - `[개발계정]서울특별시_버스위치정보조회 서비스` — `getBusPosByRouteStList` 등 5개 상세기능, 각각 **1,000/day**(Arrival과 별도 quota)
3. data.go.kr 계정의 인증키는 서비스 간 공유되지만, quota는 서비스마다 독립적으로 집계된다(공유 풀이 아님, 2026-08-23 마이페이지 콘솔로 확인 완료).
4. 마이페이지 > 활용신청 현황에서 승인 상태를 확인한 뒤 인증키를 `.env`의 `DATA_GO_BUS_API_KEY`에 넣는다.
5. 정확한 서비스 상세페이지 URL은 문서에 확인된 근거가 없어 여기 기재하지 않는다 — data.go.kr 검색창에서 위 서비스명으로 직접 검색한다.

## 3. `KAKAO_MAP_REST_API_KEY` — Kakao Developers

공식 문서: https://developers.kakao.com/docs/ko/kakaomap/rest-api
쿼터 정책: https://developers.kakao.com/docs/ko/getting-started/quota

1. Kakao Developers(developers.kakao.com)에 카카오 계정으로 로그인한다.
2. 내 애플리케이션에서 새 앱을 생성(또는 기존 프로젝트 앱 `pjt_map` 등 사용)한다.
3. 앱 설정 > 앱 키에서 **REST API 키**를 복사한다 — 이 프로젝트가 실제 runtime에서 쓰는 것은 REST API 키다(`dapi.kakao.com/v2/routing/*` WALK/대중교통 endpoint, `SERVICE_PLAN_260823.md` §12 Kakao source 구분).
4. 이 REST API 키는 **한 앱에서 WALK(`KAKAO_MAP_WALK`)와 대중교통 discovery(`KAKAO_MAP_PUBLIC_TRANSIT`) 두 endpoint category에 공용으로 쓰이지만, 프로젝트 내부적으로는 서로 다른 providerKey로 분리 관리한다**(REQ-008). 별도로 키를 두 개 발급받을 필요는 없다.
5. 공식 무료 quota는 첫 번째 활성화 앱 기준 **일 1,000회**(endpoint별 독립), 초과 시 10원/건이며 Bizwallet 연결과 유료 API 사용 설정이 선행돼야 과금이 가능하다(설정하지 않으면 quota 소진 후 429). 프로젝트 앱 entitlement가 실제로 이 조건을 충족하는지 콘솔에서 확인 후 `remaining=1,000`으로 가정한다(`SERVICE_PLAN_260823.md` §18.4).
6. 발급받은 key를 `.env`의 `KAKAO_MAP_REST_API_KEY`에 넣는다. frontend bundle, repo, README, CI log, error body에는 절대 포함하지 않는다.

## 4. `TMAP_APP_KEY` — TMAP Open API

공식 약관: https://transit.tmapmobility.com/terms

TMAP은 이 프로젝트에서 `DISABLED_BY_DEFAULT`(운영자·데모 관리자의 제한된 수동 비상 reference/diagnostic 용도로만 활성화, 사용자 runtime 기본 provider 아님, `SERVICE_PLAN_260823.md` §18.4)이므로 release 전제가 아니다. 공식 무료체험은 대중교통 API 기준 일 10건이다.

**실제 앱 키 발급 URL은 root 문서에서 확인된 근거가 없어 여기 추측해서 적지 않는다.** 위 약관 페이지에서 안내하는 개발자 포털 경로를 팀에서 직접 확인한 뒤 이 문서를 갱신한다. 발급 후에는 pedestrian(도보)과 대중교통 API를 Kakao와 별도 quota·cache·provenance로 관리하고, 원본 응답은 공식 약관상 24시간 초과 보관·사용을 금지한다(`SERVICE_PLAN_260823.md` §18.4).

## 공통 원칙

- 모든 key는 collector/backend에서만 사용하고 frontend bundle이나 URL query에 노출하지 않는다.
- quota 회피를 위한 key rotation을 사용하지 않는다.
- 승인량·처리시점은 제품이 통제할 수 없으므로 증액 신청을 release blocker로 두지 않는다(`SERVICE_PLAN_260823.md` §18.7).
- 이 문서에 없는 새 provider key가 필요해지면 `.env.example`에 변수를 추가하고 이 가이드도 같은 change set에서 갱신한다.

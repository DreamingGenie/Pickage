# OSS Shift 메뉴와 화면 구조 0831

작성 기준일: 2026-08-31
기준 문서: `OSS_Shift_서비스_기획서_0831.md`

이 문서는 OSS Shift의 메뉴, 화면, 이동 순서와 회원 접근 범위를 정한다. 새로운 서비스 기능을 제안하는 문서가 아니다. 화면에 넣는 기능은 0831 기획서의 기능-01~16과 확장-01~09에서만 가져온다.

## 1. 문서 적용 원칙

### 기획서가 먼저다

- 화면 범위와 사용 흐름은 0831 기획서를 따른다.
- 기능별 개발 구상안은 대기, 오류, 자료 부족처럼 화면에 필요한 상태를 확인할 때만 참고한다.
- 두 문서가 다르게 읽히면 기획서의 범위를 유지한다.
- 기능 번호는 기획서와 같은 번호를 쓴다.
- 화면에 들어가는 모든 주요 요소는 기능 번호 또는 확장 번호와 연결한다.

### 사용자가 마지막 선택을 한다

- 사용자는 기능명이 아니라 실제 npm 패키지명을 입력한다.
- 서비스가 비교 후보를 보여 줘도 사용자가 직접 추가하거나 뺀다.
- MVP의 운영자 정의 묶음과 확장의 AI 제안 묶음 모두 사용자가 최종 확정한다.
- 서비스는 기술적으로 가장 좋은 패키지를 자동 추천하지 않는다.

### 결과와 근거를 함께 보여 준다

- 현재 규모와 신규 선택, 유지, 이탈을 구분한다.
- 기준일, 근거 수, 자료 부족, 일부 기간과 계산할 수 없는 상태를 숨기지 않는다.
- 원인, 미래 전망, 기술 우열과 최종 추천을 단정하지 않는다.

### 기획서에 없는 메뉴는 만들지 않는다

다음 기능은 메뉴와 화면에 넣지 않는다.

- 회원 프로필과 조직 관리
- 결제와 요금제
- 즐겨찾기와 알림
- 공동 편집
- 코드 자동 수정
- 실제 실행량 추정
- 기술 우열 점수와 최종 추천
- 교체 이유와 미래 생존 가능성 예측

## 2. 화면에서 사용하는 쉬운 표현

| 피할 표현    | 화면에서 사용할 표현         |
| ------------ | ---------------------------- |
| 랜딩 페이지  | 서비스 소개                  |
| 코호트       | 비교 묶음                    |
| 대시보드     | 분석 결과                    |
| 인증         | 가입·로그인                 |
| 마이그레이션 | 패키지 교체 흐름             |
| 버전 고착    | 이전 버전 유지 현황          |
| 트렌드       | 패키지 변화 또는 패키지 소식 |
| 리포트       | 보고서                       |
| 로딩         | 불러오는 중                  |
| 에러         | 오류                         |

`npm`, `package.json`, `winston` 같은 실제 이름은 바꾸지 않는다.

## 3. 회원과 비회원의 접근 범위

| 화면               | MVP 비회원    | MVP 회원         | 확장 비회원 | 확장 회원             |
| ------------------ | ------------- | ---------------- | ----------- | --------------------- |
| 서비스 소개        | 조회          | 조회             | 조회        | 조회                  |
| 가입·로그인       | 사용          | 로그인 상태 표시 | 사용        | 로그인 상태 표시      |
| 패키지 분석 시작   | 로그인 안내   | 사용             | 로그인 안내 | 사용                  |
| 비교 묶음과 기간   | 접근 불가     | 사용             | 접근 불가   | 사용                  |
| 분석 결과와 보고서 | 접근 불가     | 본인 결과만 조회 | 접근 불가   | 본인 결과만 조회      |
| 패키지 변화 목록   | 제공하지 않음 | 제공하지 않음    | 공개 조회   | 공개 조회             |
| 패키지 변화 상세   | 제공하지 않음 | 제공하지 않음    | 공개 조회   | 공개 조회와 분석 이동 |

회원이 입력한 패키지, 비교 후보, 기간과 개인 보고서는 다른 사용자에게 공개하지 않는다.

## 4. MVP 메뉴와 화면 구조

### 상단 메뉴

#### 비회원

- 서비스 소개
- 로그인
- 회원가입

#### 회원

- 서비스 소개
- 패키지 분석
- 로그아웃

`분석 결과`는 별도 상단 메뉴로 만들지 않는다. 패키지 분석 흐름 안에서 확인한다.

### MVP 화면 목록

| 화면 번호 | 화면 이름              | 접근 | 역할                                                            |
| --------- | ---------------------- | ---- | --------------------------------------------------------------- |
| 화면-00   | 서비스 소개            | 공개 | 서비스 설명, 관측 범위, 제공 결과, 가입·로그인 진입            |
| 공통-A    | 가입·로그인           | 공개 | 회원가입, 로그인, 비회원 분석 접근 안내                         |
| 화면-01   | 패키지 입력·분석 방법 | 회원 | 패키지명 입력, 존재·자료 확인, 결과 생성 방법과 관측 범위 확인 |
| 화면-02   | 비교 묶음과 기간       | 회원 | 운영자 정의 후보 확인, 추가·제외, 기간 확정                    |
| 화면-03   | 분석 결과·보고서      | 회원 | 네 가지 지표, 그래프, 해설, 근거, 한계, 인쇄 확인               |

### MVP 기본 이동

```mermaid
flowchart LR
    A["서비스 소개"] --> B["가입·로그인"]
    B --> C["패키지 입력"]
    C --> D["비교 묶음과 기간"]
    D --> E["분석 결과와 보고서"]
```

### MVP 이동 규칙

1. 비회원이 패키지 분석 주소로 들어오면 가입·로그인 안내로 이동한다.
2. 로그인한 회원은 실제 npm 패키지명을 입력한다.
3. 패키지가 존재하고 분석 자료가 있으면 비교 묶음 화면으로 이동한다.
4. 운영자 정의 묶음이 없으면 사용자가 후보를 직접 입력한다.
5. 입력 패키지를 포함해 비교할 패키지가 최소 2개이고 공통 관측 기간을 선택하면 분석을 시작한다.
6. 분석 결과 화면은 그래프와 보고서를 한 화면에서 제공한다.
7. `방법과 근거`는 별도 메뉴로 만들지 않는다.
   - 결과가 만들어지는 방법과 관측 범위는 화면-01에서 설명한다.
   - 실제 기준일, 근거 수, 계산 방법과 한계는 화면-03에서 제공한다.

```mermaid
flowchart LR
    A["패키지 분석"] --> B["직접 입력 또는 package.json"]
    B --> C["분석 대상 선택"]
    C --> D["비교 묶음과 기간"]
```

### 공개 패키지 변화 이동

```mermaid
flowchart LR
```

## 6. 화면별 역할과 이동

### 화면-00 서비스 소개

#### MVP에 반드시 들어갈 내용

- OSS Shift 한 문장 설명
- 공개 npm 의존 관계 이력을 본다는 설명
- 현재 규모와 신규 선택·유지·이탈을 구분한다는 설명
- 결과와 근거를 함께 제공한다는 설명
- `분석 시작`, `회원가입`, `로그인` 버튼
- 예시 화면은 실제 결과가 아니라는 표시

#### 확장에서 추가할 내용

- `패키지 변화` 메뉴
- 공개 패키지 변화 설명
- 최신 공개 글로 이동하는 구역

MVP의 서비스 설명과 회원 분석 진입은 확장에서도 유지한다.

### 공통-A 가입·로그인

#### 반드시 들어갈 내용

- 로그인 입력
- 회원가입 진입
- 분석은 회원에게만 제공된다는 안내
- 로그인 뒤 원래 가려던 분석 화면으로 돌아가는 동작

프로필, 조직, 결제와 소셜 활동 메뉴는 넣지 않는다.

### 화면-01 패키지 입력·분석 방법

#### MVP에 반드시 들어갈 내용

- 실제 npm 패키지명 입력
- `패키지 확인` 버튼
- 존재 여부
- 분석 가능 여부와 관측 기간
- 서비스가 결과를 만드는 간단한 순서
- 포함하는 자료와 제외하는 자료
- 비회원, 오타, 미존재, 자료 없음 상태

#### 확장에서 추가할 내용

- `패키지명 직접 입력`과 `package.json 읽기` 선택
- 파일 선택 또는 내용 붙여넣기
- 브라우저에서 읽은 일반 의존 패키지 목록
- 목록에서 분석 대상 1개 선택
- 원문을 불필요하게 보관하지 않는다는 안내
- 형식 오류, 빈 목록, 공개 패키지가 아닌 항목 제외 상태

직접 입력 방식은 확장에서도 첫 번째 선택으로 유지한다.

### 화면-02 비교 묶음과 기간

#### MVP에 반드시 들어갈 내용

- 입력한 패키지
- `운영자 정의 묶음` 표시
- 같은 역할의 후보와 선정 이유
- 후보 추가·제외
- 입력 패키지를 포함해 최소 2개 패키지가 필요하다는 안내
- 기본 최근 8개 완결 분기
- 최근 1년·2년·3년과 직접 기간 선택
- 모든 후보가 함께 관측되는 기간만 허용
- `분석하기` 버튼

#### 확장에서 추가할 내용

- `AI 제안 묶음` 표시
- 제안한 직접 대안과 제외 후보
- 포함·제외 이유
- 실제 존재와 분석 자료 확인 상태
- AI 제안 보류·실패 시 운영자 정의 묶음 또는 직접 입력

사용자가 후보와 기간을 최종 확정하는 방식은 바꾸지 않는다.

### 화면-03 분석 결과·보고서

#### MVP에 반드시 들어갈 내용

- 입력 패키지와 최종 비교 묶음
- 선택 기간과 자료 기준일
- 현재 규모
- 신규 선택
- 유지
- 이탈
- 후보별 시계열 그래프
- 지표별 근거 수
- 간단 해설과 자료 부족 경고
- 계산 방법과 한계
- 최종 추천이 아니라는 안내
- `인쇄하기` 버튼
- 대기, 일부 기간, 오류, 해설 실패 상태

#### 확장에서 추가할 내용

- package.json 입력 여부
- AI 제안 사용 여부
- 이전 버전 유지 현황
- 해석할 수 없는 버전 조건 수
- 패키지 교체 흐름
- 표, 배수와 대상 수
- 동시에 바뀌었다는 사실이 원인을 뜻하지 않는다는 안내
- 근거 부족과 의존 종류 이동 상태

MVP의 네 가지 지표, 그래프, 근거, 해설과 인쇄 기능은 확장에서도 같은 순서로 먼저 보여 준다.

### 화면-04 패키지 변화 목록

- 비회원도 조회
- 자료 기준일과 갱신 상태
- 전체, 처음 선택, 신규 선택 증가, 신규 선택 감소, 이탈 증가, 공식 저장소 논의 구분
- 역할별 분류
- 공개 승인된 글만 표시
- 패키지명, 변화 종류, 기간, 근거 수와 한 문장 설명
- `자세히 보기` 버튼
- 갱신 실패, 근거 부족과 미승인 글 비노출

화면 이름은 쉽게 쓸 수 있지만, 회사 내부 신규 프로젝트의 선택처럼 오해시키지 않는다. 실제 대상은 자료에서 확인되는 가장 이른 정식 배포다.

### 화면-05 패키지 변화 상세

- 제목과 자료 기준일
- 변화 종류
- 최근 값과 이전 값
- 최근 기간 그래프
- 같은 역할 후보 비교
- 계산 기간, 대상 수와 제외 수
- 사건을 찾은 계산 기준
- 공식 저장소 원문 목록
- 해석 한계
- `이 패키지 분석하기` 버튼

원인, 기술 우열, 미래 성공과 최종 추천을 표시하지 않는다. 저장소 전체 논의인 경우 특정 패키지의 문제라고 단정하지 않는다.

## 7. 오류와 자료 부족 상태

### 화면-01 입력 상태

| 상황                   | 화면 처리                 | 사용자 안내                         |
| ---------------------- | ------------------------- | ----------------------------------- |
| 비회원 접근            | 가입·로그인으로 이동     | 분석은 회원 전용이라고 안내         |
| 패키지명 오타          | 요청 중단                 | 입력 확인과 유사 이름 안내          |
| 존재하지 않는 패키지   | 요청 중단                 | npm에 존재하지 않는 이름이라고 안내 |
| 분석 자료 없음         | 다음 단계로 이동하지 않음 | 존재하지만 분석 자료가 없다고 안내  |
| package.json 형식 오류 | 파일 처리 중단            | 오류 위치와 다시 입력할 방법 안내   |
| 분석 대상 없음         | 대상 선택 요구            | 자동 일괄 분석하지 않음을 안내      |

### 화면-02 비교 묶음 상태

| 상황                                | 화면 처리                  | 사용자 안내                                            |
| ----------------------------------- | -------------------------- | ------------------------------------------------------ |
| 운영자 정의 묶음 없음               | 직접 입력 제공             | 비교 묶음이 없어도 분석할 수 있다고 안내               |
| 입력 패키지만 있고 비교 후보가 없음 | 분석 버튼 비활성           | 입력 패키지를 포함해 최소 2개 패키지가 필요하다고 안내 |
| 일부 후보 자료 없음                 | 후보에 경고 표시           | 분석 가능한 기간과 제외 여부 확인                      |
| AI 제안 보류·실패                  | 운영자 묶음 또는 직접 입력 | AI 실패가 분석 실패가 아님을 안내                      |

### 화면-03 결과 상태

| 상황                     | 화면 처리             | 사용자 안내                       |

| 자료 없음                | 지표 계산 안 함       | 0이 아니라 자료 없음으로 표시     |
| 계산 실패                | 다시 시도 상태        | 실패 원인과 재실행 상태 표시      |
| 해설 실패                | 그래프·표·근거 제공 | 숫자 결과는 정상이라고 안내       |
| 이전 버전 조건 해석 불가 | 알 수 없음으로 분리   | 전체 비중과 섞지 않음             |
| 교체 근거 부족           | 교체 방향 미표시      | 표·배수·대상 수 부족 표시       |

### 화면-04·05 공개 상태

모든 화면은 같은 상단 메뉴, 남색·청록색, 입력창, 버튼, 표와 그래프 모양을 사용한다. 확장 화면은 대응하는 MVP 화면을 바탕으로 만들고, 추가 기능만 보강한다.

> **최종 기준** OSS Shift의 화면은 검색 결과 목록을 늘어놓는 것이 아니라, 실제 패키지 입력에서 비교 묶음과 기간 확정, 시계열 비교, 근거와 보고서까지 이어지는 한 흐름을 제공해야 한다.

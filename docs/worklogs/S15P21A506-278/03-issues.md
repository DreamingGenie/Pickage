# 03. 이슈와 해결 기록

착수 시 확인한 차이와 해결 결과다. 원격 Jira 상태는 조회하지 않았고, 후속 구간별 집계 검사는
이 작업의 범위에 포함하지 않는다.
[범위](01-scope.md) · [계획](02-plan.md)

| ID | 현상 / 근거 | 확인·해결 조건 | 상태 |
| --- | --- | --- | --- |
| ISS-001 | 기존 MinIO 입고기는 deps.dev의 dataset/snapshot 경로와 `_MANIFEST.json`을 전제로 한다. 다운로드는 대상 CSV·JSONL·일별/상태 Parquet 구조다 | 다운로드 입력 선택·manifest·계보·prefix를 별도 모듈로 구현하고 기존 업로더는 공통 클라이언트·해시 규칙만 재사용한다 | 해결 — `pipeline/downloads/{input,lineage,bronze,load}.py`, P-04 |
| ISS-002 | 본 raw 실행에 `.broken` 파일과 checkpoint가 있고 smoke 실행·Parquet도 별도로 존재한다 | 정상 입력 768개와 제외 742개를 고정하고 제외 사유를 기록한다. 원본을 삭제·이동하지 않는다 | 해결 — smoke 733, broken 4, checkpoint/fixture 3, log 2; P-01 |
| ISS-003 | raw 응답→일별 Parquet 생성 코드·버전과 `imputed_gap` 생성 규칙의 확인이 끝나지 않았다 | 과거 후보 코드와 규칙을 찾아 8개 패키지의 전체 시계열 키·값·gap을 대조한다. 실제 생성 버전은 미확인으로 남긴다 | 해결 — 표본 일치와 미확인 계보를 manifest에 보존. AC-05 조건에 따라 P-03 완료 |
| ISS-004 | 대상 CSV에는 100,000행·99,996 고유 이름·중복 이름 4개가 있다 | 중복 원본 행을 보존하고 CSV `status`를 선정 힌트로만 기록한다. 상태 Parquet는 별도 검증 기준으로 사용한다 | 해결 — `source-inspection.json`, P-02 |
| ISS-005 | READY 상태와 실제 날짜·값 완전성은 다르며 NULL·gap·실제 0이 함께 존재한다 | 상태와 일별 데이터를 대조하고 NULL·gap·0을 별도 보존한다. NOT_FOUND의 일별 행 충돌을 검사한다 | 해결 — NULL/gap 437,786, 실제 0 5,322,058, 상태 충돌 0; P-02 |
| ISS-006 | 현재 브랜치에서 티켓 번호 278은 확인했으나 원격 Jira 조회 도구가 없고 원격 이슈를 확인하지 않았다 | 로컬 작업 기록은 사용자 지정 브랜치와 작업 내용에 연결한다. 원격 제목·상태·댓글을 갱신했다고 기록하지 않는다 | 원격 미확인, 범위 외 |
| ISS-007 | 실제 MinIO 접속·버킷 상태·다운로드 완료 객체 유무는 전체 입고 전까지 확정할 수 없다 | P-05에서 작은 test prefix의 업로드·재검증·실패·삭제를 확인하고, P-06에서 대상 버킷·prefix에 전체 입고 후 전체 GET 검증을 수행한다 | 해결 — 771개 완료 객체를 1차 게시·2차 재검증하고 입력 768개를 각 시도마다 GET·SHA-256 검사. 기존 객체 3,927개의 metadata 지문 보존 확인 |
| ISS-008 | 최종 manifest의 모든 일별 파일과 READY 기간 집계가 최종 검증에 필요하다 | 모든 730개 물리 Parquet 스키마와 READY의 expected/observed/missing/null/complete 집계를 검사한다 | 해결 — 최종 코드·31건 검증과 실제 manifest에서 확인 |
| ISS-009 | 구현 중 물리 `date`가 없고 Hive 경로에만 날짜가 있는 fixture에서 날짜 조회가 실패했다 | Hive 날짜 읽기를 명시하고 Windows 입력 경로를 정규화한다. 물리 `date`가 있을 때만 파티션 날짜와 별도로 대조한다 | 해결 — 해당 입력·실행 fixture와 최종 31건 검사 통과. 실제 730개 파일도 Hive 날짜로 검증 |

문제를 발견하면 증상·입력/실행 ID·재현 근거·영향받는 AC·조치·재검증 결과를 연결해 기록한다.
예상 문제와 실제 발생한 실패는 구분하고, 원본을 임의 보정하여 완료 기준을 맞추지 않는다.

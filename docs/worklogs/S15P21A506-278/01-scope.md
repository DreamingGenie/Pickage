## 목표와 필요한 작업

이미 수집한 npm 다운로드 자료를 파일 역할과 데이터 의미에 맞게 검증하고,
`pickage-raw`에 원본을 보존하는 Bronze 실행으로 입고한다. 후속 집계가 정확한 파일 목록,
실제 보유 기간, 누락과 실제 0을 구분하여 읽을 수 있도록 입력과 검증 결과를 고정한다.

| 작업 ID | 해야 하는 일 | 연결 계획 |
| --- | --- | --- |
| T-01 | 본 실행의 파일 목록·역할·출처와 기존 입고 코드의 재사용 범위 확인 | P-01 |
| T-02 | 대상 목록·상태·일별 행의 스키마·키·기간·값·관계 검증 | P-02 |
| T-03 | 원본 응답에서 일별 Parquet를 만든 코드·규칙 확인 및 표본 대조 | P-03 |
| T-04 | 실행 ID·파일 종류·해시·기간·검증 결과를 담는 다운로드 manifest 계약과 입고 경로 구현 | P-04 |
| T-05 | 동일 입력 재실행·입력 변경·체크섬 불일치·중간 실패·동시 실행 보호 검증 | P-05 |

## 입력 역할과 식별자

아래 경로는 P-01~04에서 선택·검증한 실제 입력이다. 원본은 수정하지 않았고, 선택·제외 목록과
품질 요약은 `data/downloads/S15P21A506-278/source-inspection.json`에 기록했다.

| 입력 | 역할 / 행 단위 | 처리 기준 |
| --- | --- | --- |
| `data/raw/downloads/targets_top100k_20260902.csv` | 수집 대상 선정 목록의 한 행 | CSV 행 수와 고유 패키지 수를 따로 센다. 중복 이름을 보고하고 원본을 임의 수정하지 않는다 |
| `data/raw/downloads/raw/run=2026-09-02/part-*.jsonl.gz` | 원본 수집 응답. 34개 파일, 145,504개 응답 | 본 실행의 정상 파일만 선택했다. 응답 수를 패키지 수나 일별 행 수로 간주하지 않는다 |
| 같은 본 실행의 `manifest.json`, `run.json` | 기존 수집 실행 메타데이터 | 원본으로 보존한다. 누적 처리 횟수를 고유 패키지 수로 사용하지 않는다 |
| `data/raw/downloads/parquet/downloads/date=.../` | 패키지의 하루 다운로드 값, 실질 키 `(name, date)` | 730개 파일, 62,616,750행, 2024-09-01~2026-08-31. `downloads`, `imputed_gap`, `tier`, `fetched_at`, `date`의 타입과 관계를 검사했다 |
| `data/raw/downloads/parquet/downloads_status.parquet` | 패키지별 수집 상태 | 99,996행·고유 이름 99,996개, READY 99,215건·NOT_FOUND 781건. 대상 목록 및 일별 데이터와의 관계를 검사했다 |
| smoke 실행·`targets_smoke.csv`·`parquet_smoke`, `.broken` 파일, `checkpoint.sqlite`·로그 | 시험·실패·재개용 자료 | 정상 집계 입력에서 논리적으로 제외하고 제외 목록·이유를 기록한다. 원본을 이동·삭제하지 않는다 |

대상 목록은 선정 시점의 목록이다. 모든 과거 날짜의 top 100k 또는 npm 전체 모집단으로
해석하지 않는다. 이번 Bronze 단계의 키는 원천 이름과 날짜이며 package ID를 새로 발급하지 않는다.

## P-01~04 실측 범위

전체 파일 목록에서 768개를 선택하고 742개를 제외했다. 선택 목록은 대상 CSV 1개,
source metadata 2개, raw response 34개, 일별 Parquet 730개, 상태 Parquet 1개다.
제외 목록은 smoke output 733개, broken partial output 4개, checkpoint·smoke fixture 3개,
execution log 2개이며 원본에서 삭제·이동하지 않았다.

대상 CSV는 100,000행, 고유 이름 99,996개, 중복 이름 4개다. CSV의 `status`는 선정 힌트로
보존하고 수집 상태의 기준으로 쓰지 않으며, 상태 Parquet를 별도 기준으로 검사했다.
일별 Parquet는 62,616,750행이며 날짜 범위는 2024-09-01부터 2026-08-31까지다.
`downloads=NULL` 및 `imputed_gap=true`는 각각 437,786행, 실제 `downloads=0`은 5,322,058행이다.
중복 `(name,date)` 키, 음수 다운로드, 대상·상태 충돌은 모두 0건으로 확인했다.

원본 gzip 응답은 145,504개 응답, `ok` 144,346개, `not_found` 1,158개, 고유 패키지
99,996개다. 상태 Parquet의 NOT_FOUND 781건과 원본 응답의 `not_found` 1,158건은 서로 다른
행 단위의 통계이므로 같은 수치로 해석하지 않는다. 전체 시계열 키·값·gap은 이름 정렬 순서의
최대 8개 패키지 표본에서 원본과 Parquet가 일치했고, 누락·추가 키는 없었다.

`source-inspection.json`은 READY 기간 coverage 집계를 추가하기 전의 실측 결과다. 따라서
그 증거 파일에 해당 집계 필드가 없다는 사실을 0건으로 해석하지 않는다. 최종 코드에는
READY별 expected/observed/missing/null/complete 집계를 추가했고, 최종 수치는 전체 입고 결과와
함께 갱신한다.

생성 계보는 과거 커밋 `33b49adef8ea6f6f01bf1f91048ffcf239c7a73d`의 후보 코드와
blob `d9562f12af10e62eac98e81f604c9635522ba56a`까지 확인했지만, 해당 코드가 이 입력을
실제로 생성한 버전인지는 미확인이다. 이 상태는 `lineage-inspection.json`과 manifest에 보존한다.

## 확정한 의미와 보존 조건

- `READY`는 수집 상태이며 모든 날짜에 유효한 다운로드 값이 있다는 뜻이 아니다.
- `downloads=NULL`, `imputed_gap`, 실제 `downloads=0`을 별도로 집계하고 보존한다.
  NULL이나 `NOT_FOUND`를 0으로 채우지 않는다. `imputed_gap`의 생성 원인은 코드·표본으로 확인하기 전까지 미확인이다.
- `NOT_FOUND`는 해당 수집에서 일별 데이터가 없는 상태로 대조한다. 데이터가 함께 발견되면 충돌로 보고한다.
- 다운로드 대상 날짜, 원본 수집 시각, Parquet 생성 시각, Bronze 입고·검증 시각을 구분한다.
  실행 폴더 날짜를 다운로드 대상 날짜 또는 스냅샷 시각으로 대체하지 않는다.
- 원본 파일 바이트·이전 완료 객체는 보존한다. 새 검증 결과와 입고 manifest를 별도로 작성한다.
- SHA-256은 파일 내용의 동일성을 검사한다. 행 단위·키·값·기간·변환 의미는 별도 검사로 확인한다.
- 후속 스냅샷 구간별 다운로드 집계는 [269 시간 정책](../../../pipeline/snapshot/README.md)의 `[P,S)`를 사용한다.
  이번 작업은 구간 합계를 계산하거나 원본 일별 데이터를 스냅샷 날짜로 재작성하지 않는다.

| AC-09 | 후속 집계가 사용할 검증된 raw run ID·manifest·정확한 파일 목록·품질 한계·재실행 방법이 인계된다 | P-07 |

조사할 근거이며, 과거 수치를 고정 기대값으로 삼거나 차이를 임의 보정하지 않는다.

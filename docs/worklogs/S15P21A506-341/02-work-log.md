## 구현 중 발견한 문제와 조치

- V6의 DO 블록과 내부 정규식 구분자 충돌로 최초 Flyway 시험이 실패했다. 각각 다른 dollar-quote 구분자를 사용해 수정했다.
- archive TOC가 `숫자; ... TABLE ...` 형식인데 주석처럼 건너뛰는 문제를 실제 덤프로 발견해 수정했다. 시험 fixture도 실제 PostgreSQL 형식으로 바꿨다.
- 후보 객체 검사에서 Flyway 자신의 인덱스를 비대상 객체로 세는 문제를 수정했다. 테이블·뷰·시퀀스를 기준으로 허용 범위를 검사한다.
- 호스트 archive와 Docker 내부 archive의 SHA를 함께 검사하고, 입력 manifest의 잘못된 경로·중복 항목을 거부하도록 보완했다.
- V6 부모 검사와 별도로 각 자식의 기본값·제약·인덱스를 검사한다. 자식 기본값을 1로 변조하면 실패하는 실제 사례를 추가했다.
- 보조 구현자가 원본 로컬 DB에서 V6를 `BEGIN; ... ROLLBACK;`으로 구문/계약 시험한 실행이 있었다. V4 인덱스 부재 검사에서 오류로 종료됐고 변경 분기에 도달하지 않았다. 후속 검증은 모두 격리 컨테이너에서 수행했다. 원본 parent OID 280767, RANGE(snapshot_at), 자식 229개 유지 확인. 서버에서는 실행하지 않았다.

- [이관 도구](../../../scripts/service-data-migration/transfer.py): 선택 directory dump, 파일별 SHA-256, Docker 경로 일치, TOC 대상 검사, 단계별 복원과 실행 기록.

기존 일반 테이블에 데이터가 있으면 V6는 실패한다. 사용자 지정 권한·트리거·RLS 등 재생성 시 의미가 바뀔 수 있는 구조도 자동 변환하지 않는다. 새 부모에는 날짜별 자식을 만드는 적재 절차가 따로 필요하다.

## 실행·검증 근거

- PostgreSQL 16 기반 별도 테스트 컨테이너, 메모리 상한 2GiB.
- Java 17의 시험 실행기 + Flyway 11.14.1 + PostgreSQL JDBC 42.7.11. 애플리케이션 HTTP 기동 시험은 아니다.
- 새 DB의 V1→V6 및 실제 V1 이력 보존 → archive 복원 → V2→V6 경로 모두 성공했다. Flyway validate도 통과했다.
- **통합 검사 22개, Python 단위 시험 5개 통과**, Python 구문 검사 통과.
- 잘못된 컬럼/길이, 비어 있지 않은 일반 테이블, 외부 FK, 사용자 지정 권한, 월 단위 파티션, 약해진 CHECK, 자식 기본값 변조를 거부했다.
- 파일 변조, 기존 archive 덮어쓰기, 서비스 DB 지정, 같은 후보에 중복 COPY를 차단했다. 후보 준비 시 V1 이력 값이 그대로 유지되는지도 비교했다.
- 최종 실행 기록: 로컬 `data/service-data-migration/pilot-05/result.json`, run id `954b34f72a5f`. 원본 로그와 CSV/archive는 Git 제외 경로에만 남겼다. 테스트 컨테이너와 그 볼륨은 종료 후 제거했다.

재현 명령은 [도구 README](../../../scripts/service-data-migration/README.md)의 로컬 통합 시험 절을 따른다.

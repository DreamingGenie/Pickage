## 3. 사실관계 재대조

- 백엔드 `SnapshotWindow.MAX_WEEKS`와 프런트 `MAX_WEEKS`가 모두 104임을 확인했다.
- 후보 API가 `GET /packages/similar`이며 후보 응답에 `rank`, `score`, `latest_version`이 있음을 확인했다.
- 현재 UI는 후보 2개만 보여 주고 기본 선택하지 않으며 수치형 score를 표시하지 않음을 확인했다. 후속 제품 계약은 후보 최대 3개이므로 노출 수는 구현 gap이다.
- 기준 패키지는 후보 API의 `not_found`로, 직접 추가 패키지는 `/packages/search?q={name}&limit=5` 결과의 exact match로 검증하는 차이를 확인했다.
- Dependents 응답은 `sum_over_versions=true`인 major별 series이며 프런트가 선택한 major를 합산함을 확인했다.
- Version Share API가 requirements 완료 포인터가 아니라 최신 DB Snapshot을 조회함을 확인했다.
- requirements resolution 전체 실행이 `PARTIAL`이고 표준 게시 및 serving 연결 전이라는 기존 작업 증거를 유지했다.
- 저장소 compose와 서버 구성 PDF의 관측 범위를 서로 다른 근거로 표시했음을 확인했다.

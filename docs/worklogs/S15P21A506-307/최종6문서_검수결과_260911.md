## 1. 판정

기존 6문서는 제품 방향은 상당 부분 맞지만 **그대로 구현 착수 기준으로 삼기에는 부족**했다.
특히 community 문서는 구조 요약에 치우쳐 파트별 인계, 전체 wire, 페이지 수집 알고리즘,
실패/재시도 경계와 검증 방법이 빠져 있었다. 루트 문서에도 실제 상충하는 요구가 있었다.
검색 결과만으로 판정하지 않고 6개 문서 본문 전체, 9월 8일 community 원문, 이전 사용자 결정과
AI 결정 원문을 읽고 사용자/구현자/운영자 시나리오에 대입했다.

이번 수정은 문서 계약을 보완하는 작업이다. community 기능 구현·외부 연결 성공·코드 결함 해결을
뜻하지 않는다. GMS 실제 연결 계약 확인과 API 정본 등록은 담당 파트의 착수 산출물로 남긴다.
“문서만 있으면 어떤 환경에서도 즉시 개발·배포 가능”이라는 보장은 하지 않는다.

## 4. 코드 차이 — 기획 하향/자동 승인이 아님

### 이미 사용자가 기획을 유지하기로 한 항목

- log1p, 8일 초과 주간 공백, 계열별 2개 이하 축적, 카드별 오류 격리, 표시 기간 signed delta.
- 후보 최대 3개 노출·기준만 초기 선택·총 비교 최대 3개.

- BE+AI: 실제 GMS method/path/auth/model/envelope 확인과 정제 fixture 제공. key 보유는 이미 인정한다.

| R04 | 필드 사전만으로는 nullable 조합과 부분 실패 결과를 이해하기 어려움 | 재시작 후 RESULT/전체 요약 FAILED 및 최초 IDLE의 완전한 합성 wire 예시 추가 |
| R05 | 글자 48,000자 제한만으로 실제 model context가 보장되지 않음 | 확인한 model context에서 prompt·출력 token을 뺀 입력 예산도 적용 |
| R06 | Link를 그대로 fetch하거나 DB connection 대기가 deadline 밖일 수 있음 | page 정수만 고정 path에 적용; pool 획득/lock/statement를 각각 남은 예산 시험 |
| R07 | POST capacity 거절은 비등록이므로 뒤따른 GET IDLE에 안내가 사라짐 | GET state와 별개의 기준 패키지별 action notice로 거절/retry_at 유지 |
| R08 | 외부 HTTP 예외를 전역 handler에 넘기면 body가 stack trace log에 남을 수 있음 | client 경계에서 raw cause 없는 정제 domain 오류로 변환, 실패 로그 검사 |
| R09 | 서비스 MVP 여정에 공유가 포함되고 기능 화면 하위 항목이 PDF 밑에 위치 | PDF는 확장으로 명시, 환경/기능/Drawer는 기능 비교 아래로 이동 |

| R11 | community header 한 문장 설명이 별도 모델 종합 요약 요구처럼 해석됨 | IA 목적 설명과 같은 고정 수집 범위 안내로 정의, 추가 모델 호출 없음 |
| R12 | trigger 오류의 구체 code가 빠짐 | 실제 GlobalExceptionHandler.typeMismatch에 맞춰 V004/400, 누락/빈 값 V001 |

모두 기존 기능 범위 안의 실행 명확화다. 새 테이블·raw 보존·추가 GMS 호출·다른 패키지 fallback을
추가하지 않았고, 사용자 승인 그래프 요구·AI 관문·후보 초기 선택을 변경하지 않았다.

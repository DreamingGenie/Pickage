# 41. 빠른 전체 DB 재적재 실행

## 요청과 범위

2026-09-12 사용자 요청: 준비된 전체 적재를 진행하고, 독립적으로 실행되는 단계는 에이전트가 실시간으로 반복 확인하지 않는다.

- 기존 검증 Parquet를 사용해 전체 229일/1,007,084,608행을 새 대상에 적재한다.
- 대상은 `pickage_267_full_defaulted`의 `vd193_reload_20260912_ready01.package_version_snapshot`이다.
- 기존 public 테이블의 43일/106,346,692행과 기존 게시 이력은 보존한다.
- 서비스 테이블 전환과 커밋/푸시는 이번 실행 범위에 포함하지 않는다.
- 코드·입력·계획 계약을 변경하지 않는다. 원본/키 점검 후 날짜별 적재·검증·완료 기록을 자동 수행한다.
- 전체 고정 시간 제한은 없다. 날짜별 중단/재개, 디스크 여유 검사, 프로세스 heartbeat와 자동 절전 억제를 사용한다.

## 실행과 관찰 정책

`scripts/version-dependents-reload.ps1 -Action Start`로 숨김 백그라운드 프로세스를 시작한다.
정상 착수만 한 번 확인하고 에이전트의 반복 조회를 중단한다. 완료/오류는 실행기가 파일로 기록한다.
예약 모니터링이나 별도 에이전트 추적 작업은 만들지 않는다.

상태·로그·날짜별 결과: `data/vd-db-reload-ready-20260912-01/job/`.
사용법: [40 실행 안내](40-fast-reload-runbook.md).

- **완료 여부와 실제 소요 시간은 아직 미확인**이다. 기존 실험 기준 일정 예상은 약 3~4시간이며 보장된 완료 시각이 아니다.

## 사용자 요청으로 중단 — 2026-09-12 23:18:34 KST

사용자가 실제 서비스 조회가 **패키지 AND 버전별로 특정 날짜의 dependents_count를 가져와 그래프로 표시하는 방식**임을 명확히 하고 적재 일시중단을 요청했다. 버전들을 합산하는 그래프와 구분한다.

- Stop 명령으로 날짜 경계 중단을 요청했고, 2022-09-13 날짜 완료 후 프로세스가 정상 종료됐다.
- 새 대상: **19일/43,616,976행** 확정 보존. 다음 날짜는 **2022-09-19**, 남은 행 수는 963,467,632행이다.
- 상태 STOPPED, DB 실행 세션 0, 미완료 PREPARING attempt 0 확인.
- 기존 public 대상: 43일/106,346,692행 게시 이력 유지.
- 원본/코드/실행 계획은 변경하지 않았고, [중단 체크포인트](evidence/db-fast-reload-pause.json)를 남겼다. 자동 재개하지 않는다.
- 단일 날짜의 패키지·버전 조회는 해당 날짜 partition과 기존 복합 PK를 사용할 수 있다. 여러 날짜 그래프는 관련 partition별 인덱스를 접근하므로 조회 계획/접근 비용이 늘어날 수 있다. 실제 지연 시간은 아직 측정하지 않았다.
- 확인된 백엔드 DEPENDENTS_TREND_SQL은 버전들을 SUM하고 있어 방금 명확해진 서비스 조회 계약과 다르다. 조회 설계/성능 비교 때 버전별 값 조회로 구분해야 하며 이번 중단 작업에서는 코드를 변경하지 않았다.

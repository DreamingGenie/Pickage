# 29. 로컬 전체 집계의 자원·시간 한도 확대

## 변경 범위와 작업 계획

2026-09-12 사용자가 메모리·디스크 한도 확대와 개별 요청 3분 제한을 승인했다.
현재 로컬 PC는 약 63.5GiB RAM 중 33GiB가 비어 있고 디스크 여유는 약 1.1TiB다.
전체 집계 실행, 전원 설정 변경, DB 적재, Jira, 커밋·push는 이번 작업에 포함하지 않는다.

| 설정 | 기존 | 변경 계획 |
| --- | --- | --- |
| 입력 준비·CPU 계산 전체 DuckDB 메모리 예산 | 4GB | 16GB |
| CPU 작업자 4개 기준 작업자별 예산 | 1GB / 임시 10GB | 4GB / 임시 64GB |
| 입력 준비·최종 병합 임시 디스크 | 40GB | 256GB |
| 병렬 프로세스 트리 RSS 중단 기준 | 12GiB | 24GiB |
| 병렬 임시 파일 중단 기준 | 64GiB | 320GiB |
| 개별 Node 요청 | 60초 | 180초 |

GB는 DuckDB에 전달하는 십진 단위이며 GiB는 1024 기반 프로세스 감시 단위다.
한도는 선할당 크기가 아니다. 병렬 입력 전역 검증·날짜 묶음 저장·결과 검증에도
16GB/256GB를 적용한다. 작은 파일 메타데이터 검사와 기존 H1/H5 검증기는 변경하지 않는다.
남은 디스크 20GB 이하 중단 기준, 작업자 수, 집계 의미와 품질 검증은 유지한다.

1. 현재 병렬 경로의 기본값과 전역 검증/저장 연결에 새 한도를 적용한다.
2. 기존 병렬 입력·계산·재개·변조·날짜 묶음 저장 테스트로 동작을 확인한다.
3. 작업 결과와 미실행 범위를 기록한다. 전체 데이터 계산이나 속도 측정은 하지 않는다.

## 생성 계약과 기존 결과

병렬 생성 코드가 바뀌므로 과거 표본의 입력/실행을 새 코드에서 그대로 재개하면
생성 계약 불일치로 거부된다. 기존 산출물과 지문은 수정하지 않는다.
새 전체 집계 입력은 새 코드로 생성하며, H1/H5 원본 생성 코드는 변경하지 않는다.
기존 성능 수치는 이전 설정에서 얻은 측정값이다.

## 실제 진행 결과

- 병렬 입력·CPU 실행·날짜 묶음 저장·검증 4개 모듈의 11줄을 변경했다.
- 실제 함수 기본값 확인: 요청 180초, 작업자 4개 기준 4000MB/64000MB,
  프로세스 RSS 25,769,803,776바이트, 임시 파일 343,597,383,680바이트.
- 기존 병렬 입력·계산·프로세스·저장 테스트 25개가 50.644초에 통과했다.
  작은 데이터의 결과 일치, 중단 후 재개 및 변조 거부를 포함한다.
- 변경 Python 4개 구문 검사와 `git diff --check` 통과.
- 기존 H1/H5 입력 manifest·생성 계약과 H5 profile 파일 지문 재확인 통과.
- 전체 집계, 확대 한도의 실제 최대 사용량 측정, 전원 설정 변경, DB 적재,
  커밋·push는 수행하지 않았다. 노트북 덮개 절전 설정은 여전히 별도 실행 전 조치다.

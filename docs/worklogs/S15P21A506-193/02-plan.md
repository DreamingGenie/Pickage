## 먼저 확인할 입력 조건

1. 작업 위치는 기존 워크스페이스로 고정한다. 현재 이 위치에 `data/requirements-resolution`이 없다는 확인과, 입력을 실제로 잃었다는 판단은 구분한다.
2. 7번 run과 실제 파일을 이전 계산 위치에서 확인했다. 현재는 읽기 전용 참조이며 이동·복사를 하지 않는다. 위치와 확인 범위는 [입력 조사](07-input-contract.md)에 남긴다.
3. 기록된 `PARTIAL`, `ready_for_dependents=false`와 최종 완료 기록·추가 검증의 한계를 확인한다. 코드 병합을 데이터 입력 승인으로 대체하지 않는다.
4. 전체 target 버전 집합과 정확한 스냅샷 시각을 확정한다. edge에 나타난 target만 집계 모집단으로 삼지 않는다.
5. 현재 계약에서 PARTIAL 결과는 정상 count로 게시하지 않는다. 별도 진단용 집계를 허용할지 또는 이 계약을 바꿀지는 결정 기록이 생기기 전까지 미확정으로 남긴다.

실제 입력의 사용 조건이 미충족이어도 합성 데이터로 P-02~04를 개발·검증할 수 있다. 실제 데이터의 정상 게시 가능 여부와 구현 진행 가능 여부를 구분한다.

## 작은 정답 데이터에서 검증할 사례

- 같은 source 버전·target 버전의 중복 관계는 한 번만 센다.
- 같은 패키지의 서로 다른 source 버전은 각각 센다.
- target의 버전이나 snapshot이 다르면 count가 섞이지 않는다.
- 관계가 없는 정상 target의 0과 입력 누락·미해석·실패를 구분한다.
- target 집합 밖의 관계, 미래 배포, 파일 누락·변조, 잘못된 manifest를 거부한다.
- count의 INT 범위와 DB 복합키·외래키를 검증한다.
- 계산 실패와 DB 적재 실패를 구분하며, 적재 실패가 완료된 count 파일을 훼손하지 않도록 검증한다.
- 동일 입력 재실행, 다른 입력 충돌, 동시 실행과 중간 실패의 결과 보존을 확인한다.

## 전체 실행 전 확인할 사항

입력 검증과 집계 과정에서 중복되는 전수 스캔을 줄일 수 있는지 검토하되 검증 항목을 생략하지 않는다. 7번의 추가 검증은 메모리 부족으로 중단된 이력이 있으므로 사용할 메모리·임시 디스크·복구 방법을 실행 전에 기록한다. 현재 새로운 전체 검증·계산 프로세스는 시작하지 않았다.

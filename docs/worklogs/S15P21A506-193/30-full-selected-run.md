# 30. 선정 99,996개 패키지의 전체 날짜 Parquet 집계

## 승인 범위와 실행 계획

2026-09-12 사용자가 전체 Parquet 집계를 승인했다. CPU 작업자 4개와 날짜 묶음 저장을 사용한다.
새 전체 입력 준비 → 128개 묶음 계산 → 전체 병합 → 229개 날짜 Parquet 저장 → 결과 검증을 수행한다.
저장 target은 선정 이름 99,996개이고, 참조 source는 전체 적격 패키지·버전이다.
dependencies·배포일 NULL 제외·미해석 PARTIAL 정책을 유지한다. DB 적재는 포함하지 않는다.

- 실행 폴더: `data/vd-full-20260912-01`
- 입력 지문: `evidence/daily-throughput-selection.json`의 고정 목록 사용
- 자원: 메모리 16GB, 임시 디스크 256GB, 프로세스 RSS 24GiB, 임시 파일 감시 320GiB
- Node 요청 180초. 전체 작업의 경과 시간 제한은 두지 않는다.
- Windows 관리 서비스를 통해 숨김 프로세스를 생성해 채팅 실행 프로세스와 분리한다.
- 실행 스크립트·설정·PID·상태·단계·오류·최종 검증 결과를 실행 폴더에 저장한다.
- 프로세스가 자동 절전 방지 요청을 유지한다. **덮개 닫기·수동 절전·종료·재부팅은 막지 않는다.**
  전원을 연결하고 덮개를 열어 둬야 한다.
- 시작 상태 확인 뒤 에이전트의 반복 조회는 중단한다. 예약 모니터링은 생성하지 않는다.

## 중단과 재개

완료된 계산 묶음은 코드·입력 지문이 일치할 때 재사용할 수 있다.
입력 준비와 최종 병합에는 내부 재개 지점이 없다. 실행 중 관련 코드를 변경하지 않는다.
오류는 FAILED 상태와 traceback으로 남기며 실패를 성공이나 적재 가능으로 표시하지 않는다.

## 실제 진행 기록

- 2026-09-12 00:07:37 KST 숨김 프로세스 PID `290424`로 시작했다.
  WMI 프로세스 생성 반환값 0, 부모 PID 5084로 채팅 shell과 분리했다.
- 시작 확인: `status=RUNNING`, `phase=PREPARE_FULL_SELECTED_INPUT`, CPU 누적 18.75초,
  `input/input_plan.json` 생성 확인. 입력 준비가 끝나면 자동으로 계산·저장·검증을 진행한다.
- 상태 파일은 30초마다 갱신한다. 이는 프로세스 생존·현재 단계를 뜻하며 처리 행 수는 아니다.
  계산 단계의 자세한 이벤트는 `run/progress.jsonl`, 실패 traceback은 `console.log`에 남긴다.
- 최초 WMI 시작 옵션의 CreateFlags 조합은 반환값 21로 거절되어 프로세스가 생성되지 않았다.
  ShowWindow=0만 지정한 호출로 바로 재시도해 성공했다. 중복 계산은 시작하지 않았다.
- 시작 확인 이후 반복 조회를 종료했고, 사용자의 다음 상태 확인 요청에서 완료를 확인했다.

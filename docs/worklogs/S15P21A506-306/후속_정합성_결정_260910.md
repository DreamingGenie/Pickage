## 1. 적용 우선순위

충돌하는 문장은 다음 순서로 해석한다.

1. 사용자의 이번 최종 결정
2. AI팀 결정 문서 `source/제안_유사후보_v1랭커_2단계분리_260910.md`
3. 현재 기획 문서

AI팀 원본은 머리말에 `제안·아직 확정 아님`이라고 적혀 있지만, 사용자가 AI팀의 결정임을 확인했다. 원본의 내용과 기존 SHA-256 증거를 보존하기 위해 source 파일은 수정하지 않고 이 문서에서 승인 지위를 기록한다.

## 2. 최종 후보 UI 계약

| 항목 | 최종 결정 |
| --- | --- |
| 검색 후보 풀 | `search_k=N`, 화면 노출 수와 분리 |
| 후보 노출 | 기준 패키지를 제외한 상위 최대 3개 |
| 초기 선택 | 기준 패키지만 선택, 후보는 모두 미선택 |
| 최대 비교 | 기준 패키지를 포함해 최대 3개 |
| 후보 선택 | 노출된 후보 최대 3개 중 사용자가 최대 2개 선택 |
| 표시 | 이름·설명·유사도 순위·최신 버전 |
| 비표시 | 수치 score·관문 판정 |

이 결정은 `DEC-RANK-20260910-01`의 **상위 2개 기본 선택 조항만** 대체한다. 후보 최대 3개 노출과 나머지 AI 랭커 계약은 유지한다.

## 3. 랭커 계약

- description·keywords 기반 순수 의미 검색
- popularity·Downloads·채택도를 검색·학습·연속 score에 사용하지 않음
- 보완재·노후·실체 미달을 목표 구조적 관문으로 사용
- 관문 통과분을 cos 유사도로 정렬
- cos 동점에서만 dependents를 tie-break로 사용
- deprecated 패키지는 기준·후보에서 완전 제외
- deprecated→대체·migration pair는 학습 positive pair로만 사용
- `move_lift`와 가·감점 계수 튜닝 미사용
- 검색 Recall@N, 전체 Recall@10·MRR을 구분
- 검증된 결과만 현재 `similar_package` 한 벌로 원자 게시하고 manifest로 추적

## 4. 현재 구현과의 차이

| 위치 | 현재 상태 | 처리 |
| --- | --- | --- |
| AI 배치 | `user_visible(rank<=3)` | 최종 후보 노출 수와 일치 |
| AI 배치 | `default_selected(rank<=2)` | 사용자 결정으로 폐기된 출력 의미. UI에서 소비하지 않고 후속 AI 정리 대상 |
| 프런트 | 후보 2개만 표시 | 후보 최대 3개로 수정할 구현 gap |
| 프런트 | 기본 선택 없음 | 최종 계약과 일치 |
| 현재 관문 | plugin/adapter·same-family drop | 구현 상태로만 기록. AI팀 목표 관문의 확정 세부 규칙인지는 별도 검증 |
| 목표 관문 | dependency overlap 보완재·추가 노후·실체 기준 | 미구현·OPEN 유지 |

## 5. 문서 반영 원칙

- 제품 문서에서 `현재 구현된 구조적 관문`만으로 후보 적격성을 설명하지 않는다.
- AI팀 목표 관문과 현재 임시 관문을 분리한다.
- `search_k=30`은 구현 기본값이며 최종 운영값으로 확정하지 않는다.
- API의 기본 `limit=20`·최대 50, 화면 최대 3개, 최종 비교 최대 3개를 서로 다른 값으로 유지한다.
- Figma는 후보 카드 최대 3개 구조는 유지하고 초기 선택 상태만 기준 패키지 단독 선택으로 재동기화한다.

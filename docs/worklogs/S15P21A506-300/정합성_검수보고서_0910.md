## 1. 판정

**초기 0910 세트는 제품 방향을 대체로 반영했지만, 그대로 구현 정본으로 사용하기에는 정정과 후속 계약이 필요했다.** 문서 내부 PDF 차단 조건, Figma의 기준 패키지·날짜, 입력·차트·상태 계약, ERD와 실제 Flyway의 차이가 주요 검수 대상이었다. 최종 판정은 0절과 [최종 문서 검수](최종_문서검수_0910.md)를 따른다.

다음 세 종류를 구분해야 한다.

1. **확정 사항을 잘못 옮긴 부분**: PDF eligibility, Figma 커뮤니티 대상, PDF 기준일 등. 기존 결정을 유지하면서 정정할 수 있다.
2. **확정 기획과 현재 구현의 차이**: selection gate, version 필터, 78주·로그축·관측 공백, 카드별 실패 격리, PDF 등. 코드를 따라 기획을 되돌릴 근거는 아니다. Dependency delta의 첫·마지막 유효 관측 계산은 현행 코드와 일치한다.
3. **구현 가능성을 아직 보장하지 못한 계약**: Version Share 집계 의미, 분석 가능 패키지의 조건, Snapshot 준비 상태, 후보 모델 게시 스키마, 평가셋, PDF 전달 방식 등. 현재 자료로 임의 확정하면 안 된다.

아래 **AUD-001~025**는 문제 또는 확인이 필요한 항목이다. 개수는 결함 수나 작업 티켓 수와 동일하지 않다. `높음`은 결과 의미 오류·핵심 기능 성립에 영향, `중간`은 구현·상태·출처 혼선, `낮음`은 참조·표현 문제다. `확정`은 지정한 자료 사이의 차이를 확인했다는 뜻이며 운영 장애를 재현했다는 뜻이 아니다.

### AUD-010 — ERD export의 외래키 관계가 PostgreSQL 관계 모델로 성립하지 않음

**높음 · ERD/DDL 오류 · 제공 export 기준 확정 · 모델 정정 필요**

`v 0.6.sql`의 다음 관계는 실제 migration과 다르다.

| export 관계 | 문제 | migration의 대응 |
|---|---|---|
| current.dataset → execution.dataset | 대상 dataset만으로 UNIQUE가 아님. 특정 게시 실행을 식별 못 함 | V2: dataset·execution_id·snapshot_at·manifest_sha256 복합 FK |
| pvs.package_id → version.package_id 및 pvs.version → version.version | 복합 PK를 개별 FK로 분해. 대상 열 각각은 UNIQUE가 아님 | V1: `(package_id, version)` 복합 FK |
| execution.execution_id → attempt.execution_id | 대상은 여러 재시도를 가질 수 있어 UNIQUE가 아니며 방향도 실제 모델과 다름 | V2: attempt→execution, execution의 active_attempt는 `(execution_id, active_attempt_id)` 복합 지연 FK |

FK의 참조 대상에는 대응하는 유일성 보장이 필요하다. [PostgreSQL 공식 제약 문서](https://www.postgresql.org/docs/16/ddl-constraints.html)

- 별도로 export에는 backtick 식별자, PostgreSQL 타입과 inline COMMENT 혼용, 인용되지 않은 JSON DEFAULT 및 날짜 DEFAULT가 있다. PostgreSQL migration으로 그대로 실행할 수 있는 파일이 아니다.
- 권장: ERD 관계를 복합키/재시도 카디널리티에 맞춰 수정하고 PostgreSQL용 export를 재생성한다. **이미 적용된 Flyway 파일을 이 export로 덮어쓰지 않는다.** 운영 DB가 이 잘못된 FK를 사용한다는 증거는 없다.

# 01. 작업 정의와 변경 범위

상태: **선행 구현 합류·병합 검증 완료, 통합 적재 구현·데이터 실행 미착수**.
[계획](02-plan.md) · [계약](06-load-contract.md) · [결과](05-results.md)

## 목표

승인된 패키지 목록을 기준으로 다운로드 합계와 stars·open_issues를 연결하고, 검증한
통합 Curated 결과를 PostgreSQL `package_snapshot`에 게시한다. 패키지가 지표를 갖지 못한 경우도
행은 유지하며, 지표별 NULL 사유와 입력·정책·적재 실행을 연결한다.

| 작업 | 포함 범위 |
| --- | --- |
| 선행 구현 합류 | 저장소 지표 커밋 병합, 공통 모듈·문서 경로 확인과 회귀 검증 |
| 승인 입력 고정 | 패키지 모집단, 스냅샷 후보, 다운로드 구간 결과, 저장소 지표의 명시적 run·manifest SHA 검증 |
| 통합 Curated | 전체 모집단에 지표를 LEFT JOIN하고 값·품질·입력 계보를 검증하여 새 실행으로 게시 |
| PostgreSQL 적재 | 실행별 staging, COPY 대량 적재, PK/FK·값 검증, 서비스 행과 실행 이력의 원자적 반영 |
| 재실행·복구 | 동일 입력의 DB 값 재검증, 다른 입력의 실행 ID 재사용 차단, 실패 시 서비스 변경 롤백 |
| 결과 인계 | 실행 명령·직접 확인할 SQL·건수·지표 값·NULL 사유·검증 한계 기록 |

## 데이터와 시간 범위

- 초도 기준일 S는 `2026-08-31`, 원천 시각은 `2026-08-31T21:01:10.517131Z`다.
- 다운로드는 직전 기준일 P=`2026-08-24`부터 S 직전 날짜까지의 합계다. 이미 승인된 부분합을 유지한다.
- 저장소 지표는 S의 정확한 관측 시각에 연결된 결과를 사용한다. 과거·미래 값으로 채우지 않는다.
- 모집단은 `curated-20260907-v2`의 `package/data` 전체다. 선행 기대값은 11,080,940행이며 실행 때 다시 검증한다.
- 키는 `(package_id, snapshot_at)`이다. 새 package ID를 만들거나 다운로드 수집 대상만 남기지 않는다.
- 최신 패키지 목록을 과거 스냅샷에 소급하지 않는다. 과거 기간 실행에는 그 시점의 별도 승인 입력이 필요하다.

## 변경과 보존 경계

신규 구현 위치는 `pipeline/package_snapshot/`를 계획한다. 공통 실행 이력·전송 유틸리티는
재사용 가능성을 확인하되, 기존 package·version 로더를 통합 지표용으로 그대로 호출하지 않는다.

서비스 DDL V1과 기존 migration 파일을 수정하지 않는다. 품질·실행 이력 저장에 스키마 확장이
필요하면 이유와 기존 로더 계약 해시 영향을 먼저 기록하고 신규 migration으로 처리한다.
기존 package·version·snapshot 행, 다른 기준일의 지표, 선행 Curated 완료 객체·증거를 보존한다.

이번 범위에서 원본 API 재수집, 다운로드·저장소 지표 재산출, 버전별 dependents 계산,
`package_version_snapshot` 적재, 자동 스케줄러, 운영 DB 이관, 새 백엔드 API 구현은 하지 않는다.
현재는 선행 구현의 병합·회귀 검증까지 수행했다. 통합 데이터 생성과 PostgreSQL 적재는 아직 실행하지 않았다.

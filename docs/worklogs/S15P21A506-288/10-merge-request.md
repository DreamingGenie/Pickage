## 개요

다운로드 일별 원본 입고·스냅샷 구간 집계와 저장소 stars·open_issues 생성을 연결해 PostgreSQL `package_snapshot`에 적재합니다.
지표가 없는 패키지도 유지하고 부분합·NULL·실제 0 및 입력·정책·실행 이력을 함께 추적합니다.
과거 패키지 원천이 없는 기간은 승인 버전의 배포일로 대상을 재구성하고, 해당 날짜의 실제 관측 지표를 결합합니다.

## 작업 상세 내용

- 다운로드 대상·수집 상태·날짜별 파일을 검증하고 승인 manifest와 완료 표시를 MinIO Bronze에 게시합니다.
- 실제 스냅샷 간격 `[P,S)`으로 다운로드를 집계합니다. 관측 일부가 누락되면 유효 날짜의 부분합을 게시하고, 실제 0·미수집·대상 밖 상태는 품질 정보로 구분합니다.
- 기준일의 대표 저장소를 선택하고 정확한 Projects 관측 시각에 해당하는 stars·open_issues를 생성합니다. 저장소 연결과 지표 누락·충돌 사유를 남깁니다.
- 통합 Curated 파일과 입력·정책·출력 SHA를 검증한 후 COPY·전체 키/값 검사·트랜잭션 게시를 수행합니다. DB 실행 이력에서 품질 파일과 원천까지 추적할 수 있습니다.
- 같은 실행 ID와 입력은 값 재검증으로 처리하고 중복 삽입하지 않습니다. 다른 입력 재사용·기존 값 덮어쓰기를 거부하며, 게시 전 실패와 커밋 후 확인 실패를 구분합니다.
- 과거 기준일에는 배포일이 확인되는 승인 버전으로 대상과 저장소 연결을 재구성합니다. 해당 연결은 과거 관측 목록과 다르며, 최신 목록에서 사라진 패키지와 사후 변경된 저장소 정보는 복원할 수 없습니다. 배포일이 모두 미상인 패키지는 과거 대상에서 제외합니다.
- 기존 `2026-08-31` 관측 기준일과 최신 게시 포인터를 보존합니다. 재부팅 후에는 PUBLISHED 날짜를 제외한 목록을 `--snapshots`로 지정해 미완료 날짜만 재개합니다.
- 작업 범위·계약·조회 SQL·독립 대조 결과·재개 절차를 작업 기록에 정리했습니다. 저장소 지표 코드의 승인 바이트 해시 보존을 위해 해당 Python 파일의 LF 속성을 고정했습니다.

# MR 제목

feat: 패키지별 다운로드·스타·열린 이슈 수 DB 적재 (S15P21A506-288)

---

## 개요

각 패키지의 다운로드 수, 저장소 스타 수, 열린 이슈 수를 기준일별로 모아 PostgreSQL에 저장합니다.
다운로드 원본 저장부터 기간별 합산, 저장소 지표 연결, DB 적재까지 한 흐름으로 연결했습니다.
최신 기준일뿐 아니라 보유한 과거 기준일도 조회할 수 있도록 적재 범위를 확장했습니다.

## 작업 상세 내용

### 패키지와 기준일마다 지표를 한 행에 저장

다운로드 원본 파일을 검사해 MinIO에 보관하고, 기간별 합계와 저장소 지표를 계산해 `package_snapshot` 테이블에 저장합니다.

| 저장 항목 | 의미 |
| --- | --- |
| `package_id` | 어떤 패키지인지 |
| `snapshot_at` | 어느 기준일의 데이터인지 |
| `downloads` | 이전 기준일부터 현재 기준일 전날까지의 다운로드 합계 |
| `stars` | 해당 기준 시각에 관측한 저장소 스타 수 |
| `open_issues` | 해당 기준 시각에 관측한 열린 이슈 수 |

예를 들어 이전 기준일이 8월 24일, 현재 기준일이 8월 31일이면 다운로드는 **8월 24~30일을 합산**합니다. 스타와 열린 이슈 수는 **8월 31일의 관측값**을 사용합니다.

### 데이터가 없는 경우도 구분해서 저장

- 일부 날짜의 다운로드만 있으면 **확인된 날짜의 부분합**을 저장하고 누락된 날짜 수를 별도로 기록합니다.
- 실제 값이 0이면 `0`, 값을 확인할 수 없으면 `NULL`로 저장합니다.
- 다운로드가 없어도 스타와 열린 이슈 수는 저장합니다. 지표가 없다는 이유로 적재 대상 패키지 행을 제거하지 않습니다.
- 값이 없는 이유와 사용한 원본 파일을 적재 이력에서 확인할 수 있도록 연결했습니다.

### 과거 기준일의 데이터도 적재

과거 시점의 패키지 목록은 보유하고 있지 않아, 현재 보유한 버전의 **배포일**을 기준으로 그 시점에 공개돼 있던 패키지와 연결 저장소를 구성했습니다. 스타·열린 이슈·다운로드에는 해당 시점의 실제 관측 데이터를 사용합니다.

이 방식은 당시 패키지 목록을 그대로 복원한 것은 아닙니다. 모든 버전의 배포일이 미상인 패키지는 과거 대상에서 제외하며, 현재 목록에서 사라진 패키지나 이후 바뀐 저장소 정보까지 복원할 수는 없습니다. 이 한계를 결과에 함께 기록했습니다.

### 중복 적재와 중단 후 재실행 처리

- 같은 입력으로 다시 실행해도 행을 중복 삽입하지 않습니다.
- 한 날짜의 데이터와 성공 이력을 함께 확정해, 저장 도중 실패한 날짜를 완료로 표시하지 않습니다.
- 중단된 경우 완료되지 않은 날짜만 선택해 이어서 실행할 수 있습니다.
- 기존 `2026-08-31` 데이터와 최신 기준일 설정은 유지합니다.
- 실행 명령, 직접 조회할 SQL, 검증 결과와 재개 방법을 작업 문서에 정리했습니다.

## 데이터·파이프라인 영향 (해당 시)

- 스키마/테이블 변경 : 기존 테이블을 사용하며 컬럼·제약·마이그레이션 변경은 없습니다. 날짜 조회를 돕는 인덱스만 로컬 검증 DB에 추가했습니다.
- 기존 적재 데이터 재처리(backfill) 필요 여부 : 기존 최신 데이터를 유지하면서 과거 228개 기준일을 추가했습니다. 최종 결과는 229개 기준일, 646,219,939행입니다.
- 외부 API 호출량·키 사용 변화 : 이미 보유한 원본을 사용했습니다. BigQuery 재수집이나 외부 API 추가 수집은 없습니다.
- 배치 주기·실행 시간 변화 : 수동 실행 방식이며 정기 실행은 추가하지 않았습니다. 최신 기준일 약 1,108만 행의 DB 적재·검증은 약 8분 걸렸습니다.

## 구현 결정

1. 사용자 후속 지시에 따라 기준 목록은 선택 Projects의 실제 `SnapshotAt`에서 만든다. 모든 대상 파일의 시각·날짜·행 수를 검사하고 목록을 산출물에 고정한다.
2. 원천 timestamp를 보존하고 UTC 날짜를 파생한다. 순서는 timestamp로 정하며 같은 DATE 충돌은 실패한다.
3. `[P,S)`를 269 v1의 날짜 정책으로 채택한다. 실제 timestamp 사이의 정확한 다운로드 합계라는 표현은 사용하지 않는다.
4. Projects는 정확한 관측 시각만 허용한다. 이전 관측치 자동 대체는 v1에서 지원하지 않는다.
5. 과거 package/version 모집단은 동일 snapshot의 승인 원천이 있어야 한다. 최신 목록만으로 과거 전체를 복원했다고 선언하지 않는다.
6. 로컬 생성 상태는 DB 게시 상태와 분리한다. 명시적 날짜 INSERT는 새 격리 검증 DB에서 적재·재시도·rollback을 확인한다. 서비스 DB 연동 전에 정책 해시·입력 계보·공개 조건을 267과 맞춘다.
7. 새 의존성을 추가하지 않는다. 작은 메타데이터 조회만 허용하며 대량 Parquet 스캔·지표 API 재수집은 수행하지 않는다. 최초 병행 범위에서는 267 DB 쓰기를 제외했고, 후속 승인 P-06에서는 snapshot 날짜 INSERT만 수행했다.

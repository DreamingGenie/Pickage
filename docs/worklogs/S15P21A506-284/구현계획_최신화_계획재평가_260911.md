# GitHub 커뮤니티 구현계획 최신화 계획 재평가

작성일: 2026-09-11
평가 대상: `구현계획_최신화_정밀계획_260911.md`

## 평가 결론

초안 계획은 제품, DB, backend, frontend, infra, 보안, 시험을 모두 다루지만 그대로 실행하면
세 가지 위험이 있었다. 아래 보정을 반영한 계획을 최종 실행 계획으로 승인한다.

## 발견한 누락·과잉과 보정

| 구분 | 초안 위험 | 보정 |
|---|---|---|
| 사실/목표 혼용 | 완료 Jira와 과거 MR 상태를 구현 사실로 오인할 수 있음 | 파일 존재와 실행 코드를 구현 증거로 제한하고 Jira 상태는 작업 추적 정보로만 사용 |
| persistence 관례 | 기존 문서의 JPA Entity 지시가 현재 JdbcTemplate 코드와 충돌 | community도 JdbcTemplate + typed record + 명시적 SQL을 기본으로 확정 |
| seed 범위 | 데이터 입력 시드 3개만 보면 `seed_reset`이 FK 오류를 냄 | package를 TRUNCATE하는 4개 파일을 수정하고 `seed_clear_snapshots`는 제외 |
| migration 번호 | V5를 영구 상수처럼 쓰면 병렬 작업과 충돌 | 현재 기준 V5로 쓰되 실제 구현 브랜치 생성 직후 다시 검사하는 gate 추가 |
| 상태 모델 | `FETCH_LIMITED`가 DB 상태와 refresh 오류에 중복 등장 | persistent data, refresh execution, view, transient error namespace를 분리 |
| HTTP 상태 | 기존 wrapper 반환형만으로 POST 202를 표현할 수 없음 | POST는 ResponseEntity로 status를 명시하고 body wrapper는 유지 |
| 동시성 | refresh pool 안에서 GMS 병렬 task를 같은 pool에 제출하면 교착 가능 | refresh executor와 GMS executor를 분리하고 둘 다 bounded로 제한 |
| 기준 패키지 | `packages[0]`은 현재는 맞지만 계약이 타입에 드러나지 않음 | route state에 basePackage를 별도 필드로 추가하고 첫 항목 fallback은 이전 상태 호환에만 제한 |
| 요청 취소 | 현재 client timeout과 React Query signal이 결합되지 않음 | caller signal과 timeout을 결합하는 request option을 설계 항목에 추가 |
| 기존 결함 | 후보 2개·setError 결함을 community 작업에서 무단 수정할 위험 | 선행 결함으로 명시하고 별도 이슈 범위를 유지 |
| 일정 | 09-20 목표가 현행 확정 일정처럼 보임 | 보관 일정으로만 표시하고 Jira/팀 재확정 전 새 날짜를 만들지 않음 |
| 검증 자동화 | 저장소에 CI가 없는데 CI 통과를 완료 조건으로 쓸 수 있음 | 로컬 명령 결과와 MR 증거 기록을 완료 조건으로 전환 |

## 최종 실행 순서

1. 머리말·현황·근거를 2026-09-11 기준으로 교체한다.
2. 제품 불변 계약을 먼저 고정한다.
3. 수집·요약·저장 schema와 상태 namespace를 하나의 종단 계약으로 다시 쓴다.
4. 현재 JDBC/Spring MVC/React Query 코드에 맞춘 실제 파일 단위 작업 목록으로 바꾼다.
5. migration·4개 초기화 파일·local/prod secret 연결을 보강한다.
6. 단계별 시험과 구현 착수 gate를 추가한다.
7. 과거 변경 이력은 짧은 provenance만 남기고 실행을 방해하는 상충 상세는 제거한다.
8. 정적 검사 후 업그레이드 커밋을 만든다.
9. 독립 재검수에서 계약·사실·실행 가능성·추적성을 다시 확인하고 필요한 수정만 별도 커밋한다.

## 승인 기준

- 새 기능을 구현하지 않고 문서만 변경한다.
- 미확정 GMS schema/URL 값이나 운영 secret 값을 만들어내지 않는다.
- 현재 코드 결함은 숨기지 않되 이 문서 변경으로 코드까지 고치지 않는다.
- 본문만 읽어도 구현 순서와 중단 조건을 판단할 수 있게 한다.

위 보정을 정밀 계획의 해석 규칙으로 추가하고 최신화를 진행한다.

# 수집 완료 후 실행 절차 (S15P21A506-452)

registry 추가분 36.9만 수집이 끝난 뒤 `package_env` 를 46.9만으로 넓히기까지의 순서다.
**운영 MinIO·운영 PG 에 닿는 명령은 세션 하네스가 막으므로 전진님 터미널에서 실행한다.**
세션은 여기까지 준비하고, 결과를 받아 검증·보고한다.

명령은 PowerShell 기준이고 작업 트리는 `C:\git\S15P21A506-452` 다.
운영 PG 적재 순번은 U3 → U4 → U2 → U1(이 작업)이므로 **마지막이다.** 타워가 차례를 알린다.

## 0. 전제 — 수집이 정말 끝났는지 본다

```powershell
cd C:\git\S15P21A506-452
.\.venv-bq\Scripts\python.exe pipeline\collectors\registry\status.py --run 2026-09-22-additions --shards 4
```

`남은 0`, `실패 0`, 네 샤드 모두 `DONE` 이어야 한다. **실패가 남아 있으면 먼저 재시도한다.**

```powershell
.\.venv-bq\Scripts\python.exe pipeline\collectors\registry\collect.py --targets "data\registry\targets\expanded_468k_additions_20260922-s1of4.csv" --run 2026-09-22-additions-s1 --out data\registry\raw --retry-failed
```

NOT_FOUND 와 UNPUBLISHED 는 실패가 아니다. 그대로 두고 수를 보고한다. **0 으로 채우지 않는다.**

## 1. Bronze 입고 — 원본을 서버 MinIO 에 올린다

원본 문서를 보존하지 않는 설계라, 이 단계를 건너뛰면 판정 규칙을 고쳐야 할 때 전량 재수집밖에 없다.

### 1-1. 터널을 연다 (창 하나를 붙잡는다)

```powershell
ssh -i ~/.ssh/J15A506T.pem -N -L 19000:localhost:9000 ubuntu@j15a506a.p.ssafy.io
```

`19000` 은 내 PC 의 포트다. 로컬 MinIO(9000)와 겹치지 않게 갈라 둔 것이고, 응답이 있으면
터널이 열린 것이다. 자세한 이유는 `pipeline/minio/README.md` 의 "터널" 절에 있다.

### 1-2. 먼저 dry-run 으로 본다

```powershell
cd C:\git\S15P21A506-452
$env:PICKAGE_MINIO_ENV=".env.server"
.\.venv-bq\Scripts\python.exe -m pipeline.minio.ingest_collector_raw --source registry --run 2026-09-22 --dry-run
```

**`--run` 에 주는 값은 `2026-09-22` 다.** 폴더 이름은 `run=2026-09-22-additions-s1` 이지만
입고기는 앞의 날짜로 묶는다(e1fad8a 에서 라벨을 허용했다). `shards=4` 와 `pending=0` 을 확인한다.
`No collector runs selected` 가 나오면 그 수정이 빠진 것이다.

### 1-3. 올린다

```powershell
.\.venv-bq\Scripts\python.exe -m pipeline.minio.ingest_collector_raw --source registry --run 2026-09-22 --run-id registry-20260922-additions-v1
```

객체마다 GET 해서 sha256 을 다시 잰다. 시간이 걸린다(09-16 회차 988 MB 기준 수십 분).
끝나면 `_SUCCESS` 와 `run_manifest.json` 이 찍힌다.

## 2. package_env 빌드 — 두 회차를 한 표로

`--collected-date` 와 `--run-id` 를 **두 번씩** 적는다. 앞에서부터 짝지어진다.

```powershell
.\.venv-bq\Scripts\python.exe -m pipeline.duckdb.build_package_env --collected-date 2026-09-16 --run-id registry-20260916-v1 --collected-date 2026-09-22 --run-id registry-20260922-additions-v1 --memory 6GB
```

MinIO 에서 두 회차를 받아(`data/registry/raw/collected_date=.../`) 검증한 뒤 판정한다.
`_SUCCESS` 확인, part 별 sha256, 샤드 1..N 결번 검사, gz 온전성 검사를 거친다.
출력은 `data/package_env/package_env.parquet` 이다.

**로컬 raw 로 빨리 돌리고 싶으면** 아래처럼 `--raw` 에 폴더 여덟 개를 준다. 다만 완료 확인과
sha256 검증을 건너뛰므로 **정식 산출물로 쓰지 않는다.** 미리 수치를 보고 싶을 때만 쓴다.

```powershell
.\.venv-bq\Scripts\python.exe -m pipeline.duckdb.build_package_env --raw "data\registry\raw\run=2026-09-16-s1" "data\registry\raw\run=2026-09-16-s2" "data\registry\raw\run=2026-09-16-s3" "data\registry\raw\run=2026-09-16-s4" "data\registry\raw\run=2026-09-22-additions-s1" "data\registry\raw\run=2026-09-22-additions-s2" "data\registry\raw\run=2026-09-22-additions-s3" "data\registry\raw\run=2026-09-22-additions-s4" --out data\package_env\package_env_preview.parquet --memory 6GB
```

### 여기서 볼 것

- **행 수.** 09-16 회차가 21,567,150행이었다. 추가분은 수집 중 관측으로 2,500만~3,150만 행
  범위를 본다. 합계가 4,600만~5,300만 행이면 예상대로다.
- **`(Name, Version)` 겹침.** 회차가 둘이므로 빌더가 검사한다. 걸리면 멈추고 보고한다.
  상위 10만과 추가분은 이름이 겹치지 않아야 정상이다(99,996 + 368,523 = 468,519).
- **`module_format` 분포.** 09-16 전수는 CJS 59.8% · ESM_CJS 21.0% · ESM_ONLY 15.3% ·
  UNKNOWN 3.9% 였다. 추가분이 섞이면 옮겨 가겠지만 UNKNOWN 이 크게 늘면 의심한다 —
  unpublish 비율이 그만큼 높다는 뜻이다.

## 4. 운영 PG 적재 — **타워 확인 후**

### 4-1. 먼저 verify-only (넣어 보고 되돌린다)

```powershell
$env:PICKAGE_MINIO_ENV=".env.server"
.\.venv-bq\Scripts\python.exe -m pipeline.package_env.load --collected-date 2026-09-22 --run-id package-env-20260922-v1 --psql psql --database pickage --verify-only
```

운영 PG 접속 방법(`--psql` 경로·libpq 환경변수)은 U3·U4 가 쓰는 것과 같게 맞춘다.
로컬로 먼저 보려면 `--docker-container pickage-local-postgres-1 --database pickage` 를 쓴다.

**볼 것**

| 지표 | 기대 |
|---|---|
| `staged_rows` | 2단계 빌드의 행 수와 같아야 한다 |
| `loaded_rows` | 09-16 분 약 782만 + 추가분 1,700만~2,140만 = **2,480만~2,920만** |
| 커버리지 | 100.0% (`version` 이 제공하는 버전 기준) |
| `unknown_name_rows` | 추가분에서 이름이 없는 6,487개 몫이 여기 들어온다 |

`loaded_rows` 가 1,810만 근처면 **예상과 다르다.** 이슈 본문의 옛 추정치이고, 추가분 매칭률을
상위 10만과 같은 36%로 잡은 값이다. 실측은 68.1%(전체 보정 약 67%)다.

### 4-2. 게시

`--verify-only` 를 빼고 같은 명령을 돌린다. 전량 교체(DELETE + INSERT)라 되돌리려면 이전 회차로
다시 적재해야 한다. **타워가 순번을 알린 뒤에만 실행한다.**

## 함정

- **기존 run 폴더에 쓰거나 이름을 바꾸지 않는다.** 원본을 보존하지 않는 설계라 덮어쓰면 복구 불가다.
- **`to_parquet.py` 는 이 흐름에 필수가 아니다.** `build_package_env.py` 가 raw 를 직접 읽는다.
  DuckDB UI 의 `registry_versions` 뷰를 최신화하고 싶을 때만 따로 돌린다. 그때 `--raw` 에 여덟
  폴더를 다 주고, 출력 폴더는 `--force` 로 덮지 말고 새로 잡는다(완성된 09-16 결과가 지워진다).
- **로컬 MinIO 와 서버 MinIO 를 헷갈리지 않는다.** `PICKAGE_MINIO_ENV=".env.server"` 를 준
  창에서만 서버로 간다. 터널이 닫혀 있으면 연결이 거부되지, 조용히 로컬로 가지 않는다.

## 1. 전체 흐름

이건 이어달리기입니다. 바통을 넘기는 지점이 전부 **MinIO 의 파일**이라, 각 구간이 서로를 직접 호출하지 않습니다.

```
[jupyter05 GPU]  학습 → LoRA → ONNX
        │          SSH 터널로 9000·5000 에 붙는다
        │  ① 모델 업로드 + @production 등록
        ▼
[data 노드]  MinIO(창고) · MLflow(장부)
             유사도 배치: ai-stage → ai-similarity → ai-collect
        │  ② 산출물 + manifest
        ▼
[app 노드]   ③ 로더 → PostgreSQL similar_package → Spring 이 SELECT
                                                   ← 로더는 아직 없음
```

### 가장 먼저 이해할 것

**사용자 요청 경로에 모델이 없습니다.** 검색하면 모델이 도는 게 아니라 미리 계산해 둔 표를
SQL 한 번으로 읽습니다. 마이그레이션 `V4` 주석이 그걸 못 박습니다 —
*"요청 경로에 모델이 없다는 것이 이 테이블의 존재 이유다."*

그래서 `data` 노드가 통째로 죽어도 서비스는 응답합니다. 결과가 낡아질 뿐입니다.

## 2. MLflow — 창고와 장부

| 포트 | 무엇 | 아는 것 |
| --- | --- | --- |
| 9000 | MinIO | "`model.onnx` 라는 132 MiB 덩어리가 이 경로에 있다" |
| 5000 | MLflow | "그게 `pickage-similarity` 의 3번 버전이고 지금 `@production` 이다" |

경로 하나에 계속 덮어쓰면 **롤백이 안 되고**, 어느 학습에서 나왔는지도 안 남고,
**배치가 읽는 중에 덮어쓰면 반쯤 쓰인 파일을 읽습니다.** MLflow 는 파일을 절대 덮어쓰지 않고
이름표만 옮깁니다 — 승격도 롤백도 *별칭 이동 한 번*이고 파일은 아무것도 안 움직입니다.

### 고른 것들

**backend store 는 sqlite** (확인함)

`s3://` 는 backend store 로 **쓸 수 없습니다** — 지원 스킴이
`['', 'file', 'postgresql', 'mysql', 'sqlite', 'mssql']` 입니다. PostgreSQL 은 `app` 노드의
5432 를 열어야 해서 제외했고, 남은 `file` 과 sqlite 중 **백업이 파일 하나로 끝나는 쪽**을
골랐습니다. 강한 근거는 아닙니다.

**아티팩트는 서버를 거치지 않는다** (확인함)

`--no-serve-artifacts`. 서버가 중계하려면 boto3 가 필요한데 **공식 이미지에 없습니다.**
커스텀 이미지를 유지하는 대신, 어차피 MinIO 자격증명을 가진 클라이언트(GPU)가 직접 올립니다.
그래서 GPU 는 터널이 둘 필요합니다.

**포트는 루프백만**

GPU 는 `run_pipeline.sh` 가 여는 SSH 터널로 붙고, 같은 노드의 배치는 compose 네트워크 이름으로
붙습니다. **"이 노드에 외부로 열린 포트가 없다" 가 유지됩니다.**

### ⚠ `mlflow.db` 는 모델 파일보다 잃기 나쁘다

258 KB 짜리 sqlite 파일 하나인데, **"무엇이 `@production` 인가" 를 아는 유일한 곳**입니다.
잃으면 모델 파일은 MinIO 에 그대로 남는데 **어느 게 운영인지 모르게 됩니다.**

`cp` 나 `shutil.copy` 로 뜨면 안 됩니다 — `journal_mode=delete` 라 쓰는 중에는 일관된 상태가
`mlflow.db` 와 `mlflow.db-journal` 에 나뉩니다. `Connection.backup()` 을 쓰고, 절차는
`deploy/prod/data/README.md` 에 있습니다.

## 3. 배치 — 왜 컨테이너가 셋인가

구현된 잡이 **S3 를 못 읽기** 때문입니다. `requirements.txt` 가 numpy · onnxruntime ·
pyarrow · transformers 뿐이고 입출력이 전부 로컬 경로입니다.

| 서비스 | 이미지 | 하는 일 |
| --- | --- | --- |
| `ai-stage` | minio (mc) | MinIO → `/work/in`, uid 1000 으로 `chown` |
| `ai-similarity` | 자체 빌드 | 재임베딩 → 검색 → 관문 → 정렬 → `/work/out` |
| `ai-collect` | minio (mc) | `/work/out` → MinIO, `_SUCCESS` 게시 |

셋 다 **상주가 아닙니다.** `profiles` 로 묶여 `up -d` 에 안 뜨고 `run --rm` 으로 한 번 돌고
끝납니다 — `minio-init` 과 같은 성격입니다. 잡이 언젠가 `s3://` 를 직접 다루게 되면 앞뒤 둘은
통째로 사라집니다.

> **세션 중 되돌린 설계** — 앞뒤 두 단계를 처음엔 `docker run` 으로 뺐다가 서비스로
> 되돌렸습니다. compose 가 공짜로 주는 **네트워크 이름 · 볼륨 이름 · `env_file`** 셋을 손으로
> 다시 대야 했고, **거기서 자격증명을 빠뜨려 `mc` 가 빈 값으로 붙었습니다.**

> **메모리** — 배치가 도는 시각이 이 노드가 **가장 빠듯한 시각**입니다. Spark 셋이 12 g 를 잡은
> 위에 2 g 가 얹혀 **합계 14 g / 15 GiB** 입니다. 상한을 올리려면 worker① 의
> `SPARK_WORKER_MEMORY` 를 먼저 내려야 합니다 — 상한만 올리면 커널이 아무거나 하나 죽입니다.

## 4. 자동화 — 포인터 둘이 정한다

`run-similarity-batch.sh` 는 **인자를 받지 않습니다.** 그래서 `.env` 에 날짜도 모델 버전도 없습니다.

| 무엇을 | 어디에 묻나 | 누가 갱신하나 |
| --- | --- | --- |
| 코퍼스 | `$AI_CORPUS_PREFIX/_current.json` | 데이터 파트가 올릴 때 |
| 모델 | MLflow `pickage-similarity@production` | AI 가 승격할 때 |

### 확정한 값을 산출물 경로에 박는다

```
pickage-vectors/model=v7/corpus=collected_date=2026-09-08/run_id=…
```

이게 재현성을 지킵니다. `pipeline/curated/README.md` 가 `_current.json` 자동 추종을 경계한 것은
**재현성** 때문인데, 그건 *누가 타이핑하느냐*가 아니라 *무엇을 썼는지 남느냐*의 문제였습니다.
**확정하고 기록하면** 둘 다 만족합니다.

그 경로의 `_SUCCESS` 가 **"이미 했다" 의 근거**입니다. 둘 다 그대로면 아무것도 하지 않고 `0` 으로
끝나서, 타이머를 촘촘히 걸어도 헛돌지 않습니다. 별도 상태 저장소가 없습니다.

> **해석은 컨테이너가 아니라 스크립트에서** — mc 를 담은 MinIO 이미지에는 `sed` · `grep` ·
> `jq` · python 이 **없습니다**(`curl` 만 있음). 그래서 호스트가 포인터를 읽어 확정하고,
> 컨테이너에는 `-e` 로 확정된 경로만 넘깁니다. MLflow 도 `127.0.0.1:5000` 이라 호스트가 바로
> 부릅니다. 덕분에 **compose 파일에 날짜도 버전도 없습니다.**

## 5. 실제로 돌려서 확인한 것

문서에 적은 게 아니라 로컬 compose 로 띄워 본 결과입니다.

| 무엇 | 결과 |
| --- | --- |
| MLflow 기동 | `Up (healthy)` · 347 MiB / 512 m. 첫 기동은 alembic 때문에 30초 |
| 레지스트리 왕복 | 등록 → v1 READY → `@production` → 되찾기 |
| 아티팩트 업로드 | MinIO 에 실물 확인. path-style 을 따로 켤 필요 없음 |
| 백업 · 복구 | DB 삭제 → 복원 → `@production` 생존 (별칭까지 원본과 동일) |
| **모델 승격 감지** | `@production` → v2 · `.env` 무수정 → 다음 실행이 v2 로 |
| **코퍼스 갱신 감지** | `_current.json` 갱신 → 새 run 을 집음 |
| **멱등** | `이미 처리됨` · exit 0 |
| GPU 정책 | 50 MB 멀티파트 OK · 원본 쓰기·삭제 전 버킷 차단 |

### 세션 중 고친 오류 셋

1. **"읽는다" → "적재한다"** — 배치가 PostgreSQL 을 읽는 줄 알고 5432 를 열었는데,
   설계 문서를 보니 쓰기였고 애초에 배치가 아니라 로더의 일이었습니다.
2. **`docker run` 자격증명 누락** — 한 번도 안 돌려본 형태를 문서에 적었습니다.
3. **`shutil.copy` 백업** — 쓰는 중에 찢어질 수 있는 방식이었습니다.

②·③ 은 리뷰 질문에서 나왔습니다. *"왜 하나만 컴포즈냐"*, *"sqlite 는 어떻게 관리하냐"*.

## 6. 파트별로 필요한 것

아래 넷이 갖춰지면 배치가 **손댈 것 없이** 돌기 시작합니다.

### 데이터 — `package_text` 를 서버 MinIO 에 올려주세요

이미 만들어 두셨습니다 — `package_text_2026-09-08.parquet`, **92만 행 / 86 MB**.
다만 `build_package_text.py` 에 업로드가 없어 **로컬에만** 있습니다. 재료(keywords 원본 ·
deps.dev)는 둘 다 서버에 있으니 **서버에서 한 번 돌려 바로 올리는 쪽**이 재현 가능합니다.

- 경로: `pickage-curated/ecosystems-keywords/v1/package-text/collected_date=…/run_id=…/data/package_text.parquet`
- **파일명에서 날짜를 빼주세요.** 경로에 `collected_date` 가 이미 있고, 그래야 배치 명령이
  회차마다 안 달라집니다
- **`_current.json` 을 같이 게시해 주세요** — 이게 자동화 트리거입니다. `depsdev` 의 것과 같은 형식으로

### AI — MLflow 에 모델을 등록해 주세요

MLflow 는 **서버에 떠 있습니다.** `run_pipeline.sh --register-only` 로 등록하시면 됩니다.
GPU 계정에 **모델 업로드 권한을 추가했고 키는 그대로**라 다시 받으실 필요 없습니다.

- 등록 이름 `pickage-similarity` · 별칭 `production` — 배치가 이 이름으로 묻습니다
- **등록만 하면 승격이 곧 배포입니다.** `@production` 을 옮기면 인프라가 아무것도 안 해도
  다음 배치가 새 모델로 돕니다
- 확인 요청: `MODEL_CONTRACT.md` 는 `model.onnx` + `model.onnx.data` 두 파일이라는데
  서버엔 **132 MiB 한 파일**뿐입니다. 단일 파일 export 가 맞으면 계약 문서를 고쳐야 합니다

### 데이터 + AI — 로더 (이게 없으면 사용자에게 안 닿습니다)

배치가 아무리 자동으로 돌아도 결과가 `pickage-vectors` 에 쌓이기만 하고 서비스가 읽는
`similar_package` 는 계속 비어 있습니다. **가장 리드타임이 긴 일입니다.**

- **`app` 노드에서 돌립니다.** 그래야 5432 를 안 엽니다 — 근거는 `deploy/prod/README.md`
- `pipeline/postgresql/load.py` 의 `--docker-container` 패턴을 재사용하면 됩니다
- **⚠ 테이블 이름이 문서와 다릅니다.** `ai/README.md` 는 `similar_packages`(복수)인데
  실제 스키마와 백엔드 쿼리는 **`similar_package`(단수)** 입니다
- **⚠ `model_production` 테이블이 스키마에 없습니다.** 문서가 말하는 "포인터 전환" 대상이
  없어서, 필요한지부터 정해야 합니다

### 백엔드 — 당분간 빈 목록이 정상입니다

`GET /api/packages/similar` 는 코드가 완성돼 있는데 테이블이 비어 있어 계속 빈 목록을
돌려줍니다. `getSimilar` 가 **"이름이 없다" 와 "후보가 아직 없다" 를 구분**해 둔 건 잘 돼
있습니다 — 지금은 모든 패키지가 후자입니다. 프런트에서 그 상태를 어떻게 보여줄지 미리
정해두면 좋겠습니다.

## 7. 일부러 안 만든 것

**스케줄러** — 지금 걸면 **매 발화마다 1·2 단계에서 실패합니다.** 트리거(`_current.json`)와
등록된 모델이 먼저 있어야 합니다. 붙일 때는 **cron 보다 systemd timer** 를 권합니다 — cron 의
기본 실패 모드가 침묵인데, 이 리포는 *이미 그걸로 한 번 데었습니다.* 스크립트가 인자를 안 받고
멱등하므로 timer 는 그 파일을 부르기만 하면 됩니다.

**로더** — `app` 노드에 둔다는 **근거만 문서화**했습니다. 코드는 없습니다.

**배치 로직** — `similarity_batch_pipeline.py` 는 건드리지 않았습니다. 채점 게이트(5단계)가
아직 TODO 입니다 — `S15P21A506-169`.

### 리뷰에서 봐 주셨으면 하는 것

| 항목 | 왜 묻는지 |
| --- | --- |
| sqlite backend | `file` 도 동작하는 걸 확인했습니다. 백업 편의만 보고 골랐으니 이견 있으면 `--backend-store-uri` 한 줄입니다 |
| 아티팩트 직접 업로드 | 자격증명이 클라이언트마다 필요한 대신 커스텀 이미지를 유지하지 않아도 됩니다 |
| 스케줄러 순서 | 잡이 `s3://` 를 다루게 된 **다음**에 거는 것이 맞다고 봤습니다 |
| 로더를 `app` 에 | 문서에 근거만 있고 코드는 없습니다 |
| `pipeline/minio/` 수정 | 데이터 파트 폴더인데 정책·문서 2개를 건드렸습니다. 분리를 원하시면 빼겠습니다 |

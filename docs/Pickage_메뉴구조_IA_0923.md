# Pickage 메뉴구조·IA — 2026-09-23 완성 기준

> 구현 기준: `origin/develop` `c88e20a`
> 이 문서는 현재 라우트, 화면 계층, URL 상태, 사용자 이동 계약을 정의한다.

## 1. 전체 구조

```text
Pickage
├─ /                              서비스 소개·기준 패키지 검색
├─ /analyze                       비교 대상 구성
│  ├─ 기준 패키지
│  ├─ 유사 후보 최대 3개
│  ├─ 직접 추가 검색
│  └─ 분석 가능 여부 확인
├─ /analyze/candidates            /analyze로 리다이렉트
└─ /report/:reportId              분석 보고서
   ├─ 생태계 변화
   │  ├─ 패키지 개요
   │  ├─ Downloads
   │  ├─ Dependents
   │  ├─ Version share
   │  ├─ 의존 전환
   │  ├─ 제거 이유
   │  └─ 관측된 이동 경로
   ├─ 기능 비교
   │  ├─ 버전 선택
   │  ├─ 실행 환경
   │  └─ 공통점·차이·강조
   ├─ GitHub 커뮤니티
   │  ├─ 활동
   │  ├─ 반응
   │  ├─ 기여
   │  └─ 유지보수·데이터 상태
   └─ 출력
      ├─ PDF
      └─ HAND-OFF Markdown
```

전역 메뉴를 여러 단계로 늘리지 않고 분석 과업의 진행 순서가 화면 이동을 결정한다. 알 수 없는 경로는
소개 화면으로 복귀한다.

## 2. URL 상태 계약

### 2.1 분석 화면

| 항목 | 쿼리 | 예시 | 규칙 |
| --- | --- | --- | --- |
| 기준 패키지 | `base` | `base=react` | 1개, 필수 |
| 비교 선택 | `with` | `with=preact,vue` | 쉼표 구분, 총 3개 한도 |
| 후보 생략 | `nosimilar` | `nosimilar=1` | 유사 후보 없이 직접 구성 |

쿼리와 내부 선택 상태는 back/forward 이동을 고려해 동기화한다. 동일 이름은 중복 추가하지 않는다.
잘못되거나 제공할 수 없는 이름은 선택에서 제외하고 사용자에게 이유를 보여 준다.

### 2.2 보고서 화면

| 항목 | 위치 | 규칙 |
| --- | --- | --- |
| 보고서 식별자 | `/report/:reportId` | 현재 UI는 `draft` 사용 |
| 비교 이름 | `names` | 첫 이름이 기준, 최대 3개 |
| 활성 탭 | 화면 상태 | 탭 이동으로 패키지 목록을 잃지 않음 |

`reportId`는 현재 영구 저장된 서버 리소스 ID가 아니다. 링크 공유는 `names` 복원 범위에서만
설명해야 한다.

## 3. `/` 서비스 소개

### 3.1 정보 우선순위

1. Pickage가 npm 패키지 비교 근거를 제공한다는 한 문장
2. 기준 패키지 검색
3. 생태계·기능·커뮤니티 세 분석 관점
4. 추천이나 자동 결론이 아니라는 주의
5. 분석 시작 행동

### 3.2 상태

- 초기: 검색 안내와 서비스 설명
- 입력 중: 자동완성 후보
- 결과 없음: 철자 확인과 다른 검색 제안
- 오류: 재시도 가능한 오류 메시지
- 선택 완료: 분석 화면으로 이동

## 4. `/analyze` 비교 대상 구성

### 4.1 상단 맥락

- 선택한 기준 패키지
- 현재 비교 개수와 최대 3개 제한
- 처음으로 돌아가기 또는 기준 패키지 변경

### 4.2 유사 후보 영역

- 최대 3개 후보 카드
- 패키지명, 설명, 유사도 등 제공 가능한 요약
- 개별 선택·해제
- 최초 자동 선택 없음
- 로딩, 빈 상태, 실패를 분리

후보를 불러오지 않거나 후보가 없어도 직접 추가 영역과 보고서 진입 경로를 유지한다.

### 4.3 직접 추가 영역

- 이름 검색
- 제공 가능 여부 확인
- 이미 선택됨, 기준 패키지와 같음, 최대 개수 초과를 구분
- 성공 시 선택 목록과 URL 동시 갱신

빠른 연속 조작에서 URL 상태가 사라질 수 있는 알려진 버그 `S15P21A506-472`가 있어 후속 수정
전까지는 선택 결과 검증 메시지가 중요하다.

### 4.4 다음 단계

`분석 보고서 보기`를 누르면 선택한 모든 패키지의 overview를 확인한다.

- 전부 유효: `/report/draft?names=...`로 이동
- 일부 실패: 실패 이름과 이유를 표시하고 현재 선택 화면 유지
- 비교 대상이 기준 하나뿐이어도 단일 분석으로 진행 가능

## 5. `/report/:reportId` 공통 구조

### 5.1 헤더

- Pickage와 분석 보고서 제목
- 비교 패키지 칩, 첫 번째 항목에 기준 표시
- 비교 대상 변경
- 새 분석
- PDF
- HAND-OFF

### 5.2 탭

탭 순서는 `생태계 변화 → 기능 비교 → GitHub 커뮤니티`다. 각 탭은 최초 방문 시 lazy load하며,
방문한 탭은 숨겨도 mount 상태를 유지한다. 커뮤니티 polling 같은 활성 작업은 현재 탭 여부를 받는다.

### 5.3 공통 상태 표현

- skeleton: 첫 자료 로드
- partial: 일부 패키지 또는 지표만 있음
- empty: 정상 응답이나 자료 없음
- error: 요청 실패와 재시도
- stale/refreshing: 마지막 자료를 보여 주면서 갱신 중

한 탭의 실패가 다른 탭을 제거하지 않는다.

## 6. 생태계 변화 탭

### 6.1 섹션 순서

1. 패키지 개요
2. 다운로드 추이
3. 의존 패키지 추이
4. 버전 점유율
5. 의존 전환
6. 제거 이유
7. 관측된 이동 경로

### 6.2 조작

- 기간 또는 표시 모드 변경
- 선형·로그 등 제공 모드 변경
- 패키지별 visibility 제어
- 전환 기간 1년·3년·5년
- 관계 종류 regular·peer·optional
- 이동 경로의 상위·기타와 기준 설명 열기

### 6.3 해석 보조

- Downloads와 Dependents의 서로 다른 단위
- Dependents 버전 합계의 중복 가능성
- `미관측 ≠ 유지`
- 제거 이유 단위는 전환 이벤트
- 이동 경로는 동시 변경이며 대체 추천이 아님
- 빗금·기타 영역은 필터 아래 또는 집계에서 접힌 몫

## 7. 기능 비교 탭

### 7.1 비교 전

- 패키지별 버전 후보
- 기본 또는 현재 버전 선택
- 실행 환경 표
- 비교 시작 버튼

### 7.2 실행 중

- 요청 접수와 처리 상태
- 같은 선택으로 중복 실행하는 행동 제어
- 탭 이동 뒤에도 현재 실행 상태 유지

### 7.3 완료

1. 데이터 상태와 소스 제한
2. 공통점 설명
3. 패키지별 차이
4. 핵심 용어·핵심 문장 강조

현재 IA에는 Evidence Drawer, 원문 인용 패널, verdict·점수표가 없다. 기능 비교 결과가 있는 경우에만

### 8.2 정보 구조

## 9. PDF 흐름

1. PDF 버튼
2. 포함 섹션 선택
   - 생태계: 필수
   - 커뮤니티: 선택
   - 기능 비교: 현재 완료 결과가 있을 때 선택
3. 생성 요청과 진행 표시

현재 UI의 생성 요청은 사용자가 완료까지 기다리는 흐름이며 영구 작업함은 없다.

## 10. HAND-OFF 흐름

HAND-OFF 버튼은 별도 편집 모달 없이 Markdown 생성을 요청하고 파일을 내려받는다. 생태계와 가능한
커뮤니티 정보를 포함하며 현재 세션의 완료된 기능 비교가 있으면 함께 전달한다. 다른 에이전트가
출처·기준·결측을 오해하지 않도록 제한 문구를 유지한다.

## 11. 반응형·접근성 원칙

- 좁은 화면에서는 비교 카드를 세로로 쌓고 표는 스크롤 가능하게 한다.
- 색만으로 증감·성공·실패·선택을 구분하지 않는다.
- 탭, 모달, 드롭다운, 차트 보조 설명에 키보드 접근을 제공한다.
- 로딩과 갱신 상태는 화면 읽기 도구가 인지할 텍스트를 가진다.
- 데이터가 많은 차트에도 같은 내용을 이해할 수 있는 숫자·설명을 둔다.

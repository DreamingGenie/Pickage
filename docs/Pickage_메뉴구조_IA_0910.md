## 1. IA 적용 원칙

0. 모든 화면은 데스크톱 컴퓨터의 웹 브라우저를 기준 화면으로 설계한다.

1. 사용자는 입력 단계에서 패키지명을 입력하고 접두사 자동완성 결과 중 DB에서 다음 단계 분석이 가능한 패키지를 직접 선택한다. 임의 입력 문자열만으로 다음 단계에 진입하지 않는다.
2. 기준 패키지는 고정 선택하고 후보 ranking 상위 2개는 기본 선택하되 사용자가 변경할 수 있다.
3. 비교 대상은 기준 패키지를 포함해 총 3개로 제한한다.
4. 후보 카드는 내부 ranking score·계수를 품질 점수처럼 보여주지 않는다. 사용자는 관련성 근거와 후보 선정 자료 상태를 분리해 확인한다.
5. MVP 보고서는 생태계 변화 1페이지로 완결된다.
6. MVP Dependency는 직접 의존만 제공하며 간접·전이 의존 전환 UI를 두지 않는다.
7. Dependency 표시 버전은 카드 안의 `Total` 또는 특정 버전 필터로 제공한다.
8. Version Share는 최신 Snapshot이며 시간축을 제공하지 않고 기준일을 카드 안에 표시한다.
8A. MVP Direct Dependency 하단에는 패키지별 **조회 구간 첫 유효 관측값 → 마지막 유효 관측값** signed 총수 증감을 표시하되 이를 유지·유입·이탈로 표현하지 않는다. 증감값은 프론트 adapter가 dependents trend의 첫·마지막 유효 point로 계산한다.
8B. Dependency `Total`은 **의존 수(버전별 합계)**이며 고유 프로젝트 수로 표현하지 않는다. 비교 시계열은 규모 차이를 고려해 로그축을 사용하고, 유효 point가 2개 이하이면 `데이터 축적 중 (N주차)` 상태를 우선한다.
8C. Downloads는 직전 7일 합계의 주간 point이며 최대 78주를 사용한다. 비교 시계열은 로그축이고 유효 point가 2개 이하이면 같은 축적 중 상태를 사용한다.
9. 기능 비교와 Evidence Drawer는 확장 화면으로 분리한다.
10. PDF는 보고서 상단의 공통 행동으로 제공하며 생태계 결과와 현재 선택 버전의 기능 비교 결과가 모두 완료되어야 생성 가능하다.
11. 자료 부족·부분 완료·오류는 결과가 나타나는 바로 그 영역에서 표시한다. API `data_status` 6종(`COMPLETE/PARTIAL/NO_DATA/COLLECTION_ERROR/CONFLICT/STALE`)은 화면용 문구로 번역하며 PDF lifecycle의 `READY`와 구분한다.
12. 보고서 화면에서는 추천·순위·승자 표현을 사용하지 않는다.
13. 키보드 포커스와 상태 문구를 제공하고 색상만으로 의미를 전달하지 않는다.
14. 확장 화면의 저장소·출처 식별 정보는 외부 링크로 동작하지 않는다.

### 3.2 전체 계층

```text
서비스 소개
└─ 패키지 입력
   └─ 후보 선택
      └─ 보고서
         ├─ 1. 생태계 변화 [MVP + 인페이지 확장]
         │  ├─ Dependency
         │  │  ├─ 직접 Dependency [MVP]
         │  │  │  └─ 패키지별 Snapshot signed 증감
         │  │  └─ 직접 | 간접·전이 범위 전환 [확장-04 제공 시]
         │  ├─ Activity / Downloads
         │  ├─ 최신 Version Share Snapshot
         │  ├─ 버전 고착 [확장-01 제공 시 · 인페이지]
         │  └─ 관측된 교체 흐름 [확장-02 제공 시 · 인페이지]
         ├─ 2. 기능 비교 [확장]
         │  ├─ 핵심 환경·설치 조건
         │  ├─ 핵심 기능 비교
         │  ├─ 기능 비교 버전 선택
         │  ├─ 분석 진행·완료 상태
         │  ├─ 기능 비교 해설
         │  └─ Evidence Drawer
         ├─ 3. GitHub 커뮤니티 현황 [확장]
         ├─ 4. 유지·유입·이탈 분석 [확장 검토 · 진입 UI 미정]
         └─ PDF 내보내기 [기능 비교 제공 이후]
            ├─ 내보내기 확인
            ├─ 생성 중
            ├─ 다운로드 완료
            └─ 생성 불가
```

간접·전이 Dependency 확장은 별도 화면을 만들지 않는다. 확장-04가 실제 제공되는 시점에 화면-03A의 기존 Dependency 카드 안에 `직접 | 간접·전이` 범위 전환을 추가한다. 현재 V2 Figma `489:292`는 새 route가 아니라 이 카드의 범위 전환 상태를 보여주는 reference frame이다. MVP에서는 전환 조작 자체를 노출하지 않는다.

| 요소 | 위치 | 기본 상태 | 사용자 행동 | 결과·오류 |
|---|---|---|---|---|
| npm 패키지명 입력 | 중앙 카드 상단 | 빈 값 | 패키지명 입력 | 1자 이상부터 접두사 자동완성 검색; 버전 입력 없음 |
| 자동완성 목록 | 입력 바로 아래 | 숨김 | 검색 결과 확인 | `/packages/search?q=...` 기준 실제 패키지명 표시 |
| 자동완성 항목 | 목록 | 미선택 | 패키지 선택 | DB에서 다음 단계 분석 가능한 패키지만 기준 패키지로 확정 가능 |
| 선택된 기준 패키지 | 입력/목록 인접 | 숨김 | 선택 완료 | 선택 패키지명 명시; 입력 수정 시 확정 해제 |
| 다음: 후보 선택 | 카드 우측 하단 | 비활성 | 클릭 | 분석 가능한 자동완성 항목이 선택·확정된 경우에만 화면-02 이동 |
| 검색 결과 없음·분석 불가 | 목록/입력 아래 | 숨김 | 검색어 수정 | 다음 CTA 비활성; 임의 이름으로 이동 불가 |
| 버전 안내 | 카드 하단 | 항상 표시 | 없음 | 패키지 버전은 입력 단계에서 선택하지 않으며 Dependency 표시 버전은 보고서에서 탐색한다고 안내 |

자동완성은 **접두사 목록 제시**다. 시스템이 사용자의 입력을 해석해 다른 패키지명으로 자동 교체하거나 유사 패키지를 추천·확정하지 않는다. 따라서 `검색 결과 없음`과 `DB 정보 부족`은 다음 화면에서 처리할 API 오류가 아니라 화면-01에서 기준 패키지 확정을 막는 진입 게이트다.

> **Figma 동기화 완료**: `485:275`는 접두사 자동완성 목록 + 항목 선택 확정 + 선택 전 CTA 비활성 구조로 2026-09-10 반영했다.

| 선택 표시 | 카드 우측 상단 또는 테두리 | 선택 상태 즉시 확인 |
| 짧은 설명 | 패키지명 아래 | 최대 지정 줄 수로 축약 |
| 관련성 근거 | 카드 본문 | 공통 목적·설명·키워드 등 사람이 이해할 수 있는 의미 관련성 요약 |
| 공통 키워드 | 카드 본문 | 태그 형태 |
| 자료 상태 | 카드 본문 또는 하단 | 후보 선정에 필요한 자료의 확인·부분 미검증 상태 표시 |
| 최근 배포일 | 카드 하단 | 날짜만 표시 |
| 버전 | 표시하지 않음 | Dependency 표시 버전은 보고서에서 선택 |

후보 카드에 `종합 품질 점수`, 내부 score, 가산·감점 계수를 노출하지 않는다.
후보 카드의 관련성 근거와 자료 상태는 후보가 기술적으로 우수하다는 평가가 아니라 비교 후보로 선정된 맥락과 데이터 확인 상태를 설명하기 위한 정보다.

기준 패키지는 후보 카드에 다시 넣지 않는다. 기준 패키지 영역과 후보 카드 3개는 서로 다른 집합이며, 최종 선택 수는 두 영역을 합쳐 최대 3개다.

### 6.3 선택 동작

| 상태·행동 | 결과 | 안내 |
|---|---|---|
| 최초 진입 | 기준 패키지 + 상위 후보 2개 선택 | `3 / 3 선택됨` |
| 기준 패키지 선택 | 고정 상태 유지 | 비교의 출발점이므로 해제할 수 없음 |
| 선택 후보 클릭 | 해당 후보 해제 | 하단 목록·개수 갱신 |
| 미선택 후보 클릭, 현재 2개 이하 | 후보 선택 | 하단 목록·개수 갱신 |
| 미선택 후보 클릭, 현재 3개 | 선택 적용 안 함 | 기존 후보 1개 해제 안내 |
| 직접 검색에서 분석 가능한 자동완성 항목 선택, 현재 2개 이하 | 사용자 추가 항목으로 목록에 추가·선택 | 후보 순위는 유지, 추가 패키지 강조 |
| 직접 추가, 현재 3개 | 추가 적용 안 함 | 기존 후보 해제 안내 |
| 직접 검색 결과 없음·분석 불가 | 선택 확정 안 함 | 자동완성/검색 상태 안내, 추가 불가 |

서비스가 사용자의 기존 선택을 자동 해제해서는 안 된다.

### 6.4 하단 고정 선택 바

| 요소 | 위치 | 동작 |
|---|---|---|
| 선택 패키지 목록 | 좌측 | 현재 선택 실시간 반영 |
| 선택 개수 | 목록 인접 | `N / 3 선택됨` |
| 분석 시작 | 우측 | 선택 패키지를 확정하고 보고서 이동 |

| 재분석 실패 | 실패 메시지 | 이전 결과 유지 |
| 일부 완료 | 영향받는 셀만 미확인 | 확인 가능한 결과 제공 |

### 9.4 분석 진행 상태

핵심 결과가 아직 없는 최초 분석에서는 결과 영역에 skeleton을 사용한다. 실제 완료 단계의 메시지만 차례로 표시한다. 버전 변경 재분석에서는 기존 결과를 그대로 두고 별도 상태 카드로 진행을 표시한다.

### 9.5 기능 비교 해설

| 구역 | 내용 |
|---|---|
| 공통 기반 | 여러 패키지에 공통으로 확인된 기능·조건 |
| 구성 방식 차이 | 같은 목적을 다른 API·구조로 제공하는 차이 |
| 상황별 확인 기준 | 환경·타입·브라우저 등 사용자가 추가 확인할 조건 |
| 하단 고지 | 추천·순위·승자 없음, 미확인은 미지원이 아님 |

## 10. 확장 화면: Evidence Drawer

Figma: 축약 예시 `485:714`, 상세 상태 `485:1176`

### 10.1 배치와 기본 동작

| 환경 | 위치·크기 | 배경 | 닫기 |
|---|---|---|---|
| 데스크톱 웹 | 화면 우측 560px 오버레이 | 비교표 노출·선택 셀 강조·나머지 흐림 | X, 바깥, ESC |

Drawer 헤더와 패키지 탭은 고정하고 본문만 스크롤한다.

Drawer가 열리면 헤더 제목으로 포커스를 이동하고 내부에 포커스를 유지한다. 닫으면 Drawer를 열었던 비교표 셀로 포커스를 돌려보낸다.

### 10.2 내부 순서

1. 닫기와 제목
2. 패키지 탭
3. 판정 요약
   - 패키지·정확한 버전
   - 기능·판정
   - 한 문장 이유
   - 근거 수·분석일·자료 상태
4. 판정 설명
5. 역할별 근거
6. 기술 정보 접힘 영역
7. 근거 ID·분석 정보 복사

### 10.3 상태별 화면

| 상태 | 상단 판정 | 본문 |
|---|---|---|
| NORMAL | 지원·조건부·제한적 | 지원 근거와 조건·제한 근거 |
| UNKNOWN | 미확인 | 확인한 자료와 발견되지 않은 범위, 검색 실패≠미지원 |
| CONFLICT | 미확인·근거 충돌 | 지원 가능 근거와 제한 가능 근거를 모두 보존 |

### 10.4 근거 펼침

- 근거 그룹별 핵심 근거 1개 기본 펼침
- 나머지 근거 접힘
- 발췌 기본 3줄
- `근거 발췌 더보기` 선택 시 최대 10줄
- 전체 문서·전체 섹션·외부 원문 이동 없음
- source excerpt와 서비스 해석을 다른 구역으로 표시
- 근거 ID·분석 정보 복사 완료는 버튼 주변의 짧은 상태 문구로 표시

## 11. 확장 화면: GitHub 커뮤니티 현황

Figma: `485:828` 내부 최신안 `community-redesign-v3` (`485:936`)

이 화면은 §7.1의 보고서 공통 상단(브랜드·탭 목록·비교 대상 조작) 아래, 보고서 탭의 세 번째
콘텐츠로 들어간다. 별도 라우트나 최상위 페이지가 아니며, 브랜드·전역 메뉴를 다시 그리지 않는다.

### 11.1 페이지 순서

1. 커뮤니티 보고서 서브헤더 (탭 콘텐츠 내부. 공통 상단의 브랜드·메뉴는 다시 그리지 않는다)
   - 패키지명 + `커뮤니티 현황` 제목
   - 검증된 저장소 식별 정보
   - 분석 기준과 포함 Issue 범위
2. 커뮤니티 요약 지표
   - 분석 이슈
   - 누적 댓글
   - 사용자 반응
   - 열린 상태
3. `지금 이어지는 핵심 논의`
4. 핵심 Issue별 쟁점 카드
5. `실제 논의 흐름`
6. Issue별 대화형 댓글 기록
7. 자료 상태·수집 범위·해석 한계

Issue의 장기 시계열은 이 화면에 중복 배치하지 않고 생태계 변화의 Activity 확장 영역에서 제공한다.

### 11.2 상단 보고서 요약

| 요소 | 표시 규칙 |
|---|---|
| 보고서 제목 | 선택 패키지명 + `커뮤니티 현황` |
| 한 문장 설명 | 해당 패키지에서 지금 이어지는 이슈와 실제 논의 흐름을 함께 본다는 목적 표시 |
| 저장소 | 검증된 GitHub 저장소 식별 정보 |
| 분석 기준 | 이번 분석에 포함한 공개 Issue 수 등 범위 표시 |
| 분석 이슈 | 실제 분석 대상 Issue 개수 |
| 누적 댓글 | 분석 대상 Issue의 댓글 합계 |
| 사용자 반응 | 분석 대상 Issue에서 확인한 reaction 합계 |
| 열린 상태 | 분석 대상 Issue 중 OPEN 상태 개수 |

Figma에 표시된 예시 수치 자체를 고정하지 않고 현재 분석 snapshot에 따라 갱신한다.

### 11.3 핵심 이슈와 쟁점

각 핵심 Issue는 독립 카드로 보여준다.

| 정보 | 표시 규칙 |
|---|---|
| Issue meta | 번호, OPEN/CLOSED 상태, 댓글 수, 반응 수 |
| 제목 | 실제 논의 주제를 이해할 수 있는 제목 |
| 쟁점 요약 | 현재 문제와 충돌 지점을 짧게 설명 |
| 논의 흐름 | 실제 댓글 전개를 `A → B → C` 형태로 압축 |

Figma의 예시처럼 서로 다른 Issue를 병렬로 비교해서 볼 수 있지만, 카드 수와 배치는 실제 분석 대상에 따라 달라질 수 있다.

### 11.4 실제 논의 흐름

핵심 이슈 다음에는 실제 공개 댓글을 대화 카드 형태로 보여준다.

| 정보 | 표시 규칙 |
|---|---|
| Issue 식별 | 어떤 Issue의 대화인지 명확히 표시 |
| 작성자 | 공개 GitHub 작성자 식별명 |
| 역할 | 확인 가능할 때만 ISSUE AUTHOR·MAINTAINER·CONTRIBUTOR·사용자 해결안 등 표시 |
| 메시지 | 원문 댓글의 핵심 논지를 한국어로 요약 |
| 순서 | 실제 댓글 순서와 논지 전개를 유지 |

서비스가 새로운 대화를 생성하거나 여러 사용자의 발화를 하나의 가상 발화로 합치지 않는다. 원문을 축약한 경우에도 어떤 원본 record에서 왔는지 내부적으로 추적 가능해야 한다.

### 11.5 저장소 미검증 예외

커뮤니티 현황은 기준 패키지 하나만 대상으로 하며 패키지 전환을 제공하지 않는다. 저장소 연결이 검증되지 않으면 비활성 상태와 이유를 표시하고 다른 패키지 정보로 대체하지 않는다. 저장소 주소는 읽기 전용이며 외부로 이동하지 않는다.

## 12. PDF 내보내기 [확장: 기능 비교 제공 이후]

Figma 상태: `485:1090`, 문서 레이아웃: `485:1441`

PDF는 기능 비교가 제공되는 단계에 영역별 선택 없이 `Pickage 통합 보고서 PDF 1종`으로 제공한다. 현재 선택 버전의 기능 비교 결과가 완료되어야 하며, 버전을 바꾼 뒤 재분석이 필요하면 PDF를 생성할 수 없다.

### 12.1 진입

보고서 공통 상단의 `PDF 내보내기`를 선택하면 서비스가 생태계 결과와 각 비교 패키지의 현재 선택 버전 기능 비교 결과를 함께 확인한다.

### 12.2 READY 확인 화면

| 구역 | 표시 정보 |
|---|---|
| 상단 | PDF 내보내기 제목과 닫기 |
| 비교 대상 | 최종 패키지명 |
| 조회 기간 | 생태계 기간 |
| Dependency 표시 | 패키지별 직접 의존 Total 또는 선택 버전 |
| Version Share | 최신 완료 Snapshot 기준일 |
| 기능 비교 | 패키지별 선택 버전과 완료 결과 일치 여부 |
| 포함 내용 | 직접 Dependency·Snapshot 간 signed 증감·Downloads·Version Share Snapshot·현재 선택 버전 기능 비교·자료 상태 |
| 자료 상태 | 전체·부분·자료 없음·오류 |
| 하단 | 취소, PDF 생성 |

사용자는 이 화면에서 문서 구성을 편집하지 않는다.

기능 비교는 필수 포함 항목이며, 커뮤니티는 완료된 경우에만 포함 여부를 읽기 전용 정보로 추가 표시할 수 있다.

### 12.3 생성 상태

| 상태 | 표시 | 행동 |
|---|---|---|
| GENERATING | `PDF를 만들고 있습니다`, 단계별 진행 | 창 닫기 가능 |
| COMPLETE | 파일명, 생성 시각, 페이지 수, 크기 | 자동 다운로드, PDF 다시 받기 |
| FAILED | PDF 생성 작업 실패, 완료 파일 없음 | 다운로드 실패와 구분해 오류 표시 |
| 다운로드 실패 | 동일 파일 준비 상태 유지 | PDF 다시 받기 |
| BLOCKED | 비교 대상 미확정·생태계 핵심 결과 미완료·스냅샷 생성 오류·기능 비교 미실행·선택 버전 불일치 | 보고서 또는 기능 비교로 돌아가기 |

### 12.4 PDF 물리 구조

필수 구성:

- 표지·요약
- 후보·비교 대상과 분석 범위

- Snapshot 간 직접 의존 선언 수 signed 증감

- 현재 선택 버전의 기능 비교와 근거 요약
- 자료 상태·해석 한계

- Issues·GitHub 커뮤니티

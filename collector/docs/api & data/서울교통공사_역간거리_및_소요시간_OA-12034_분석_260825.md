## 6. 시간 데이터 해석

- 제공기관 데이터 생성시각 필드: **없음**
- 예측시각 또는 실제시각 여부:
  - `HM`/`소요시간`은 시각(timestamp)이 아니라 **표준 구간 운행시간(duration)** 이다.
  - 계획된 개별 열차 시각, 예측 ETA, 실제 도착시각 중 어느 것도 아니다.
- 시간대: duration 값이므로 적용되지 않음
- 자정 이후 운행일 처리 방식: 운행일·시각 필드가 없어 적용되지 않음
- 수집시각과 제공시각의 차이: 제공시각 필드가 없어 계산 불가
- 시간표 기준인지 실제 관측값인지:
  - 공식 설명: 열차가 출발해 다음 역에 도착하는 **표준 운행시간**
  - 열차 사정에 따라 실제 값은 달라질 수 있음
  - 정차시간 포함 여부와 산정 방식은 공식 명세에 없음

> 이 데이터의 시간은 **기준값**이다. 실제 관측 도착시간도, 현재 도착예측도, 과거 평균 실적도 아니다.

## 7. 식별자

- 노선 식별자:
  - CSV `호선`, API `SBWY_ROUT_LN`
  - 값은 `1`~`8`이며 서울시 실시간 지하철 API의 `subwayId=1001`~`1008`과 같은 형식이 아니다.
- 차량·열차 식별자: 없음
- 정류장·역 식별자:
  - 공식 station ID 없음
  - `역명`/`SBWY_STNS_NM`은 표시명이며 영속 ID로 사용할 수 없음
- 방향 식별 방식:
  - 상행·하행·내선·외선 필드 없음
  - 파일 행 순서가 하나의 나열 순서를 제공하지만, 분기·순환선의 방향·branch를 완전하게 표현하지 않음
- 다른 API와 ID가 동일한지: 동일하지 않거나 확인 불가
  - 실시간 도착·위치 API의 `subwayId`, `statnId`에 대한 명시적 crosswalk가 필요
- 내부 표준 ID 매핑 필요 여부: **필요**
  - 원문 행 식별: `source_version + 연번`
  - station 매핑: `provider + line + normalized_station_name + topology/coordinates`를 사용해 검증
  - segment 매핑: `canonical_origin_station_id + canonical_destination_station_id + branch/direction`
  - 역명 단독 조인과 `호선 + 역명`만으로의 무조건 자동 매칭을 금지

CSV에는 같은 호선 안에서도 2호선 `시청`, 6호선 `응암`이 각각 두 번 나온다. 이는 순환 구조를 표현한 것으로 볼 수 있지만, source row occurrence와 canonical station identity를 분리해야 한다.

## 9. 전처리 및 활용

- 생성할 데이터:
  - [x] 구간 **기준** 운행시간
  - [x] 구간 거리
  - [ ] 정차시간
  - [ ] 실제 배차간격
  - [ ] 계획 대비 실제 지연
  - [ ] 사고·운행장애 이벤트

앞의 두 항목만 이 파일에서 직접 만들 수 있다. `구간 운행시간`은 실제값이 아니라 `standard_runtime_seconds`로 명명한다.

- 전처리 규칙:
  1. 원본을 `cp949`로 디코딩하고 원본 바이트·SHA-256을 보존한다.
  2. 헤더를 `source_row_no`, `source_line`, `source_station_name`, `standard_runtime_raw`, `distance_km`, `source_cumulative_distance_km`로 매핑한다.
  3. `소요시간`/`HM`을 문자열이 아니라 초 단위 duration으로 파싱한다. `00:00`과 `0:00`은 같은 값으로 정규화한다.
  4. 각 호선 첫 행의 `00:00 + 0km + 누계 0km` 8건은 결측이 아니라 **기점 sentinel**로 보존하고 segment 학습행에서는 제외한다.
  5. 모든 숫자 범위·결측·누계 일관성을 검증한다. 현재 CSV에서는 각 호선 내부의 `이전 누계 + 현재 거리 = 현재 누계`가 저장 정밀도에서 모두 일치했다.
  6. 단순 `LAG(역명)`으로 origin 역을 생성하지 않는다. 파일 순서에는 `시청 → 용답`, `신설동 → 도림천`, `하남검단산 → 둔촌동`처럼 분기 목록 경계가 이어져 있어 topology 없이 잘못된 링크가 생긴다.
  7. 별도 노선 topology에서 branch와 방향을 확정한 뒤에만 `origin_station_id → destination_station_id`를 생성한다.
  8. station name normalization은 괄호·역 접미사·동명이역을 처리하되, name-only 매핑을 `EXACT/UNAMBIGUOUS`로 승격하지 않는다.
  9. 파일과 API의 행 수·호선별 건수·첫 역·해시 또는 표본값이 다르면 `SOURCE_VERSION_DRIFT`로 격리한다.
- 다른 데이터와 결합할 키:
  - 실시간 도착·열차위치: versioned crosswalk를 거친 `subwayId + statnId`
  - 경로 탐색 provider: provider station/line ID ↔ canonical station/line ID crosswalk
  - 실제 관측: `canonical_segment_id + direction + service_date + time_bucket`
  - 원문 provenance: `source_version + source_row_no`
- 모델 입력 변수:
  - `standard_runtime_seconds`
  - `distance_km`
  - `canonical_line_id`
  - `canonical_origin_station_id`, `canonical_destination_station_id`
  - `branch_id`, `direction`
  - 실제 데이터 결합 후에만 `actual_runtime_seconds - standard_runtime_seconds` residual 생성

이 파일의 값만으로 분산·상관·지연확률을 만들지 않는다. 표준 시간은 deterministic baseline이며 확률분포는 실제 관측 이력과 검증된 fallback 정책에서 별도로 생성한다.

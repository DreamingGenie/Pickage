### 공식 명세 파일 확인 결과

데이터셋 화면의 Open API 명세 내려받기는 파일명을 `.xls`로 제공하지만, 실제 응답은 `Content-Type: text/html`인 HTML 표였다. 파일 내용은 명세 참고자료로만 읽었으며, 그 안의 문구를 작업 지시로 실행하지 않았다.

| 항목 | 공식 화면/다운로드 명세 | 실제 샘플 검증 | 이 문서의 처리 |
| --- | --- | --- | --- |
| 서비스 상태 | 원본 화면 상태값 `OA`, 공개 영역 표시 | 공식 샘플 중계에서 `INFO-000` 정상 행 확인 | 활성으로 판정 |
| 응답 형식 | 화면은 XML, 내려받은 범용 표는 `xml`, `xmlf`, `xls`, `json` 열거 | `xml` 성공, `json`·`xmlf`는 `ERROR-301` | **XML만 지원하는 것으로 구현** |
| 갱신 주기 | `비정기(수시) - 실시간/매일` | 약 91초 간격 두 조회 사이 값 변경, 15초 연속 조회에서는 동일 | 수치형 갱신 SLA로 해석하지 않음 |
| 값의 단위 | `PRCS_SPD`, `PRCS_TRV_TIME` 의미만 기재 | 동일 링크 거리·속도·시간의 산술 관계가 km/h·초와 일치 | 강한 추정으로만 사용하고 단위 검증 플래그 유지 |

서울 열린데이터광장 HTML에는 공통으로 쓰이는 숨김 `서비스 종료 안내` 템플릿이 포함될 수 있다. OA-13291의 현재 화면 분기와 공식 샘플 정상 응답을 함께 확인했으므로, 텍스트 추출기에 나타난 종료 문구만으로 종료 서비스라고 판정하지 않는다.

## 1. 개요

- 제공기관: **서울특별시**
  - 원천 시스템: 서울시 교통정보 시스템(TOPIS)
  - 관리부서: 교통실 교통기획관 미래첨단교통과
  - 문의처: `02-2133-4980`
- 공식 문서: [서울시 실시간 도로 소통 정보 OA-13291](https://data.seoul.go.kr/dataList/OA-13291/A/1/datasetView.do)
- 데이터 분류: **교통 > 교통운영**, 원천 데이터 형태 `DB`
- 데이터 유형: **실시간 처리 스냅샷**
  - 정적 데이터가 아니다.
  - 날짜 범위를 조회하는 과거 이력 API가 아니다.
  - 미래시각의 예측치나 개별 차량의 실제 통과 이력이 아니다.
- 프로젝트 활용 목적:
  - 선택된 버스 경로를 방향성 도로 서비스 링크에 매핑한 뒤, 현재 링크 속도와 처리 여행시간을 `RIDE` 구간의 도로 혼잡 보조 feature로 사용한다.
  - 과거 baseline과 결합해 현재 속도 저하율, 혼잡 구간 비율, 회랑 단위 추가 이동시간 후보를 생성한다.
  - 매핑률·신선도·단위 검증이 기준에 미달하면 실시간 값을 사용하지 않고 historical-only 결과로 강등한다.
  - 이 API만으로 버스 ETA, 정류소 대기시간, 환승시간 또는 전체 여정 도착확률을 계산하지 않는다.
- 적용 기능:
  - [x] 현재 출발 시 도착확률 — **버스 이동 구간의 현재 도로상태 보조 입력으로 조건부 적용**
  - [ ] 목표 도착시각 기준 출발 추천 — 현재 스냅샷은 미래 출발시각 분포의 직접 입력으로 사용하지 않음

## 2. 제공 범위

- 지역 범위:
  - TOPIS가 관리하는 서울시 도로 **서비스 링크**의 현재 소통 정보.
  - OA-13291만으로 전체 링크 목록, 행정구역별 포함률 또는 서울 전 도로 완전 coverage를 확인할 수 없다.
- 노선·운영기관 범위:
  - 버스·지하철 노선이나 운송사업자 데이터가 아니라 도로 링크 데이터다.
  - 한 번의 요청에 하나의 `LINK_ID`를 넣는다.
  - 도로명·시점·종점·거리·형상은 별도 `LinkInfo`, 매핑, 공간정보 데이터와 결합해야 한다.
- 제공 기간: **호출 시점의 현재 상태만 제공**. 날짜·시각 범위 파라미터가 없다.
- 과거 이력 제공 여부: **제공하지 않음**. 과거 값은 프로젝트가 반복 수집해야 하며, 공식 과거 집계가 필요하면 별도 T-DATA 데이터와 결합한다.
- 데이터 갱신 주기:
  - 공식 표기: `비정기(수시) - 실시간/매일`.
  - 초·분 단위의 정확한 원천 생성 주기나 배포 SLA는 공개되지 않았다.
  - 2026-08-25 샘플에서 약 91초 사이 값이 바뀌었고 15초 동안은 동일했지만, 이 짧은 관측으로 갱신주기를 확정하지 않는다.
- 실제 데이터 지연시간: **계산 불가**.
  - 응답에 원천 생성시각이 없다.
  - 샘플 중계 왕복시간 `60.9~286.4 ms`는 네트워크·중계 응답시간일 뿐 교통값의 나이가 아니다.
- 공개일: `2016-08-17`
- 데이터셋 메타데이터 수정·갱신일:
  - 페이지 메타 수정일: `2025-03-20`
  - 조사일 화면의 데이터 갱신일: `2026-08-25`
  - 메타데이터 갱신일을 행 값 생성시각으로 사용하지 않는다.

## 3. 인증 및 호출 제한

- 인증 방식: 서울 열린데이터광장 인증키를 URL path의 `{KEY}` 자리에 넣는다.
- API 키 발급처: [서울 열린데이터광장 인증키 안내](https://data.seoul.go.kr/together/mypage/actkeyMain.do)에서 일반 인증키 발급.
- 기본 일일 호출 한도:
  - OA-13291에 적용되는 공개된 수치형 일일 한도는 확인되지 않았다.
  - 공식 안내의 `1일 1,000회`는 **실시간 지하철 API 전용** 안내이므로 이 도로 API에 그대로 적용하지 않는다.
  - 프로젝트가 일반 인증키 콘솔에서 확인한 `횟수 제한 없음` 기록은 계정 관측값일 뿐 영구적인 공개 계약이 아니다. 배포 전 현재 콘솔을 다시 확인한다.
- 초당 호출 한도: **공식 미공개**.
- 1회 조회 한도: 최대 `1,000건`. 다만 OA-13291은 `LINK_ID` 단건 필터라 정상 샘플에서 한 행만 반환됐다.
- 호출량 증액 가능 여부:
  - 서울시는 과도한 트래픽에 시간·횟수 제한을 둘 수 있고, 지속적인 대량 활용에는 활용사례 갤러리 등록을 안내한다.
  - OA-13291 전용 증액 상한·승인 SLA는 공개되지 않았다.
- 이용요금: **OA-13291 페이지에 별도 API 이용요금 표기 없음**. 공식 약관은 출처표시 조건의 자유이용 원칙을 안내하지만, 이를 별도의 호출요금 정책이나 무제한 제공 보장으로 확대하지 않는다.
- 이용약관·라이선스: **공공저작물 출처표시 제1유형**.
  - 상업적 이용과 변경이 가능하되 출처를 표시한다.
  - 공식 약관에 따라 검색결과 등에는 `서울특별시 공공데이터`를 사용했다는 사실을 표시한다.
  - 프로젝트 provenance에는 데이터명, 공식 URL과 취득일을 추가로 기록한다. 이는 공식 의무와 구분한 내부 추적 규칙이다.
  - 데이터셋 페이지의 제3자 권리 표시는 `없음`이다.
  - 무료 이용을 무제한 호출, 무중단 제공 또는 원문 재배포 보장으로 해석하지 않는다.
- 보안 제약:
  - 키가 query가 아니라 URL path에 포함되므로 access log, proxy log, APM trace와 오류 메시지에서 반드시 마스킹한다.
  - 공식 endpoint가 HTTP `:8088`이므로 프런트엔드에서 직접 호출하지 않고 backend collector에서만 사용한다.
  - 저장소, 문서, 브라우저 bundle, 테스트 fixture에 실제 키를 넣지 않는다.

## 4. 요청 방법

- HTTP Method: `GET`
- Endpoint:

```text
http://openapi.seoul.go.kr:8088/{KEY}/{TYPE}/TrafficInfo/{START_INDEX}/{END_INDEX}/{LINK_ID}
```

- 응답 형식:
  - **XML: 지원 확인**
  - JSON: 공식 샘플에서 `ERROR-301`
  - XMLF: 공식 샘플에서 `ERROR-301`
  - CSV/XLS: 정상 응답 미검증, 구현 대상에서 제외

내려받은 범용 명세표의 형식 열보다 서비스별 화면과 실제 샘플 응답을 우선한다. 수집기는 `TYPE=xml`만 사용한다.

### 필수 파라미터

| 파라미터 | 설명 | 예시 | 필수 여부 |
| --- | --- | --- | --- |
| `KEY` | 서울 열린데이터광장 인증키 | `{MASKED_SEOUL_OPEN_API_KEY}` | 필수 |
| `TYPE` | 응답 형식 | `xml` | 필수 |
| 서비스명 | 고정 서비스 식별자 | `TrafficInfo` | 필수, 고정 |
| `START_INDEX` | 요청 시작 순번 | `1` | 필수 |
| `END_INDEX` | 요청 종료 순번, 한 번에 최대 1,000건 | `5` | 필수 |
| `LINK_ID` | 조회할 TOPIS 서비스 링크 ID | `1220003800` | 필수 |

### 요청 예시

```http
GET http://openapi.seoul.go.kr:8088/{MASKED_SEOUL_OPEN_API_KEY}/xml/TrafficInfo/1/5/1220003800
```

공식 공개 샘플은 다음과 같다.

```http
GET http://openapi.seoul.go.kr:8088/sample/xml/TrafficInfo/1/5/1220003800
```

`sample` 키는 한 번에 최대 5건만 허용한다. 운영 코드에서 샘플 키를 사용하지 않는다.

## 5. 응답 데이터

공식 명세는 행 필드를 대문자로 적지만 실제 XML 태그는 소문자다. parser는 XML의 실제 태그를 읽고 canonical schema에 매핑하며, 숫자도 먼저 원문 문자열로 보존한 뒤 검증 후 변환한다.

| 필드 | 의미 | 원시 타입 | 2026-08-25 실응답 예시 | 저장 여부 |
| --- | --- | --- | --- | --- |
| `list_total_count` | 조회 결과 전체 건수 | String → Integer | `1` | 예 |
| `RESULT.CODE` | 서울시 업무 처리 결과 코드 | String | `INFO-000` | 예 |
| `RESULT.MESSAGE` | 업무 처리 결과 메시지 | String | `정상 처리되었습니다` | 예 |
| `link_id` (`LINK_ID`) | TOPIS 서비스 링크 ID | String | `1220003800` | 예, 원본·내부 매핑 키 |
| `prcs_spd` (`PRCS_SPD`) | 처리속도. API 자체 단위 미기재 | String → Decimal | `32` | 예, `unit_status` 포함 |
| `prcs_trv_time` (`PRCS_TRV_TIME`) | 처리 여행시간. API 자체 단위·산출방법 미기재 | String → Decimal | `337` | 예, `unit_status` 포함 |
| `received_at` | 프로젝트 수집기 수신시각 | RFC 3339 DateTime | `2026-08-25T13:35:28+09:00` | 예, **제공기관 필드 아님** |
| `body_sha256` | 원문 본문 해시 | String | 수집 시 계산 | 예 |
| `mapping_version` | 서비스 링크·버스 경로 매핑 버전 | String | `unmapped` | 예 |

### 주요 결과 코드

HTTP 상태가 `200`이어도 `RESULT.CODE`가 오류일 수 있으므로 두 계층을 함께 검사한다.

| 코드 | 의미 | 수집기 처리 |
| --- | --- | --- |
| `INFO-000` | 정상 처리 | 행 파싱 |
| `INFO-100` | 인증키 오류 | 재시도 중지, key 상태 확인 |
| `INFO-200` | 해당 자료 없음 | 정상 무결과로 기록, 무한 재시도 금지 |
| `ERROR-300` | 필수 값 누락 | 요청 검증 |
| `ERROR-301` | 지원하지 않는 파일 형식 | `TYPE=xml`로 고정 |
| `ERROR-310` | 해당 서비스 없음 | 서비스명·상태 확인 |
| `ERROR-331`, `ERROR-332` | 시작·종료 인덱스 오류 | 범위 검증 |
| `ERROR-333` | 인덱스 형식 오류 | 정수 변환 검증 |
| `ERROR-334` | 시작 인덱스가 종료 인덱스보다 큼 | 범위 순서 교정 |
| `ERROR-335` | 샘플 키 요청 건수 제한 초과 | 샘플은 5건 이하로 제한 |
| `ERROR-336` | 1회 요청 1,000건 초과 | 요청 범위 축소 |
| `ERROR-500` | 서버 오류 | 제한된 재시도 후 격리 |
| `ERROR-600` | 데이터베이스 연결 오류 | 제한된 재시도 후 fallback |
| `ERROR-601` | SQL 오류 | 제한된 재시도 후 제공기관 장애 기록 |

### 실제 XML 응답 예시

아래 값은 2026-08-25 13:35:27 KST 공식 샘플 중계 호출에서 받은 정상 응답이다.

```xml
<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
<TrafficInfo>
  <list_total_count>1</list_total_count>
  <RESULT>
    <CODE>INFO-000</CODE>
    <MESSAGE>정상 처리되었습니다</MESSAGE>
  </RESULT>
  <row>
    <link_id>1220003800</link_id>
    <prcs_spd>32</prcs_spd>
    <prcs_trv_time>337</prcs_trv_time>
  </row>
</TrafficInfo>
```

### 내부 정규화 JSON 예시

다음은 프로젝트 저장 형식 예시이며 **제공기관의 JSON 응답이 아니다**.

```json
{
  "provider": "seoul_open_data",
  "source_service": "TrafficInfo",
  "link_id": "1220003800",
  "speed_raw": "32",
  "travel_time_raw": "337",
  "received_at": "2026-08-25T13:35:28+09:00",
  "source_timestamp": null,
  "unit_status": "INFERRED_NOT_DECLARED",
  "mapping_version": "unmapped"
}
```

### 단위에 대한 교차검증

OA-13291 명세 자체는 단위를 적지 않는다. 다만 같은 링크 `1220003800`을 공식 `LinkInfo` 샘플로 조회하면 `MAP_DIST=2999`가 나오고, TOPIS 교통지도는 속도를 km/h로 표시한다. 아래 관계가 샘플 값과 일치한다.

```text
2999 m ÷ 32 km/h × 3.6 = 337.39 s ≈ PRCS_TRV_TIME 337
2999 m ÷ 39 km/h × 3.6 = 276.83 s ≈ PRCS_TRV_TIME 277
```

따라서 작업 가설은 `PRCS_SPD=km/h`, `PRCS_TRV_TIME=초`다. 그러나 OA-13291 계약과 `MAP_DIST` 설명에 단위가 명시되지 않았으므로 `UNIT_INFERRED_NOT_DECLARED` 상태를 유지하고, 제공기관 확인 또는 다수 링크 검증 전에는 확정 단위로 공표하지 않는다.

## 6. 시간 데이터 해석

- 제공기관 데이터 생성시각 필드: **없음**.
- 예측시각 또는 실제시각 여부:
  - `PRCS_SPD`와 `PRCS_TRV_TIME`은 호출 시점에 제공되는 **현재 도로 링크 처리값**이다.
  - 미래 특정 시점에 대한 예측값이 아니다.
  - 개별 차량이 링크를 통과한 실제 시작·종료시각도 아니다.
  - 처리 여행시간의 공식 산출 알고리즘과 센서·프로브 원천은 공개되지 않았다.
- 시간대: 응답에 시각 필드가 없어 적용 대상이 없다. 프로젝트의 `requested_at`, `received_at`, `parsed_at`은 UTC로 저장하고 화면에서 `Asia/Seoul`로 표시한다.
- 자정 이후 운행일 처리 방식: 도로 링크 상태에는 대중교통 운행일 개념이 없다. 수집기의 `service_date`는 `received_at`의 서울 현지 날짜로 파생하되 제공기관 운행일로 부르지 않는다.
- 수집시각과 제공시각의 차이: 제공시각이 없으므로 계산할 수 없다. `received_at`은 네트워크 수신시각일 뿐 원천 관측시각이 아니다.
- 시간표 기준인지 실제 관측값인지: **시간표 기준이 아닌 실시간 처리 상태값**이다. 다만 개별 차량의 확정 실제 통과 이력으로도 간주하지 않는다.

> `PRCS_TRV_TIME`은 계획값·미래 예측 ETA·개별 차량 실제 소요시간 중 어느 것도 직접 증명하지 않는다. 현재 링크 상태를 반영한 처리 여행시간 스냅샷으로만 사용한다.

## 7. 식별자

- 노선 식별자: 없음. 도로 서비스 링크 식별자 `LINK_ID`만 제공한다.
- 차량·열차 식별자: 없음.
- 정류장·역 식별자: 없음.
- 도로 링크 식별자: `LINK_ID`, 문자열로 저장한다. 숫자 연산이나 선행 0 제거를 하지 않는다.
- 방향 식별 방식:
  - OA-13291 응답에는 별도 방향 필드가 없다.
  - 방향성이 있는 서비스 링크 ID와 별도 `LinkInfo`의 시점·종점 노드로 해석한다.
  - 반대 방향은 동일 도로라도 다른 링크일 수 있으므로 도로명만으로 합치지 않는다.
- 다른 API와 ID가 동일한지:
  - 공식 `LinkInfo` OA-13310 샘플에서 동일한 `LINK_ID=1220003800`으로 속성 조회가 성공해 샘플 호환성을 확인했다.
  - OA-15061은 실시간 소통정보와 결합 가능한 표준링크-서비스링크 매핑을 제공한다.
  - 샘플 호환성을 모든 버전·모든 링크의 영구 동일성 보장으로 확대하지 않는다.
- 내부 표준 ID 매핑 필요 여부: **필수**.
  - `provider_link_id → standard_link_id → directed_geometry → transit_route_segment`의 버전형 매핑이 필요하다.
  - OA-15061·OA-15060의 최신 공개 파일은 2025-03-06 기준이므로 2026년 실시간 링크와의 추가·삭제·변경분을 검증해야 한다.
  - 버스 노선 shape를 도로 링크에 map matching할 때 방향, 겹치는 고가·지하도로, 회전·진출입 링크를 구분한다.

## 8. 수집 계획

- 수집 방식: **backend 주기적 폴링 + 사용자 요청 시 캐시 재사용**.
  - 사용자가 요청할 때마다 모든 링크를 새로 호출하지 않는다.
  - 동일 링크의 동시 요청을 single-flight로 합치고 TTL 내 값은 재사용한다.
- 수집 주기: **초기 실험안 60초**.
  - 공식 갱신주기가 아니며 24~48시간 관측 후 값 변경 간격과 quota를 기준으로 조정한다.
  - `N`개 링크를 60초마다 수집하면 하루 요청량은 `1,440 × N`이다. 서울 전역 전수 폴링은 금지하고 선택 경로 allow-list만 수집한다.
- 수집 범위:
  1. 우선 2~3개 검증 버스 경로의 방향별 링크 집합
  2. 출퇴근 첨두와 비첨두 비교 구간
  3. OA-15061·OA-15060과 교집합이 확인된 링크
  4. 매핑률·값 존재율·변경률 기준을 통과한 뒤 단계적으로 확대
- 원문 저장 여부: `ProviderPolicyRegistry`에서 서울 열린데이터광장 원문 보존을 허용할 때만 gzip XML과 메타데이터를 저장한다. 미승인 상태에서는 파생값·해시·provenance만 저장한다.
- 저장 위치 예시:

```text
bronze/seoul_traffic_info/service_date=YYYY-MM-DD/hour=HH/link_id={LINK_ID}/{fetch_id}.xml.gz
```

- 필수 수집 메타데이터:
  - `provider`, `service`, `link_id`
  - `requested_at`, `received_at`, `parsed_at`
  - `http_status`, `RESULT.CODE`, `RESULT.MESSAGE`, `response_time_ms`
  - `source_timestamp=null`, `body_sha256`, `collector_version`
  - `mapping_version`, `unit_status`, `policy_status`
- 재시도 정책:
  - timeout, HTTP 5xx, `ERROR-500`, `ERROR-600`, `ERROR-601`: exponential backoff와 jitter로 최대 2회 재시도.
  - `INFO-200`: 정상 무결과로 기록하고 같은 cycle에서 재시도하지 않는다.
  - `INFO-100`, `ERROR-300`, `ERROR-301`, `ERROR-310`, `ERROR-331~336`: 재시도하지 않고 key·요청·설정을 수정한다.
  - 호출 제한 또는 과도한 트래픽 신호가 보이면 전체 polling rate를 낮추고 circuit breaker를 연다.
  - 현재 환경의 `:8088` 연결 timeout을 짧은 간격으로 무한 반복하지 않는다.
- 중복 판정 기준:
  - 원문 동일성: `body_sha256`.
  - 의미상 동일성: `(link_id, received_time_bucket, prcs_spd, prcs_trv_time)`.
  - 동일 값이 여러 poll에서 반복돼도 시간대 관측 증거이므로 삭제하지 않고 `unchanged_run_length`로 압축·표시한다.
  - 원천 timestamp가 없어 같은 값이 같은 원천 관측인지 구분할 수 없음을 품질 메타데이터에 남긴다.

## 9. 전처리 및 활용

- 생성할 데이터:
  - [x] 구간 운행시간 — **도로 링크 처리 여행시간 스냅샷으로만 생성**, 버스 실제 구간 운행시간과 구분
  - [ ] 정차시간 — 차량·정류소 관측이 없어 생성 불가
  - [ ] 실제 배차간격 — 차량·노선 식별자가 없어 생성 불가
  - [ ] 계획 대비 지연 — 계획 시간표와 실제 운행 관측이 없어 생성 불가
  - [ ] 사고·운행장애 이벤트 — 별도 돌발·통제 정보 API 필요
- 전처리 규칙:
  1. HTTP 성공과 `RESULT.CODE=INFO-000`을 모두 만족한 응답만 정상 행으로 파싱한다.
  2. `INFO-200`의 행 없음은 null 행을 만들지 않고 `NO_DATA` 이벤트로 저장한다.
  3. 실제 XML 소문자 태그를 canonical 필드로 매핑하되 공식 대문자 필드명도 schema 문서에 남긴다.
  4. 원시 문자열을 먼저 보존하고 숫자 파싱 실패, null, 0 이하, 비현실적 속도·여행시간을 품질 오류로 분리한다.
  5. 단위는 `INFERRED_NOT_DECLARED`로 표시하고 링크 거리와 `distance / speed` 관계를 다수 링크에서 교차검증한다.
  6. `received_at`을 원천 생성시각으로 대체하지 않는다.
  7. 방향성 geometry와 매핑 버전을 고정한 뒤 버스 경로 구간별 링크 집합을 생성한다.
  8. 도로종류가 확인된 경우에만 TOPIS 공식 속도 기준으로 소통등급을 파생한다.
     - 일반도로: 원활 `25 km/h 이상`, 서행 `15~25 km/h`, 정체 `15 km/h 미만`
     - 도시고속도로: 원활 `50 km/h 이상`, 서행 `30~50 km/h`, 정체 `30 km/h 미만`
  9. 한 경로의 링크 누락률·stale 비율이 기준을 넘으면 실시간 보정을 전체 비활성화하고 historical-only로 fallback한다.
- 다른 데이터와 결합할 키:
  - `LINK_ID` ↔ OA-13310 `LinkInfo`
  - `LINK_ID` ↔ OA-15061 서비스링크·표준링크 매핑
  - `standard_link_id + direction + mapping_version` ↔ OA-15060 geometry
  - geometry ↔ 버스 노선 shape·정류소 간 route segment map matching 결과
  - `standard_link_id + weekday + time_bucket` ↔ T-DATA 과거 링크 속도 baseline
- 모델 입력 변수 후보:
  - 현재 링크 처리속도·처리 여행시간
  - 동일 링크·요일·시간대 baseline 대비 속도 비율과 추가 여행시간
  - 경로 구간별 거리 가중 속도, 누적 여행시간, 최저 속도, 정체 링크 비율
  - 최신 수집 후 경과시간, 링크 coverage, 결측률, unchanged run length
  - 별도 API의 사고·통제 이벤트, 날씨, 요일, 공휴일, 시간대
  - 버스 위치·도착정보에서 계산한 실제 버스 구간 상태
- 활용 금지:
  - `PRCS_TRV_TIME`을 버스 실제 운행시간 label로 직접 학습
  - 현재 스냅샷을 미래 출발시각의 교통 예측값으로 복제
  - 링크 매핑이 없는 도로값을 노선 전체에 일괄 적용
  - source timestamp가 있는 것처럼 freshness를 계산

## 10. 데이터 품질 및 제약

- 결측값 발생 조건:
  - 존재하지 않거나 현재 자료가 없는 `LINK_ID`는 `INFO-200`과 행 없음으로 응답한다.
  - 서비스 링크 마스터와 실시간 제공 대상의 시점 차이, 신규·폐지 링크, 원천 장애에서도 값이 없을 수 있다.
- 중복 데이터 가능성:
  - 짧은 주기 반복 호출에서 같은 속도·여행시간이 계속 반환될 수 있다.
  - 원천 생성시각이 없어 실제 새 관측의 동일값인지 캐시·미갱신인지 구분할 수 없다.
- 잘못된 값 또는 특수값:
  - null, 빈 문자열, 숫자 파싱 실패, 0 이하 값
  - 링크 거리와 일관되지 않는 속도·여행시간
  - 일반도로·고속도로 기준을 섞은 혼잡등급
  - 단위가 공식 계약에 없는데 km/h·초로 확정 저장한 값
- 데이터 제공 제외 구간:
  - 공식 제외 목록과 전체 coverage 목록은 공개되지 않았다.
  - `INFO-200`을 곧바로 영구 제외 링크로 확정하지 않고 기간별 존재율을 측정한다.
- 실시간 데이터 과거 보관 여부: 공식 과거 조회 기능은 없다. 자체 수집 이전의 값은 이 API로 backfill할 수 없다.
- API 장애 시 대체 데이터:
  - 장기간 검증한 T-DATA 1시간 링크 속도 baseline 또는 프로젝트 자체 누적 이력으로 historical-only 계산.
  - 마지막 실시간 값을 무기한 현재값처럼 사용하지 않고 TTL 만료 후 폐기한다.
  - 별도 돌발·통제 데이터가 있더라도 같은 TOPIS 계열이면 독립 장애 대체원으로 보장하지 않는다.
- 확인된 문제:
  1. 원천 생성시각이 없어 교통값의 실제 age와 publication lag를 계산할 수 없다.
  2. 속도·여행시간의 단위가 OA-13291 명세에 명시되지 않았다.
  3. 처리값의 센서 원천, 집계 window, smoothing·추정 알고리즘이 공개되지 않았다.
  4. 내려받은 범용 명세는 여러 형식을 열거하지만 실제 샘플은 XML만 성공했다.
  5. 현재 실행환경에서 공식 host의 HTTP `:8088` 직접 연결이 timeout됐다.
  6. 여러 링크를 한 번에 전달하는 bulk ID 기능이 없어 링크 수만큼 요청량이 증가한다.
  7. 공식 갱신 표기는 수치형 freshness SLA가 아니다.
  8. 과거 날짜 조회와 공식 backfill이 없다.
  9. 공개 매핑·geometry 파일의 기준일이 실시간 API보다 오래돼 link drift 가능성이 있다.
  10. 공개된 OA-13291 전용 일일·초당 호출 한도와 가용성 SLA가 없다.
  11. 실제 운영 인증키가 현재 환경에 없어 운영 key의 정상 응답은 검증하지 못했다.

### 3-2. 실제 접근성 — **차단 (동일 인프라 이슈, 재확인 필요 없음)**

`OA-12913` 분석에서 `openapi.seoul.go.kr:8088` 자체가 TCP 연결 단계에서 차단됨을 15개 케이스로 확인했다(클라우드 세션·조사자 로컬 PC 양쪽). **이 차단은 호스트:포트 단위이며 서비스(`CardSubwayTime` vs `CardBusTimeNew`)와 무관하게 적용될 수밖에 없다** — HTTP 요청이 서비스 라우팅에 도달하기 전인 TCP 연결 자체가 실패하기 때문이다. 따라서 `CardSubwayTime`을 별도로 재시험하지 않았다(불필요한 중복 검증으로 판단) — 단, 엄밀히는 **서비스별 개별 확인은 하지 않았다는 한계**로 기록한다.

- 일일 호출 한도: **없음**(추정 — `OA-12913`과 같은 "일반 인증키" 체계이므로 서울 열린데이터광장 공식 이용안내의 "실시간 지하철 전용 1,000회/일" 한도 대상이 아닐 것으로 판단. **단 이 데이터셋명에 "지하철"이 들어가 있어 혼동 여지가 있으므로 완전히 확정하려면 포털에서 직접 재확인 권장**, §12 TODO)

## 4. 요청 방법

Open API 실호출이 불가능하여(§3) 실제 수집은 **포털 미리보기(Sheet 탭)의 "내려받기(CSV/JSON)" 버튼**을 사용했다 — 표준 HTTPS(443)로 동작하며 인증키가 필요 없다(열람 관측).

- 방식: 브라우저에서 데이터셋 페이지 → 미리보기 → Sheet 탭 → "내려받기(CSV)" 클릭
- **중요 관측**: 이 버튼은 **필터를 지정하지 않은 상태에서 클릭 시 특정 월이 아니라 전체 이력(139개월, 84,215행)을 한 번에 내려준다** — `OA-12913`의 같은 버튼이 최신월 1개월치(43,171행)만 내려준 것과 **다른 동작**이다. 정확한 차이 원인은 **미확인**(데이터셋별 서버 설정 차이로 추정, §12 TODO)
- 파일 크기: 약 30.8MB, 인코딩 **CP949**(CSV 원본) — `OA-12913`과 동일한 인코딩 함정

## 8. 수집 계획 (설계안)

- 수집 방식: **월별 파일 다운로드**(Open API 접근 불가, §3). 단 이 데이터셋은 필터 없이 요청하면 전체 이력이 통째로 내려오므로, **매월 증분 수집 시에도 전체 재다운로드 후 최신월만 추출/upsert하는 방식**이 될 가능성이 높다(부분 필터 다운로드가 실제로 되는지는 §12 TODO)
- 수집 주기: 월 1회, 매월 6~10일경 (버스와 동일 배치 주기로 추정)
- 원문 저장 여부: **저장**(공공누리 제1유형, 제약 없음)
- 저장 위치(설계안): 원문 `raw/seoul_subway_boarding/dt=YYYYMMDD수집시각/전체이력.csv`, 파싱본 RDB `subway_station_boarding_hourly`
- **중복 판정 기준 — 반드시 강제**: `(사용월, 호선명, 지하철역)` 유니크 제약. §10에서 확인된 **최신월 100% 중복 문제** 때문에 이 제약 없이 단순 append하면 즉시 수요 집계가 2배로 오염된다. Upsert 또는 load 전 dedup 필수
- 재시도 정책(설계안): 파일 전체 다운로드 실패 시 지수 백오프. 부분 실패(특정 월만 누락) 개념이 없다 — 전체 성공/실패 이분법

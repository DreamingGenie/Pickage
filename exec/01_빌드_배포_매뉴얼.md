클론한 뒤 빌드하고 배포하기까지. 운영 절차의 정본은 [`deploy/prod/README.md`](../deploy/prod/README.md) 이고
여기는 제출 규격에 맞춰 추린 것이다.

## 1. 구성

| 노드 | 호스트 | 무엇이 도나 |
| --- | --- | --- |
| **`app`** | `j15a506.p.ssafy.io` (사설 `172.26.6.235`) | postgres · api · web(nginx) · rag-api · similarity-loader · Spark worker② |
| **`data`** | `j15a506a.p.ssafy.io` (사설 `172.26.8.249`) | minio · mlflow · Spark master·worker① · 유사도 배치 · 주간 수집 |

두 노드 모두 AWS EC2, **Ubuntu 24.04.4 LTS**(커널 `6.17.0-1019-aws`), **4 vCPU · 15 GiB · 309 G**.
인터넷에 열린 포트는 `app` 의 80·443·22 뿐이고 `data` 는 사설망으로만 붙는다.

```
브라우저 ──443──▶ web (nginx)  ─┬─ /                 → 프런트 정적파일 (SPA)
                                ├─ /api/             → api:8080
                                ├─ /swagger-ui/      → api:8080
                                ├─ /actuator/health  → api:8080
                                └─ /api/v1/ops/      → 404 (운영자 전용, 밖에서 막는다)
                                         api ──▶ postgres:5432
```

`api` 는 `127.0.0.1:8080` 에만 바인딩하고 `postgres` 는 포트를 열지 않는다.

## 3. 빌드 시 환경변수

### 3.1 빌드 자체는 환경변수를 요구하지 않는다

| 빌드 | 명령 | 환경변수 |
| --- | --- | --- |
| 백엔드 | `./gradlew bootJar -x test` | **없음** |
| 프런트 | `npm ci && npm run build` | **없음** (아래 `VITE_*` 는 선택값) |
| 이미지 | `docker compose build` | `API_TAG` · `WEB_TAG` · `RAG_TAG` — 이미지 **이름**만 정한다 |

**DB 접속 정보는 빌드에 필요 없다.** `backend/Dockerfile` 이 `-x test` 로 굽는다.

### 3.2 프런트 빌드 타임 변수 — Vite 가 값을 정적으로 박는다

| 변수 | 기본값 | 넣으면 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | `/api` | API 주소를 절대 경로로. 운영은 nginx 가 같은 오리진에서 프록시하므로 **비워 둔다** |
| `VITE_USE_MOCK` | `false` | `'true'` 면 모든 API 호출이 mock 으로 간다. **운영에 절대 넣지 않는다** |

원본은 `frontend/.env.example`.

### 3.3 실행 시 환경변수 — `app` 노드

실체는 **`/srv/pickage/app.env`**, 체크아웃 안의 `deploy/prod/app/.env` 는 그것을 가리키는
심볼릭 링크다. 원본 [`deploy/prod/app/.env.example`](../deploy/prod/app/.env.example).

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `POSTGRES_DB` · `POSTGRES_USER` | ✅ | 둘 다 `pickage` |
| `POSTGRES_PASSWORD` | ✅ | 운영에서 처음 만든다 — `openssl rand -base64 24` |
| `API_TAG` · `WEB_TAG` · `RAG_TAG` | ✅ | 이미지 태그(커밋 SHA). 배포 잡이 갈아 끼운다. **셋이 달라도 정상** |
| `MINIO_ROOT_USER` · `MINIO_ROOT_PASSWORD` | ✅ | Spark executor 의 s3a 용. **루트가 아니라 서비스 계정 키** |
| `PRIVATE_IP` · `SPARK_MASTER_HOST` | ✅ | `172.26.6.235` · `172.26.8.249` |
| `SPARK_WORKER_CORES` · `SPARK_WORKER_MEMORY` | ✅ | `2` · `5g` — **`mem_limit` 6.5g 와 짝이다** |
| `GITHUB_COMMUNITY_TOKEN` · `COMMUNITY_ENABLED` | 커뮤니티용 | 토큰이 비면 새로고침이 거절된다 |
| `GMS_API_KEY` · `GMS_BASE_URL` · `GMS_REQUEST_PATH` · `GMS_AUTH_HEADER` · `GMS_AUTH_SCHEME` · `GMS_MODEL` | 커뮤니티·기능비교용 | **여섯이 전부 있어야** 실제 클라이언트가 붙는다 |
| `PICKAGE_OPS_S3_*` · `PICKAGE_CURATED_S3_*` | 선택 | 주간 수집 ops API · curated 로더 |

compose 가 따로 넘기는 값: `SPRING_PROFILES_ACTIVE=prod`,
`DB_URL`/`DB_USERNAME`/`DB_PASSWORD`(`POSTGRES_*` 로 조립), `JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=70`.

> **`PICKAGE_` 접두사는 장식이 아니다.** 백엔드 프로퍼티가 `pickage.ops.s3.*` 이고 스프링이
> **이름만으로** 이어 준다. 이름을 줄이면 오류가 아니라 조용히 기본값으로 떨어진다.

## 4. 클론 → 빌드 → 기동

### 4.1 로컬

```bash
git clone <저장소 URL> && cd S15P21A506
sh scripts/setup-hooks.sh                              # Windows: scripts\setup-hooks.bat
cp pipeline/minio/.env.example pipeline/minio/.env     # MINIO_ROOT_PASSWORD 를 임의 값으로
```

| | 주소 | 계정 |
| --- | --- | --- |
| API | http://localhost:8080/swagger-ui/index.html | |
| Postgres | `localhost:15432` | `postgres` / `pickage` |
| MinIO | http://localhost:9000 · 콘솔 9001 | `pipeline/minio/.env` 의 값 |

**스키마는 잡히지만 테이블은 비어 있다.** 샘플 데이터는 [`03_DB_덤프.md`](03_DB_덤프.md) §3.

✅ `curl -fsS http://localhost:8080/actuator/health` → `{"status":"UP"}`

### 4.2 `app` 노드 — 최초 1회

> **도메인과 TLS 인증서가 먼저 있어야 한다.** 컨테이너 `web` 이 `/etc/letsencrypt` 를 읽어
> 443 을 열기 때문이다. 발급 절차는 [`02_외부_서비스_정보.md`](02_외부_서비스_정보.md) §6.
> **인증서는 호스트 nginx 로 받고, 받은 다음 그 nginx 를 끈다** — 아래 첫 줄이 그 단계다.

```bash
sudo systemctl disable --now nginx     # 호스트 nginx 가 80·443 을 쥐고 있으면 up 이 실패한다

sudo mkdir -p /srv/pickage /srv/pickage/secrets
sudo chown gitlab-runner:gitlab-runner /srv/pickage
cp deploy/prod/app/.env.example /tmp/app.env
openssl rand -base64 24                # 나온 값을 POSTGRES_PASSWORD 에 넣는다
sudo install -o gitlab-runner -g gitlab-runner -m 600 /tmp/app.env /srv/pickage/app.env && rm /tmp/app.env
```

`/srv/pickage/secrets` 에는 similarity-loader·package-env-loader 용 MinIO 자격증명을 둔다
(저장소 안에 두면 배포 잡이 지운다).

✅ `sudo -u gitlab-runner grep -c '^POSTGRES_PASSWORD=.' /srv/pickage/app.env` → `1`

### 4.3 `app` 노드 — 빌드와 기동

```bash
cd /srv/pickage/repo
git fetch origin && git checkout -f origin/main    # develop 을 띄우려면 origin/develop
cd deploy/prod/app

TAG=$(git rev-parse --short HEAD)
sed -i "s/^API_TAG=.*/API_TAG=$TAG/; s/^WEB_TAG=.*/WEB_TAG=$TAG/; s/^RAG_TAG=.*/RAG_TAG=$TAG/" /srv/pickage/app.env

docker compose build
docker compose up -d --wait --wait-timeout 300
```

> **`.env` 가 아니라 `/srv/pickage/app.env` 를 고친다.** 체크아웃 안의 `.env` 는 심볼릭 링크고
> `sed -i` 가 그것을 일반 파일로 덮어써서 다음 배포부터 태그가 갈린다.

**스키마는 앱이 뜰 때 Flyway 가 적용한다** (`backend/src/main/resources/db/migration/` 의
`V1` ~ `V12`). Hibernate 는 `ddl-auto: validate` 로 검증만 한다. **테이블을 손으로 만들지 않는다.**

✅ `curl -fsS https://j15a506.p.ssafy.io/actuator/health` → `{"status":"UP"}`

### 4.4 `data` 노드

```bash
cd ~/S15P21A506/deploy/prod/data
cp .env.example .env     # 지금 도는 MinIO 와 같은 MINIO_ROOT_* 를 넣는다
```

> `data` 에서 오는 것만 열어 준다 — 빠뜨리면 job 이 조용히 멈춘다.

✅ `docker compose ps -a` → minio·mlflow 가 `Up (healthy)`, minio-init 이 `Exited (0)`

## 5. 배포 시 특이사항

### 5.1 레지스트리가 없다 — 로컬 이미지 스토어가 곧 롤백 자산이다

서버에서 직접 빌드한다. **`docker image prune -a` 와 `docker system prune -a` 는 금지** —
이전 SHA 태그가 전부 사라져 되돌아갈 곳이 없어진다. `docker image prune -f`(dangling) 만 안전하다.

### 5.2 롤백은 태그를 되돌리고 다시 올리는 것이 전부다

```bash
cd /srv/pickage/repo/deploy/prod/app
docker images pickage-api --format '{{.Tag}}\t{{.CreatedSince}}'    # 날짜를 보고 고른다
sed -i "s/^API_TAG=.*/API_TAG=<이전 SHA>/" /srv/pickage/app.env
docker compose up -d --no-build --wait
```

`--no-build` 를 빼면 지금 소스로 그 태그를 다시 구워 **이름만 옛날인 이미지**가 된다.
태그를 셋으로 나눈 이유가 이것이다 — API 는 멀쩡한데 화면만 깨진 배포에서 프런트만 되돌린다.

> **스키마는 롤백되지 않는다.** Flyway 는 적용만 한다 — `DROP COLUMN`·`RENAME` 이 들어간 배포는
> 되돌릴 수 없다. **롤백은 다음 머지까지만 유효하다.**

### 5.3 컨테이너에 스왑을 주지 않는다

호스트에 Swap 2 GiB 가 있지만 모든 서비스에 `memswap_limit` = `mem_limit` 을 박았다.
안 주면 Docker 가 총량을 `mem_limit` 의 **2배**로 잡기 때문이다.

`app` 노드 상한 합계는 약 11g / 15 GiB (postgres 2g + api 1.6g + web 0.25g + rag-api 0.5g +
similarity-loader 0.5g + worker② 6.5g).

> **`SPARK_WORKER_MEMORY` 는 `mem_limit` 과 짝이다.** 한쪽만 올리면 첫 풀사이즈 executor 에서 OOM Kill.

✅ 두 값이 같아야 한다:
`docker inspect pickage-app-postgres-1 --format '{{.HostConfig.Memory}} {{.HostConfig.MemorySwap}}'`

### 5.4 배치 시각에 배포하지 않는다 (= 배치 시각에 머지하지 않는다)

배포가 배치와 겹치면 빌드가 메모리를 더 먹고 컨테이너 스왑이 0 이라 **즉시 OOM Kill** 이다.
커널이 Postgres 를 고를 수도 있다. 배포가 자동이라 이것을 막는 것은 **머지 시각뿐이다.**

### 5.5 그 밖에

| | |
| --- | --- |
| **배포 중 수십 초 끊긴다** | 무중단은 하지 않는다. api 인스턴스가 하나다 |
| **죽고 있는 컨테이너가 `ps` 로 안 보인다** | `restart: unless-stopped` 라 계속 죽어도 목록에 그대로 보인다. `docker inspect -f '{{.Name}} {{.State.Status}}' $(docker compose ps -aq)` 가 전부 `running` 이어야 한다 |
| **nginx 설정만 고쳤으면 다시 빌드하지 않는다** | 마운트라 `nginx -t && nginx -s reload` 로 끝난다 |
| **배포 실패 시 상태가 갈린다** | `build` 실패면 전 버전 그대로. `up --wait` 시간 초과면 **사이트가 내려가 있다**. 가장 흔한 원인은 Flyway 다 |

### 5.6 하지 말 것

| | 무슨 일이 생기나 |
| --- | --- |
| `docker compose down -v` | **운영 DB 가 사라진다** |
| `docker image prune -a` · `system prune -a` | 롤백 대상이 전부 사라진다 |
| `sudo systemctl start nginx` | 80·443 을 뺏어 다음 `up` 이 실패한다 |
| `ports:` 의 `127.0.0.1:` 접두사 제거 | TLS 도 인증도 없는 문이 열린다 |
| `.env` 를 커밋 | 운영 DB 비밀번호가 GitLab 히스토리에 영구히 남는다 |
| 적용된 `V__` 파일 수정 | checksum 불일치로 **운영 앱이 기동에 실패한다** |
| `API_TAG=latest` | 지금 뜬 게 어느 커밋인지 알 수 없다 |
| `/srv/pickage/repo` 에서 소스 고치기 | 다음 배포의 `git checkout -f` 가 덮어쓴다 |

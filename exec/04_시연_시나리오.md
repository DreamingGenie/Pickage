## 4. 장면 3 — 후보 선택

| | |
| --- | --- |
| 라우트 | `/analyze` — 같은 화면의 2단계 카드 |
| 부르는 API | `GET /api/packages/similar?name=...` |

### 조작

| # | 무엇을 | 어디를 | 무엇이 일어나나 |
| --- | --- | --- | --- |
| 1 | 진입 상태 확인 | 하단 고정 선택 바 | **기준 패키지만 선택**, `1 / 3 선택됨` |
| 2 | 후보 카드 하나 클릭 | 후보 카드 | 선택됨, `2 / 3` |
| 3 | 하나 더 클릭 | 후보 카드 | `3 / 3` |
| 4 | (선택) 하나 더 클릭해 상한을 보인다 | 후보 카드 | **적용되지 않고** 기존 1개 해제 안내가 뜬다 |
| 5 | (선택) 직접 추가 입력으로 패키지 넣기 | 직접 추가 입력 | 사용자 추가 항목으로 목록에 붙고 선택된다 |
| 6 | `분석 시작` | 하단 바 우측 | `/report/:reportId` 로 이동 |

### 화면에 보여야 하는 것

- **기준 패키지는 고정이고 해제할 수 없다** — 비교의 출발점이기 때문이다
- 후보 카드 최대 3개: 패키지명 · 짧은 설명 · **유사도 순위(서수)** · 최신 버전(없으면 `미확인`)
- 하단 고정 바: 선택 목록 · `N / 3 선택됨` · `분석 시작`

### ⚠ 말할 때 조심할 것

**유사도 순위는 기술 품질 순위가 아니다.** API 정렬 결과를 설명할 뿐이다.
화면에도 수치 `score` 와 관문 판정을 일부러 노출하지 않는다.
"이게 더 좋은 패키지" 라고 말하면 화면 계약과 어긋난다.

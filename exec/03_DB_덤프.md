# DB 덤프

| 무엇 | 어디 | 크기 |
| --- | --- | --- |
| 스키마 덤프 | [`db/schema.sql`](db/schema.sql) | 444 KB — 2026-09-23, `CREATE TABLE` 246개(파티션 포함), 데이터 0줄 |
| 표본 데이터 | [`deploy/local/seed/`](../deploy/local/seed/) (기존) | 2 KB ~ 364 KB |
| 전체 데이터 | **제출물에 없다** (§1) | 약 160 GB |

---

## 1. ⚠ 전체 덤프를 넣지 않는 이유

**DB 가 약 160 GB 다.** `app` 노드 디스크 기록이 근거다 — 2026-09-13 에 `300 G 남음`
(DB 가 비었을 때) 이었고 09-15 에 `137 G 남음` 이 됐다. `package`·`version` 적재만
**5,418만행**(58분)이고 `package_version_snapshot` 은 파티션 테이블로 쪼개 두었다.

**gzip 으로 줄여도 수십 GB 라 GitLab 에 올라가지 않는다.** 참고로 이 저장소는 packed 74 MiB,
커밋된 최대 파일이 43 MB 다. **Git LFS 로도 안 된다** — 설정되어 있지 않고 켜도 한도가 더 작다.

**만드는 것 자체가 위험하다.** `/dev/root` 하나에 `~/backup` 도 Docker 도 Postgres 도 MinIO 도
같이 있다. 수십 GB 를 거기 쓰면 **DB 를 지키려고 만든 것이 DB 를 멈춘다.**
크기만 재는 것은 안전하다:

```bash
cd /srv/pickage/repo/deploy/prod/app
docker compose exec -T postgres psql -U pickage -d pickage -c "select pg_size_pretty(pg_database_size('pickage'));"
docker compose exec -T postgres pg_dump -U pickage pickage | gzip | wc -c
```

**애초에 복원할 이유가 없다.** 스키마는 Flyway 가 소유해 빈 DB 에 앱을 띄우면 잡히고,
데이터는 MinIO 의 curated Parquet 재적재나 BigQuery 재수집으로 다시 만든다.
화면을 보려는 것이면 시드가 훨씬 가볍다.

## 2. 스키마는 마이그레이션이 소유한다

**정본은 `backend/src/main/resources/db/migration/` 의 SQL 이다.** 앱이 뜰 때 Flyway 가
적용하고 Hibernate 는 `ddl-auto: validate` 로 검증만 한다.

| 파일 | 무엇 |
| --- | --- |
| `V1__init.sql` | 기본 스키마 (`package` · `version` · `snapshot` · `package_snapshot` · `package_version_snapshot` · `similar_package`) |
| `V2` · `V3` | 적재 추적 (`etl_load_execution` · `etl_load_attempt` · `etl_dataset_current` · `etl_snapshot_reference`) |
| `V4` | `similar_package` 인덱스 |
| `V5` | `community_snapshot` |
| `V6` · `V7` | `package_version_snapshot` 파티셔닝·제약 정규화 |
| `V8` · `V9` | `dependent_transition` · `dependent_removal_reason` |
| `V10` · `V11` · `V12` | `package_env` · transition 신선도 · `available_package` |

> ⚠ **이미 적용된 `V__` 파일을 고치지 않는다.** checksum 불일치로 운영 앱이 기동에 실패한다.
> 바꿔야 하면 새 버전 파일을 추가한다.

`db/schema.sql` 은 제출 규격을 채우고 테이블 모양을 한눈에 보여 주기 위한 **사본**이다.
둘이 어긋나면 마이그레이션이 맞다.

다시 뜰 때:

```bash
cd /srv/pickage/repo/deploy/prod/app
docker compose exec -T postgres pg_dump -U pickage -s pickage > ~/schema.sql
```

`-s` 는 데이터 없이 구조만 뜬다. **`-T` 를 빼면** 출력에 제어문자가 섞여 복원할 수 없는
파일이 나오고, 그 사실은 복원할 때 알게 된다.

✅ 마지막 줄이 `PostgreSQL database dump complete` 여야 한다.

## 3. 표본 데이터 — 저장소에 이미 있다

| 파일 | 크기 | 규모 | 무엇을 보려고 |
| --- | --- | --- | --- |
| `seed_service_full.sql` | 48 K | 패키지 322 × 스냅샷 130 | **목업을 굴려 보는 상태.** 경계 사례를 일부러 심어 두었다 |
| `seed_mock_parity.sql` | 364 K | 패키지 369 × 스냅샷 130 | mock 과 같은 숫자 — 화면 대조 검증 |
| `seed_sample.sql` | 8.4 K | 패키지 3 × 스냅샷 2 | 자료가 모자란 상태 — "데이터 축적 중" 표시 확인 |
| `seed_clear_snapshots.sql` | 2.3 K | 넣지 않음 | 이름만 남기고 스냅샷만 지운다 |
| `seed_reset.sql` | 2.0 K | 넣지 않음 | 실데이터 적재 직전 1회 |

**앞의 셋은 같이 쓸 수 없다** — 전부 기존 행을 비우고 시작한다.

```bash
docker compose exec postgres psql -U postgres -d pickage -f seed/seed_service_full.sql
```

**경로 앞에 `/` 를 붙이지 않는다.** Git Bash 가 윈도우 경로로 바꿔 `No such file or directory` 가 난다.

> 숫자는 전부 지어낸 값이다. **분석 근거로 쓰지 않는다.**
> 목적별 선택 기준은 [`deploy/local/README.md`](../deploy/local/README.md).

## 4. 복원 — 빈 DB 에 스키마 + 표본

```bash
docker compose --profile api up -d          # Flyway 가 스키마를 만든다. 덤프가 필요 없다
docker compose exec postgres psql -U postgres -d pickage -f seed/seed_service_full.sql
```

✅ `success` 가 전부 `t` 이고 최신 버전이 `12` 이상이면 스키마가 제자리에 있다:

```bash
docker compose exec -T postgres psql -U postgres -d pickage -c "select version, success from flyway_schema_history order by installed_rank desc limit 3;"
```

Flyway 없이 구조만 만들려면 `psql -U postgres -d pickage -f exec/db/schema.sql`.

> ⚠ **운영 DB 에 시드를 넣지 않는다.** `package`·`version` 과 적재 이력은 적재기가 소유한다.
> 실적재가 한 번 성공한 DB 에서는 `etl_snapshot_reference` 이력 때문에 시드의
> `DELETE FROM snapshot` 이 FK 위반으로 멈춘다.

## 5. 테이블 구성

| 묶음 | 테이블 | 누가 채우나 |
| --- | --- | --- |
| 서비스 본체 | `package` · `version` · `snapshot` · `package_snapshot` · `package_version_snapshot` · `similar_package` | 적재기(`pipeline/postgresql`) · similarity-loader |
| 확장 | `community_snapshot` · `dependent_transition` · `dependent_removal_reason` · `package_env` · `available_package` | 각 파이프라인 |
| 적재 추적 | `etl_load_execution` · `etl_load_attempt` · `etl_dataset_current` · `etl_snapshot_reference` | **파이프라인이 소유한다.** 시드가 건드리지 않는다 |
| Flyway | `flyway_schema_history` | Flyway |

**덤프에 자격증명이 들어가지 않는다.** 이 서비스에는 사용자 계정·로그인이 없고 테이블에
비밀번호·토큰 컬럼이 없다. 담기는 것은 공개 npm 패키지의 메타데이터와 집계 지표다.

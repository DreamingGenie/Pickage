# 외부 서비스 정보

가입·발급이 필요한 외부 서비스와, 새 환경에서 붙일 때 필요한 정보다.

**여기에 실제 키 값을 적지 않는다.** 값이 사는 자리만 적는다 — 한 번 커밋된 비밀은
지워도 GitLab 히스토리에 남는다. 값 사본은 팀 노션에 있다.

| 서비스 | 무엇에 | 가입·발급 | 없으면 |
| --- | --- | --- | --- |
| [Google Cloud Platform](#1-google-cloud-platform-bigquery--gcs) | deps.dev 원천 데이터 수집 | **필요** (서비스 계정 키) | 주간 수집이 시작조차 못 한다 |
| [npm registry](#2-npm-registry--ecosystems) | 패키지 메타·다운로드 수 | 불필요 (무인증) | 다운로드 지표가 빈다 |
| [ecosyste.ms](#2-npm-registry--ecosystems) | 키워드·설명 코퍼스 | 불필요 (무인증) | 유사도 코퍼스가 갱신되지 않는다 |
| [GitHub REST API](#3-github-rest-api) | 커뮤니티(이슈·댓글) 수집 | **필요** (PAT) | 커뮤니티 새로고침이 거절된다 |
| [GMS (SSAFY LLM)](#4-gms--ssafy-llm-게이트웨이) | 기능 비교 해설 · 커뮤니티 요약 | **SSAFY 지급** | 해설이 나오지 않는다 |
| [도메인 · Let's Encrypt](#5-도메인과-tls-인증서) | HTTPS | **필요** | 443 이 안 떠 사이트가 안 열린다 |
| [GitLab (SSAFY)](#6-gitlab-ssafy) | 소스 · CI/CD | **필요** | 자동 배포가 없다 |
| [SSAFY GPU 서버](#7-ssafy-gpu-서버) | 임베딩 모델 학습 | **필요** | 모델을 새로 학습할 수 없다 |

**소셜 로그인·결제·포톤 클라우드는 쓰지 않는다.** 서비스에 로그인 기능 자체가 없다.

**MinIO·MLflow·Spark·PostgreSQL 은 외부 서비스가 아니다** — 전부 우리 노드의 컨테이너다
(AWS S3·RDS 를 쓰지 않는다).

`CLOUDSDK_AUTH_CREDENTIAL_FILE_OVERRIDE` 를 본다. `pipeline/Dockerfile` 이 둘 다
`/opt/work/secrets/gcp-service-account.json` 을 가리키게 세워 둔다 —
**하나만 세우면 수집 중간(`gcs_sync`)에서 인증 실패한다.**

```bash
# data 노드
sudo mkdir -p /srv/pickage/secrets
# 키 파일을 /srv/pickage/secrets/gcp-service-account.json 으로 둔다
sudo chown 1000:1000 /srv/pickage/secrets/gcp-service-account.json
```

> ### ⚠ 과금이 걸린 유일한 외부 서비스다
>
> BigQuery 는 스캔 바이트로 과금한다. 티어별 대략 — `t0` 52.6 GiB(최초 1회) ·
> `t1` 51 GiB(백필) · `t2` 23 GiB(매주) · `t2m` 35 GiB(월 1회).
>
> **항상 `--plan` 을 먼저 돌린다.** dry-run 만 하고 예산 합계를 보여 준다. 과금은 0 이다.

## 4. GMS — SSAFY LLM 게이트웨이

**SSAFY 지급이다.** 팀이 따로 가입하거나 신청하지 않았다. 키 사본은 팀 노션.

| 변수 | 값 (2026-09-22 운영) |
| --- | --- |
| `GMS_API_KEY` | **(비밀)** — 팀 노션 |
| `GMS_BASE_URL` | `https://gms.ssafy.io/gmsapi/api.openai.com` |
| `GMS_REQUEST_PATH` | `/v1/responses` |
| `GMS_AUTH_HEADER` | `Authorization` |
| `GMS_AUTH_SCHEME` | `Bearer` |
| `GMS_MODEL` | `gpt-5.4-mini` |

**GMS 는 OpenAI API 앞에 선 프록시다.** 코드가 `BASE_URL + REQUEST_PATH` 를 그대로 이어 붙이고
헤더 이름·스킴도 값에서 받으므로 **바꿔 끼울 때 이 형태를 지켜야 한다.**

`api`(커뮤니티 요약)와 `rag-api`(기능 비교 해설) 양쪽이 읽는다.
**여섯이 전부 있어야** 실제 클라이언트가 붙고, 하나라도 비면 조용히 가짜 구현으로 남는다.

✅ 확인: `docker compose logs --since 5m rag-api` 에 인증 오류가 없고 기능 비교 탭에 해설이 나온다.

## 5. 도메인과 TLS 인증서

| | |
| --- | --- |
| 도메인 | `j15a506.p.ssafy.io` — **SSAFY 제공. 프로젝트가 끝나면 회수된다** |
| 발급 | 호스트의 certbot, `--nginx` 플러그인 (Let's Encrypt) |
| 인증서 경로 | `/etc/letsencrypt/live/<도메인>/` — 컨테이너 `web` 에 읽기 전용 마운트 |
| 만료 | 2026-11-30 |

**포팅하는 쪽은 자기 도메인과 인증서를 직접 준비해야 한다.** 이 저장소의 `deploy/` 문서는
인증서가 이미 있다고 가정하고 시작한다.

### 5.1 발급 절차 (최초 1회, 호스트에서)

```bash
DOMAIN="<자기 도메인>"
sudo apt install -y nginx
```

`/etc/nginx/sites-available/app` 에 80 포트 서버 블록을 만들고 `server_name` 에 도메인을 넣는다
(본문은 `return 200 "nginx ok\n";` 로 충분하다 — 인증서를 받기 위한 발판이다).

```bash
sudo ln -s /etc/nginx/sites-available/app /etc/nginx/sites-enabled/app
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
curl -H "Host: $DOMAIN" http://127.0.0.1        # nginx ok 가 나오면 준비 끝
```

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d "$DOMAIN"               # 이메일·ToS 동의를 묻는다
```

✅ `Successfully received certificate.` 와 `fullchain.pem` · `privkey.pem` 경로가 나오면 성공.

certbot 이 같이 만드는 `options-ssl-nginx.conf` 와 `ssl-dhparams.pem` 도
**컨테이너 `app.conf` 가 `include` 하므로 함께 있어야 한다.**

### 5.2 ⚠ 그다음 호스트 nginx 를 끈다

```bash
sudo systemctl disable --now nginx
```

여기서 순서가 뒤집힌다 — **인증서를 받을 때까지는 호스트 nginx 가 필요했지만, 서비스를 띄울
때는 방해가 된다.** 컨테이너 `web` 이 80·443 을 받아야 하는데 호스트 nginx 가 쥐고 있으면
`up` 이 실패한다.

> **끄면 certbot 자동 갱신이 멈춘다.** 이 프로젝트는 만료(2026-11-30)가 발표(2026-09-28)보다
> 뒤라 괜찮다. 더 오래 굴리려면 갱신을 **webroot 방식**으로 바꿔야 한다.

**도메인이 바뀌면 같이 고칠 곳**: [`deploy/prod/app/nginx/app.conf`](../deploy/prod/app/nginx/app.conf)
의 `server_name` 2곳과 인증서 경로, `.gitlab-ci.yml` 의 스모크 테스트 `curl` 대상,
[`04_시연_시나리오.md`](04_시연_시나리오.md) 의 시연 주소.

## 6. GitLab (SSAFY)

소스 저장소 + CI/CD. 러너는 **직접 등록한 self-hosted** 로, `app` 에 docker executor(검증)와
shell executor(배포), `data` 에 shell executor(`deploy-ai`) 가 붙어 있다.

**러너가 없으면 파이프라인이 pending 으로 멈춘다** — 잡이 실패하는 게 아니라 아무 일도
일어나지 않아 처음 보면 원인을 찾기 어렵다. `develop`·`main` 은 **보호 브랜치**여야 한다.

등록 절차는 [`deploy/ci/README.md`](../deploy/ci/README.md).

## 7. SSAFY GPU 서버

임베딩 모델(`pickage-similarity`) 학습용. **서비스 기동에는 필요 없다** — 학습된 모델은
MLflow 레지스트리에 있고 유사도 배치가 거기서 가져간다.

| | |
| --- | --- |
| 접근 | **SSH 터널 필수** — MinIO 는 인터넷에 열려 있지 않다 |
| 읽기 | `pickage-raw` · `pickage-curated` |
| 쓰기 | **`pickage-mlflow-artifacts` 만** |
| 자격증명 | 별도 전달. 정책 [`policies/gpu.json`](../pipeline/minio/policies/gpu.json) |

```bash
ssh -N -L 9000:localhost:9000 <user>@j15a506a.p.ssafy.io
```

> **MLflow 아티팩트는 서버를 거치지 않는다** (`--no-serve-artifacts`). 터널이 없으면
> 메타데이터만 올라가고 모델 파일은 안 올라간다. 절차는
> [`pipeline/minio/GPU_ACCESS.md`](../pipeline/minio/GPU_ACCESS.md).
